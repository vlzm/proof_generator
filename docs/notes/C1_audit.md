# Аудит C1 — `docs/incoming/lrx_2n3_proof_checked.md`

Дата: 13.09.2026 (сессия 6). Первый локальный аудит базового комплекта
(PLAN §8, «параллельно доступно»; PROBLEM §6.2 отмечает C1 как не
аудированный). Бюджет — 1 сессия.

## 0. Объект аудита

- Файл: `docs/incoming/lrx_2n3_proof_checked.md` (английский текст,
  291 строка), сопровождающий код `docs/incoming/lrx_2n3_check.py`.
  Оба — часть «прежнего комплекта», добавлены владельцем в коммите 972890f.
- Заявление: `D_n <= floor(A_n)` при n >= 4 (первая формула теоремы),
  следствие `D_n <= B_n + floor(4n/3) - 3` (вторая формула), где
  `A_n = 2P + n - (2P+11n-11)/(3n)`, `P = floor(n^2/4)`, `B_n = n(n-1)/2`.
  Это C1 в реестре CLAIMS.md.
- Конвенции L/R/X (§3 текста) идентичны `oracle/moves.py`: сверено построчно
  (`apply_move`, `freely_reduce` в `lrx_2n3_check.py` совпадают дословно
  с `oracle/moves.py`, кроме имён). Файл использует нейтральное правило
  разрешения ничьей на дуге («choose either direction in a tie»), тогда как
  проект принял конкретное соглашение (правило 16, антиподальный шаг
  положителен); `lrx_2n3_check.py:signed_shortest_step` конкретно выбирает
  положительное направление при ничьей — совпадает с правилом 16, это один
  из двух допустимых по тексту выборов, не искажение доказательства (для
  антиподальной транспозиции такой выбор даёт случай M=1,E=2 из §3 текста,
  а не M=2,E=0; оба случая доказаны в тексте отдельно, см. ниже).
- Существенное наблюдение: конструкция §§1–2 (выбор кратчайших путей,
  выбор переносчика b на вершине максимального скачка нагрузки «−→+»,
  стягивание ребра, дизъюнктные сокращения XX) — **та же конструкция**,
  что и N1 §§1–3 (`docs/incoming/LRX_STRICT_PROOF_RU-1.md`, уже PROVED,
  C18): формула `S(C) = 2M(C) + E(C) - 1` и локальное слово длины `2F(C)-S(C)`
  совпадают дословно. N1 — более точная (по потерям) переработка того же
  локального слова с иной (более тонкой) оценкой третьего этапа; общая
  часть уже независимо реализована как `constructions/strict_upper.py`
  (strict_upper-1.0) и проверена `checks/check_C28.py`/`check_C32.py`.
  Это сокращает объём аудита: специфика C1 — неравенство (5) и цепочка
  усреднения §§3–5, а не сама локальная конструкция.

## 1. Вердикт

Логические переходы §§1–5 проверены по одному (ниже); пробелов, ложных
лемм и ошибок округления не найдено. Ключевое неравенство (5)
(`3nS(C) >= 5(F(C)+k)`) и цепочка усреднения (§§4–5) дают заявленный
результат корректно, включая округление до `floor(A_n)` и переход
к более простой (более слабой) форме `B_n + floor(4n/3) - 3`. §6
(резкость (5)) — воспроизведена точно.

Итог для реестра: **C1 — PROVED** (локальный аудит одной сессии, один
аудитор). Источник сообщал доказательство как проверенное (провенанс,
не локальный аудит, PROBLEM §6.2); теперь есть независимая проверка текста
и независимый численный чекер (§3 ниже, `checks/check_C1.py`).

Эта оценка не заменяет C16/N1: C1 слабее при каждом n в диапазоне таблицы
PROBLEM §5.1 (`floor(A_n)`: 8, 13, 19, 26, 35 при n=4..8 против точных
D_n = 6, 10, 15, 21, 28); C16 (`U_n`) уже строго её улучшает, а сама C1 не
подтверждает и не опровергает C15 (`D_n<=B_n`). Ценность аудита — закрыть
последний неаудированный документ базового комплекта (наряду с gap-файлом,
C4/C10/C11 — отдельная, не выполненная в этой сессии задача) и получить
независимо проверенное неравенство (5), которое отличается от уже
установленных N1-лемм (C21, C29) и может быть полезно как самостоятельный
инструмент.

## 2. Переходы, проверенные вручную

### §1. Пути и нагрузки одного цикла

- (1): скачок нагрузки `h_i - h_{i-1}` на вершине цикла — ровно 4 случая по
  знакам `d_{j-1}, d_j` (0, ±2), вне цикла — 0. Верно, идентично N1's
  «правилу скачков» (уже проверено в аудите N1).
- (2) `F+k <= nM+E`: из «t различных рёбер перед подъёмами имеют нагрузку
  `<= M-2`» получаем `nM-F = sum_i(M-h_i) >= 2t` (t рёбер вносят `>=2`
  каждое, остальные `>=0`, так как `h_i<=M` всегда); вместе с `k=E+2t`
  даёт `F+k <= (nM-2t)+(E+2t) = nM+E`. Рёбра действительно различны: подъёмы
  происходят в t различных вершинах цикла, их предшествующие рёбра индексом
  `i-1` также различны (вершины цикла попарно различны на Z_n). Верно.

### §2. Реализация цикла с переносчиком

- Стягивание ребра `{b,b+1}`, проекция путей на кольцо из n−1 слотов,
  `A = F - h_b = F - M` (h_b = M по выбору b). Верно: b выбран на подъёме
  до M, значит нагрузка ребра `{b,b+1}` (= h_b по определению индексации)
  равна M.
- Дизъюнктные сокращения XX: не более одного сокращения на переход,
  предшествующая и последующая дуги не могут обе «отдать» букву одному и
  тому же соседнему переходу — по построению (первая/последняя буква дуги
  однозначно определена её знаком). Не менее `k-1-t` подходящих переходов
  (все переходы, кроме t смен знака `+→−`, которых нет в вершине b по
  выбору). Итог `|W_C| <= 2(F-M)+k-1-2(k-1-t) = 2F-S(C)`,
  `S(C)=2M+E-1`. Верно, идентично N1 §2 (C18, уже PROVED).

### §3. Неравенство (5) — специфика C1

- (6): подстановка `F+k<=nM+E` (неравенство (2)) в `S=2M+E-1` корректна
  (убывающая по `F+k` функция `-5(F+k)`, оценка сверху на `F+k` даёт оценку
  снизу на `-5(F+k)`, алгебра `3n(2M+E-1)-5(nM+E)=n(M-3)+(3n-5)E` проверена
  вручную и чекером).
- Три случая (`M>=3` тривиален; `M=1` вынуждает `E=k>=2` по правилу (1),
  так как подъём требует `h_i>=2>M`; `M=2,E>=1`; `M=2,E=0` вынуждает
  чередование знаков на каждой вершине, связность носителя и чётность нагрузки
  дают ровно одну вершину нагрузки 0, откуда `t=1, k=2` — транспозиция,
  `S=3`, `F<=n`) — каждый разобран и даёт заявленную нижнюю оценку
  (`4n-10`, `2n-5`, `4n-10` соответственно), положительную при n>=4.
  Совпадает с независимым разбором транспозиций в PROBLEM §5.3/C24 (там —
  частный случай отражений; здесь — общий случай любой транспозиции).
  Проверено вручную и исчерпывающим перебором (§3 ниже).

### §4. Сборка циклов и вращений

- Тождество (7) `pi ∘ f_c^{-1} ∘ lambda^c = id` — прямая проверка
  определения `f_c = lambda^c ∘ pi` (перестановки индексов, композиция
  строго в заявленном порядке применения слов слева направо). Верно.
- (8): суммирование (5) по циклам даёт `sum_C S(C) >= (5/3n) sum_C (F(C)+k)
  = (5/3n)(F_c+N_c)`, откуда `sum_C(2F(C)-S(C)) <= (2-5/3n)F_c-(5/3n)N_c`.
  Верно (все величины неотрицательны, суммирование неравенств одного знака
  допустимо).
- H(c) (формула (9)) — **дословно совпадает** с H(c) конструкции N1
  (PROBLEM §5.2), уже независимо проверена в аудите N1 (C18 цепочка,
  `checks/check_C28.py` лемма 6). Не переаудировано заново, использовано
  как уже установленный факт.
- (10): сумма (8) + H(c) — это ровно те же две части внешней сборки, что
  и в N1 (внутренние слова по первому визиту переносчика + внешний маршрут);
  сборка идентична N1 §3 (C18, PROVED). Не переаудировано заново.

### §5. Усреднение

- (11): `sum_c F_c = n*P` — для каждого i значения `f_c(i)=pi(i)+c` пробегают
  все n вершин при переборе c, значит `sum_c delta_n(i,f_c(i)) = sum_j
  delta_n(i,j) = P` для каждого i; суммируя по i и деля на n даёт `P`.
  Аналогично `sum_c N_c = sum_i #{c: f_c(i)!=i} = sum_i (n-1) = n(n-1)`
  (ровно одно значение c даёт неподвижную точку i). Проверено вручную
  и точной арифметикой (Fraction), см. §3 ниже.
- (12): `sum_c H(c) = n + (n-1)(n-2) + P` (раскладка суммы по формуле (9) и
  тождеству `sum_{c=1}^{n-1} delta_n(0,c) = P`), делённая на n даёт
  `n-2+(P+2)/n`. Проверено вручную алгебраически (совпадает с текстом
  поразрядно) и точной арифметикой.
- Финальная выкладка `d(pi,id) <= min_c[...] <= average_c[...] = 2P+n-(2P+11n-11)/(3n)`
  — усреднение верхних оценок остаётся верхней оценкой минимума (не требует,
  чтобы среднее было пи-независимым; здесь оно оказывается таковым только
  благодаря (11)–(12), что делает результат универсальной константой, а не
  ослабляет логику). Округление `floor` для целого `d(pi,id)` — корректно,
  так как `d(pi,id)` — целое, а верна нестрогая верхняя оценка вещественным
  числом. Проверено точной арифметикой: `floor(A_n)` совпадает с целочисленной
  формулой кода (`ceil`-версией) на всём проверенном диапазоне (§3).
- Второй (более слабый, «человеческий») вид оценки и пороги («correction
  is at most -3 for even n>=6 and odd n>=5», n=4 отдельно) — численно
  подтверждены как достаточные (не только на пороговых n, но и вне их,
  избыточно) на 4 <= n <= 100000 точной целочисленной арифметикой (§3).
  Утверждение текста о порогах — про то, где работает его аналитический
  аргумент «коррекция <= −3», а не про то, где сам явный вывод неверен;
  сама вторая формула — верная (хотя не всегда точная) верхняя оценка
  на всём проверенном диапазоне.

### §6. Резкость (5)

- Семейство `C_r` (n=4r): пересчитаны `k=8, t=4, E=0, F=3n-8` по явному
  списку шагов; нагрузки `m` и `m+2` на два набора из 4 рёбер каждый,
  `nm+2(n-4)=3n-8` даёт `m=1`, отсюда `M=3`, `S=2*3+0-1=5`,
  `3n*5=5(3n-8+8)=15n` — точное равенство. Проверено вручную и чекером
  (`cycle_data` из `constructions/strict_upper.py`, независимая от текста
  реализация той же формулы) для `r = 2..25` (n = 8..100).

## 3. Машинная сверка

`checks/check_C1.py` (версия check_C1-1.0, ядро oracle-1.0, конструкция
strict_upper-1.0). Не переаудирует то, что уже покрыто N1-аудитом (сама
конструкция локального слова и H(c) — `check_C28.py`/`check_C32.py`);
проверяет специфику C1:

1. **Неравенство (5)** на каждом нетривиальном цикле f_c для всех pi, всех
   c при 4 <= n <= 9 (см. отчёт для точного числа циклов и n=9) — 0
   нарушений; отдельно собраны точные (равенство) случаи для сравнения с §6.
2. **Цепочка округления** точной рациональной арифметикой (`fractions.Fraction`,
   без float) при 4 <= n <= 100000: `floor(A_n)` совпадает с целочисленной
   формулой источника (`stated_bound`, использующей `ceil`) на каждом n;
   вторая (более слабая) формула `B_n+floor(4n/3)-3` — везде не меньше
   первой (достаточна как верхняя оценка на всём диапазоне, не только
   в заявленных текстом порогах).
3. **Семейство §6** — `r = 2..25` (n = 8..100), точное равенство в (5)
   на каждом r.
4. **Кросс-исполнение**: слово, построенное эталонной реализацией источника
   (`docs/incoming/lrx_2n3_check.py`), повторно исполнено независимым
   движком `oracle/moves.py:apply_word` (не собственным `apply_word`
   источника) — сортирует pi и укладывается в заявленную оценку, для всех
   pi, всех c при 4 <= n <= 9.

Результаты — `data/runs/check_C1/report.md` (числа и время).

## 4. Замечания к изложению (не пробелы)

- Текст пишет «choose either direction in a tie» (§1), не фиксируя
  конкретное соглашение; результат (5) не зависит от выбора (оба возможных
  случая для антиподальной транспозиции — M=1,E=2 и M=2,E=0 — разобраны
  и оба дают S=3). Стоит явно сослаться на это при сравнении с N1
  (правило 16 проекта), чтобы не создавать впечатления противоречия
  конвенций.
- Раздел 5 использует обозначения `N_c` (число сдвинутых точек, `sum_C k`)
  и не вводит число циклов `K_c` отдельно (в отличие от N1) — не ошибка,
  просто C1 не нуждается в K_c, так как использует более грубую (не
  почленную) оценку (5) сразу на F_c, N_c.
