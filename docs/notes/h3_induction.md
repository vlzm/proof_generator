# H3 — индуктивная редукция: попытка, вердикт

Дата: 14.09.2026 (сессии 10–11). Задача из PLAN §4.3, п. 3 / §8: индуктивная
редукция для C15 — определить вложение задачи размера n − k в задачу
размера n и стоимость имитации её ходов, с целью точной (без запаса)
рекурренты, телескопирующейся ровно в `B_n` (`B_n - B_{n-1} = n - 1`
всегда, `B_n - B_{n-2} = (n-1)+(n-2)`). Бюджет — 2 сессии до письменного
вердикта. Сессия 10 (§§1–5) проверила k = 1 (удаление одного элемента);
сессия 11 (§6) — k = 2 (удаление пары). Обе REFUTED; H3 закрыта (§7).

## 0. Итог

Обе проверенные формы редукции «удалить k элементов массива сразу»
**отклонены** явными контрпримерами: k = 1 — при n = 8, 10, 11, 12
(§§1–5, растущий избыток +1 → +2); k = 2 — при n = 12, после того как
держалась ровно (без запаса!) при 6 <= n <= 11 (§6). k = 2 откладывает
провал (n = 12 вместо n = 8), но не устраняет его. Решение: письменный
вердикт (AGENTS.md правило 12), обе сессии бюджета H3 израсходованы;
следующий фронт — §7 (аудит S1/C8).

## 1. Определение редукции

Дана pi из S_n. Для значения v из 0..n-1 определим `reduce_v(pi)` — массив
длины n − 1, полученный удалением элемента, равного v (соседние элементы
смыкаются, относительный порядок остальных сохраняется), затем понижением
значений больше v на 1 (чтобы получилась перестановка 0..n-2). Это самое
естественное вложение S_{n-1} в S_n «с одним фиксированным элементом» —
ровно то вложение, о котором предупреждает PLAN §4.3: «фиксированный
элемент нельзя молча исключать: L и R вращают весь массив».

Проверяемая гипотеза: существует v (и, возможно, поворот результата),
такие что `d_n(pi) - d_{n-1}(reduce_v(pi)) <= n - 1`, для ВСЕХ pi из S_n.
Если так — рекуррента `T_n <= T_{n-1} + (n-1)` доказана для этой конкретной
конструкции (нужно ещё показать, как реально построить слово такой длины,
но сама числовая оценка уже была бы установлена).

Две версии, обе минимизируются по v из n вариантов:

1. **Без поворота** — `reduce_v(pi)` берётся как есть (голова подзадачи
   там же, где была голова pi относительно оставшихся элементов).
2. **Со свободным поворотом** — дополнительно берётся минимум по всем
   n − 2 поворотам результата (переход `reduce_v(pi)` в `apply_word(reduce_v(pi), "L"*k)`,
   k = 0..n-2), стоимость поворота НЕ учитывается. Это верхняя граница
   того, чего может достичь любая редукция «удалить один элемент»: если
   даже она не укладывается в n − 1, ни одна более осторожная (платящая за
   поворот) версия тоже не уложится.

## 2. Метод проверки

`experiments/h3_reduction.c` (h3_reduction-1.0): по сертифицированным
таблицам `dist_n{n}.bin` (PROBLEM.md, ядро oracle-1.0) для n и n − 1,
исчерпывающий перебор всех n! перестановок; для каждой — минимум по v
(и, во второй версии, по повороту) числа `d_n(pi) - d_{n-1}(...)`; отчёт —
максимум этого минимума по всем pi (это именно то число, которое рекуррента
обязана не превышать n − 1). n = 11, 12 — таблицы вне git (см.
`docs/notes/repo_state.md`), воспроизведены `exact/bfs_fast.c`
(n=11: 16 с, n=12: 4 мин на этой машине) для однократной проверки, не
закоммичены (см. правило `data/tables/` — только 4..10 в git).

Даже без учёта стоимости поворота (искусственно щедрая версия) минимум
`d_n - d_{n-1}` по всем n выборам v превышает n − 1 уже при n = 8, и снова
при n = 10, 11, 12 — не единичный сбой при малом n, а повторяющееся и
**растущее** явление: избыток +1 при n = 8, 10, 11, но уже +2 при n = 12.
На пяти проверенных n (8, 9, 10, 11, 12) избыток ни разу не уменьшается
и в последней точке удваивается — данных мало для формулы роста, но
направление (растёт, не стабилизируется на +1) то же, что в H10/H11
(независимая обработка циклов теряет Theta(n), не O(1)).
Наименьший контрпример (по числу n, затем по лексикографическому рангу
перестановки — правило 6 AGENTS.md): **n = 8, pi = (3,6,0,7,4,5,2,1)**
(`d_8(pi) = 23`; минимум по всем v и поворотам подзадачи n = 7 равен 15, а
не `<= 7`; цикловой тип pi — 6-цикл `(0 3 7 1 6 2)` плюс две неподвижные
точки 4, 5, не отражение и не имеет частного вида). Автоморфизм
`p -> sigma_n o p o sigma_n` (PROBLEM §4.3) не даёт нового кандидата на
этом входе: `sigma_8 o pi o sigma_8 = pi` (неподвижная точка автоморфизма),
проверено прямым вычислением.

## 4. Вывод

Семейство редукций «удалить один элемент из массива» (с любым выбором
удаляемого элемента, с любым поворотом результата, бесплатным) не может
дать точную рекурренту `T_n <= T_{n-1} + (n-1)` при всех n: контрпримеры
существуют, не исчезают и не стабилизируются с ростом n (n = 8, 10, 11 —
избыток +1; n = 12 — уже +2). Это не вопрос неудачного конкретного
алгоритма симуляции ходов подзадачи — вердикт относится к самой ЧИСЛОВОЙ
величине `d_n(pi) - min d_{n-1}(...)`, взятой в самой оптимистичной форме
(бесплатный поворот), так что никакая реализация «удалить-и-симулировать»
не спасёт эту схему.

Это согласуется с уже установленными в проекте препятствиями:
- H10/H11 (`docs/notes/h10_verdict.md`): независимая обработка циклов
  перестановки (конструкция N1) теряет `Theta(n)` на аффинных входах —
  тот же класс явления («разбить на части и решить независимо» стоит
  дороже, чем кажется).
- H13-I (`docs/notes/h13i_verdict.md`, сессия 9): усреднение и локальные
  одномерные критерии выбора разреза не дают точной границы.

Во всех трёх случаях попытка свести общую задачу к «более простой»
структуре (сдвиг c, разрез (q,c), удалённый элемент) без учёта СОВМЕСТНОГО
взаимодействия оставшихся частей теряет ровно там, где нужна точность
O(1), а не O(n).

## 5. n = 12 — довершено после публикации сессии

n = 12 был запущен в фоне до публикации вердикта (не дожидались —
три контрпримера n = 8, 10, 11 уже исчерпывающе устанавливали вердикт §4);
фоновый прогон завершился отдельно (44 мин процессорного времени) и дал
`target=11, worst_no_rotation=15, worst_with_free_rotation=13` —
превышение уже на 2, а не на 1 (`argmax_rot = (0,1,7,8,2,3,9,4,10,11,5,6)`,
`data/runs/h3_induction/reduction_n12.log`). Это меняет вывод §3 с
«избыток стабилен на +1» на «избыток растёт» — сильнее подтверждает §4:
схема не просто иногда даёт лишний ход, а теряет точность без предела.

## 6. Сессия 11 (2 из 2): удаление пары элементов

Кандидат 3 из прежнего списка — индукция сразу на два уровня размера:
удалить ПАРУ значений `{v1, v2}` из массива за один шаг (`C(n,2)` вариантов
вместо n), понизить оставшиеся значения на 1 или 2 по числу удалённых
меньших, и сравнить с `d_{n-2}`. Цель — уложиться в телескопированный
бюджет двух шагов рекурренты: `d_n(pi) - d_{n-2}(reduce_{v1,v2}(pi)) <= 2n-3`
(`= (n-1)+(n-2)`, ровно то, что дают два шага H3 подряд). Без свободного
поворота (§1 показал, что поворот лишь откладывает провал, не снимает
его, и с парами он был бы намного дороже — `C(n,2)*(n-2)` кандидатов
на pi). Код — `experiments/h3_reduction_pair.c` (h3_reduction_pair-1.0),
тот же метод (сертифицированные таблицы n и n−2), исчерпывающе.

| n | target = 2n−3 | worst (min по всем парам) | вердикт |
|---|---|---|---|
| 6 | 9 | 9 | ok (точно) |
| 7 | 11 | 11 | ok (точно) |
| 8 | 13 | 13 | ok (точно) |
| 9 | 15 | 15 | ok (точно) |
| 10 | 17 | 17 | ok (точно) |
| 11 | 19 | 19 | ok (точно) |
| 12 | 21 | **22** | **EXCEEDS (+1)** |

(`data/runs/h3_induction/pair_n6_10.log`, `pair_n11.log`, `pair_n12.log`.)

При 6 <= n <= 11 худший случай попадает РОВНО в цель (не с запасом) —
удаление одного элемента (§3) вообще не давало такой чистой серии равенств
подряд (равенство было только при отдельных n = 5, 6, 7, 9, вперемешку
с превышением). При n = 8..10 экстремальная перестановка одна и та же по
структуре: `pi = (0, 1, n-1, n-2, ..., 2)` (тождество на первых двух
позициях, разворот остального); лучшая пара для неё — `{v1, v2} = {0, 2}`
(не `{0, 1}` и не две наибольшие!), и после удаления результат — снова
перестановка того же вида `(0, n-3, ..., 1)` длины n − 2 (самоподобие
семейства при этой редукции, но с потерей одной единицы «тождественного
префикса» на каждом шаге). Наивное локальное правило «удалить пару под
головой» (`v1=pi[0], v2=pi[1]`) отклонено отдельно — превышает цель уже
при n = 6 (`pi=(1,0,5,4,3,2)`, худшее 11 > 9), так что даже при экстремуме,
где схема пар работает, нужный выбор пары — не тривиальная локальная
формула, а поиск (или недоказанное правило вроде «0 и 2»).

При n = 12 — превышение, но не на прежней экстремальной семье:
наименьший контрпример `pi = (4,3,6,5,0,11,2,1,8,7,10,9)` (минимум по всем
55 парам — 22 > 21; цикловой тип — две транспозиции `(0 4)`, `(2 6)`,
6-цикл `(1 3 5 11 9 7)`, неподвижные точки 8, 10). Пары «откладывают»
провал схемы с n = 8 (одноэлементная версия) до n = 12, но не устраняют
его — на бОльшем n экстремум смещается на структурно другой вход.

## 7. Итоговый вердикт H3

Обе проверенные формы «удалить k элементов массива за раз, лучший выбор,
без штрафа за поворот» (k = 1 и k = 2) не дают точной (без запаса)
рекурренты для C15 при всех n: k = 1 ломается при n = 8, k = 2 — при
n = 12. Рост k явно покупает больше n до первого контрпримера
(грубо, n=8 при k=1 vs n=12 при k=2 — не строго k*4, но в этом
направлении), однако это не путь к C15 с ФИКСИРОВАННЫМ k: доказательство
нужно для ВСЕХ n одним и тем же (или растущим вместе с n) k, а рост
самого k с n превращает «индукцию по одному шагу» в исходную нерешённую
задачу целиком (при k = n − 4 редукция вырождается в прямое сравнение
с базой). Без нового структурного наблюдения (не просто «больше пар на
переборе») это направление исчерпано в рамках отведённого бюджета
(2 сессии, AGENTS.md правило 12).

H3 закрыта отрицательным результатом. Реестр: C38 (k=1), C39 (k=2).
Следующий фронт — аудит нижней оценки S1 (C8, PLAN §3.2): верхняя оценка
(H10/H11, H13-I, H3 — три независимых направления) методично отклоняет
схемы «разбить и решить независимо» с нулевым запасом; в отсутствие
кандидата на C15 стоит проверить, не является ли нижняя оценка (S1) уже
готовым инструментом (C8 сейчас CLAIMED, аудит не проводился — PLAN §3.2,
бюджет 2 сессии). Отдельно, дешевле: продолжение H13-R/H13-I с
направлением совместного критерия баланса разрезов (`h13i_verdict.md` §3).
