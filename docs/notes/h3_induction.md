# H3 — индукция `D_n <= D_{n−1} + (n − 1)`: формализация и арифметическая проверка

Дата: 15.09.2026 (сессия 9). Код: `experiments/h3_reduction.py`
(h3_reduction-1.0), ядро oracle-1.0, сертифицированные таблицы C2v
(4 <= n <= 10). Отчёт: `data/runs/h3_reduction/report.md`.
Статус: H3 не доказана и не опровергнута; установлено, что в строгой форме она
не является путём, независимым от H13 (линейной модели).

## 1. Что именно утверждает H3

`B_n − B_{n−1} = n − 1` и `B_4 = 6 = D_4`, поэтому

```text
D_n <= D_{n−1} + (n − 1) при всех n >= 5   =>   D_n <= B_n при всех n >= 4 (C15).
```

Запас нулевой: каждый лишний ход на переход к меньшей задаче ломает индукцию.
Схема, которая могла бы это дать, состоит из двух частей:

1. **Подготовка.** Из любого состояния p n-задачи за `m <= n − 1` ходов прийти
   в состояние q, которое читается как «(n−1)-задача плюс один припаркованный
   элемент z в одной ячейке окружности».
2. **Имитация.** Кратчайшее (или конструктивное, длины `<= B_{n−1}`) слово
   меньшей задачи исполнить ход в ход: один ход меньшей задачи — один ход
   большей (имитация 1:1).

Тогда `len <= m + B_{n−1} <= (n − 1) + B_{n−1} = B_n`.

## 2. Имитация 1:1 требует линейной модели (H13)

Окружность n-задачи — это окружность (n−1)-задачи, в которую вставлена ячейка
с элементом z (PROBLEM §2: позиции неподвижны, голова ходит, X меняет две
позиции под головой). Тогда:

- шаг головы меньшей задачи стоит 1 ход, **кроме** шагов через ячейку z:
  такой шаг стоит 2 хода (голова обязана пройти лишнюю ячейку — L и R двигают
  голову по всем n позициям, «пропустить» ячейку нельзя);
- обмен меньшей задачи на ребре, которое в большей задаче разорвано ячейкой z
  (то есть между двумя соседями z), вообще не является одним ходом: элементы
  a z b переставляются в b z a тремя обменами.

Значит имитация 1:1 возможна тогда и только тогда, когда слово меньшей задачи
**не переходит и не обменивает через ячейку z** — это в точности определение
линейного слова с разрезом в z (C33, `docs/notes/h13_line_model.md` §0).
Поэтому пункт 2 требует

```text
max по состояниям (n−1)-задачи d_line <= B_{n−1},
```

то есть исходную H13 (`max_pi d_line(pi) = B_n`, VERIFIED 4 <= n <= 9, C33).
Вывод: **H3 со строгой имитацией 1:1 не независима от H13** — она требует того
же самого факта о линейной модели и добавляет к нему отдельную задачу о
подготовке (`m <= n − 1` ходов, включая выбор места парковки, то есть разреза).
Ослабления («имитация со средней стоимостью 1 + eps») ломают нулевой запас.

## 3. Арифметическая проверка одноэлементной редукции

`reduce(p, k)` — удалить из массива элемент с индексом k и перенумеровать
значения (голова остаётся на индексе 0 нового массива). Это единственная
естественная одноэлементная редукция состояния. По сертифицированным таблицам
измерены две величины (`experiments/h3_reduction.py`):

```text
excess(p) = d_n(p) − min_k d_{n−1}(reduce(p,k)),
slack(p)  = max_k d_{n−1}(reduce(p,k)) − (d_n(p) − (n − 1)).
```

Смысл: если схема паркует элемент так, что редукция — `reduce(p,k)`, и имитирует
кратчайшее слово меньшей задачи 1:1, то её слово имеет длину
`m + d_{n−1}(reduce(p,k))` и обязано быть не короче `d_n(p)`. Поэтому редукции
с `d_{n−1} < d_n(p) − m` для схемы недопустимы; `slack(p) >= 0` — необходимое
условие существования допустимой парковки **без подготовки**.

Результаты (exhaustive при 5 <= n <= 8; выборка 100 000 состояний при n = 9):

| n | max excess | n − 1 | min slack | состояний со slack < 0 | подготовка `|u| <= n−1` спасает |
|---|---|---|---|---|---|
| 5 | 5 | 4 | 0 | 0 из 120 | — |
| 6 | 8 | 5 | 0 | 0 из 720 | — |
| 7 | 9 | 6 | −1 | 1 из 5040 | да (исчерпывающе) |
| 8 | 11 | 7 | −2 | 62 из 40320 | да (исчерпывающе) |
| 9 | 12 | 8 | −2 | 19 из 100 000 | не проверялось |

Читается так:

1. `max excess > n − 1` при всех проверенных n (5, 8, 9, 11, 12 против
   4, 5, 6, 7, 8): самая «дешёвая» редукция всегда несовместима с имитацией
   1:1 — удаление одного элемента способно убрать больше трудности, чем n − 1.
   Простейший пример: антиподальная транспозиция `tau_n` (C34, лемма B)
   с `d = n + 1`, у которой удаление любого из двух переставленных элементов
   даёт тождественную перестановку (`d = 0`). Значит **никакое фиксированное
   правило удаления** (одно и то же k при всех p) не годится: измеренные
   максимумы по каждому k тоже превышают n − 1 при всех проверенных n.
2. Необходимое условие `slack >= 0` без подготовки выполняется при n = 5, 6
   **с нулевым запасом** (минимум ровно 0) и нарушается начиная с n = 7.
   Все нарушения при n = 7, 8 снимаются подготовкой длины `<= n − 1`
   (проверено перебором всех слов), то есть арифметического противоречия пока
   нет — но парковка обязана зависеть от состояния и использовать подготовку,
   и запас в среднем близок к нулю.

## 4. Что делать дальше с H3

- Узел общий с H13: пункт 2 (имитация) = линейная модель. Отдельного выигрыша
  от H3 нет, пока `max_pi d_line <= B_n` не доказана.
- Если H13-I и H13-R будут доказаны, H3 не понадобится (они дают C15 напрямую
  по C12).
- Самостоятельная часть H3 — задача о подготовке: доказать, что за `<= n − 1`
  ходов из любого состояния достижимо состояние, в котором найденный разрез
  линейной модели проходит рядом с головой. Это осмысленная подзадача, но она
  не заменяет H13.
- Не тратить бюджет на «редукцию удалением элемента» в исходном виде:
  измеренные excess-значения показывают, что она несовместима с нулевым
  запасом рекурренты.
