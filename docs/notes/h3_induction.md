# H3 — induction on n: the "triple cut" reduction (session 10)

Дата: 14.09.2026. Ядро oracle-1.0, таблицы C2v (4 <= n <= 10). Код:
`experiments/h3_induction_probe.py` .. `probe4.py`. Отчёты:
`data/runs/h3_induction_probe/`.

Задача (PLAN §4.3 п. 3, гипотеза H3): найти вложение задачи размера n-1
в задачу размера n такое, что стоимость имитации ходов меньшей задачи даёт
`D_n <= D_{n-1} + (n-1)`, что по индукции с базой `D_4 = B_4 = 6` даёт
`D_n <= B_n` (C15), поскольку `B_n - B_{n-1} = n-1` тождественно (сумма
B-разности, немедленно из B_n = n(n-1)/2). Предупреждение правила из PLAN:
L и R вращают весь массив, фиксированный элемент нельзя молча исключать;
запас рекурренты нулевой (в диапазоне 4 <= n <= 12 разность D_n - D_{n-1}
равна n-1 точно на каждом шаге, т.к. D_n = B_n там).

## 0. Определение «тройного разреза»

Для `p in S_n` (массив длины n) и позиции `i in {0,...,n-1}`: `v = p[i]`.
`REST` — массив p с удалённым индексом i (n-1 элементов, в исходном
циклическом порядке; удаление слота и смыкание окружности). Для сдвига
значения `s in {0,...,n-2}`: `base_order = [(v+1+t) mod n : t=0..n-2]`
(остальные n-1 значений в их естественном циклическом порядке, начиная
сразу после v); `order = base_order`, повёрнутый на s; `label[order[j]]=j`.
Для сдвига массива (реализации головы) `k in {0,...,n-2}`:

```text
p'_{i,s,k} = rotate_left( [label[x] for x in REST], k )   -- перестановка размера n-1
```

**Тройной разрез** p при (i, s, k) — это p'_{i,s,k}. Всего n(n-1)^2
кандидатов на p.

## 1. Находка

Численно (исчерпывающая проверка по сертифицированным таблицам,
5 <= n <= 9 — n=4 тривиальна как база):

```text
для всех p in S_n:  max_{i,s,k} d(p'_{i,s,k}) + (n-1)  >=  d(p)
```

т.е. у каждой p есть тройной разрез (i,s,k), для которого
`d(p) <= d(p'_{i,s,k}) + (n-1)`. Максимум по (i,s,k) — потому что нужен
разрез, чья задача размера n-1 «достаточно трудна» (даёт достаточно
большое d(p')), а не самый лёгкий: см. §2, почему минимум здесь не тот
критерий.

Проверено `experiments/h3_induction_probe4.py` (h3_induction_probe4-1.0):
точное равенство `max = 0` (граница острая, зазор нулевой) при каждом
5 <= n <= 9, ноль нарушений:

```text
n=5: 0 s          n=6: 0.2 s        n=7: 2.6 s
n=8: 39.5 s        n=9: 583.9 s (все 362 880 перестановок, все n(n-1)^2=648 разрезов)
```

Острота достигается на sigma_n при каждом n: разрез (i=n-1, s=0, k=0)
(удалить последнюю позицию, без сдвига значения и массива) переводит
`sigma_n` РОВНО в `sigma_{n-1}` (значение на последней позиции sigma_n —
это 2, вычитание 1 из значений > 2 у остатка даёт в точности sigma_{n-1});
`d(sigma_n) = B_n`, `d(sigma_{n-1}) = B_{n-1}`, `B_n - B_{n-1} = n-1` —
равенство без зазора автоматически. Кроме sigma_n острота встречается и на
других входах при n = 7, 8, 9 (например `(1,0,3,6,7,2,5,4)` при n=8).

## 2. Что перепробовано и отклонено по пути

1. **Пять фиксированных детерминированных правил** (удалить слот по
   значению: максимум, минимум; по позиции: первая, последняя; по
   голове: больший из двух под головой) — единственный кандидат на p, без
   выбора. Все проваливаются уже при n = 5, с растущим зазором и числом
   нарушений (`experiments/h3_induction_probe.py`, `report_n5_9.json`):

   ```text
   n=5: зазор 1 (9, 2, 2, 9, 6 нарушений из 120)
   n=8: зазор 3-4 (3017-3213 нарушений из 40320)
   n=9: зазор 3   (24234-27400 нарушений из 362880)
   ```

2. **Лучшая (самая ДЕШЁВАЯ) из n позиций** (минимум d(p') по всем позициям
   удаления, без сдвига значения и без вращения) — тоже проваливается,
   растущий зазор (`experiments/h3_induction_probe2.py`): зазор 1, 3, 3, 4, 4
   при n=5..9, до 152 794 нарушений из 362 880 при n=9.
3. **Лучшая (самая дешёвая) из n×(n-1) пар позиция+вращение** — ХУЖЕ, а
   не лучше (`experiments/h3_induction_probe3.py`): зазор растёт до 6 при
   n=8. Причина — минимум здесь неверный критерий: нужен разрез, ДОСТАТОЧНО
   ТРУДНЫЙ, чтобы годиться для трудной p, а не самый лёгкий; добавление
   вращения только расширяет выбор в сторону ЕЩЁ более лёгких кандидатов
   (правильный запрос — максимум, не минимум, см. §1).
4. Первая попытка с максимумом, но БЕЗ вращения и сдвига значения (только
   позиция) — уже намного лучше: точное совпадение (зазор 0) при n = 5, 6;
   1 нарушение (зазор 1) при n = 7; 62 нарушения (зазор до 2) при n = 8.
5. Максимум по (позиция, вращение), без сдвига значения — зазор 0 при
   n <= 7; ровно 1 нарушение при n = 8 (зазор 1, вход
   `(3,6,0,7,4,5,2,1)`, d=23, нужно d(c) >= 16, лучшее без сдвига
   значения — 15).
6. Добавление сдвига значения s (полный «тройной разрез», §0, §1) снимает
   и это последнее нарушение: для того же входа находится (i=7 или 6,
   разные s,k) с d(c) = 16 — ровно достаточно.

Вывод: три степени свободы нужны одновременно (позиция удаления, сдвиг
значения остатка, вращение массива); ни одна пара не достаточна уже при
n = 8, а полный набор — исчерпывающе достаточен при 4 <= n <= 9.

## 3. Статус: необходимое условие подтверждено, конструкции нет

То, что показано в §1 — числовое НЕОБХОДИМОЕ условие для индуктивного
доказательства `D_n <= D_{n-1} + (n-1)`: если бы оно не выполнялось для
какой-то p, никакая лифтинг-конструкция вида «решить p'_{i,s,k} и
доплатить n-1 ход» не могла бы существовать для этой p ни при каком
алгоритме. Подтверждение (VERIFIED 5 <= n <= 9, по независимым
сертифицированным таблицам d для n и n-1) — это НЕ доказательство: мы
не предъявили ни одного реального слова длины `d(p'_{i,s,k}) + (n-1)`,
сортирующего p; только показали, что арифметика (два табличных числа)
согласована.

## 4. К конструкции: препятствия

Набросок того, что нужно реальной конструкции (случай i = n-1 для
конкретности; тогда REST занимает настоящие позиции 0..n-2 без сдвига, и
«шов» — это ребро {n-2, 0} малой окружности размера n-1, которое в
БОЛЬШОЙ окружности не является настоящим рёбром: между ними стоит позиция
n-1 со значением v):

1. **Пересечения при вращении.** Каждый L/R геодезического слова малой
   задачи, пересекающий шов {n-2,0}, требует 2 настоящих хода вместо 1
   (обойти позицию n-1, не трогая её); остальные L/R — 1 к 1.
2. **Обмены на шве.** X малой задачи РОВНО на шве (обмен малых позиций
   n-2 и 0) не реализуем напрямую: эти позиции не смежны в большой
   окружности. Нужно либо избегать этого ребра в выбранной геодезической
   малой задачи, либо платить отдельно. Избегание одного ребра окружности
   — это ТОЧНО линейная модель H13 (`docs/notes/h13_line_model.md`):
   `d_line(p') - d(p')` при 4 <= n <= 9 равно 0 на большинстве входов, но
   до 4-5 на некоторых (аффинные входы, n=8,9; C33) — т.е. эта дорога
   заново вносит открытый разрыв H13, а не обходит его.
3. **Возврат v и остаточных сдвигов.** После решения p'_{i,s,k} значение v
   всё ещё стоит на позиции i (не потревожено), а массив сортирован не к
   id_{n-1}, а с точностью до сдвига значений s и вращения k. Нужно:
   переставить v на его целевую позицию; отменить сдвиг s (обычно
   поворотом сортированного участка); отменить вращение k. Все вместе —
   отдельная стоимость, не оценённая.

Сумма всех четырёх слагаемых (п.1-3, три штуки) должна укладываться в
бюджет n-1 ОДНОВРЕМЕННО с тем, что (i,s,k) выбраны так, чтобы d(p') было
максимальным (§1) — то есть выбор (i,s,k), закрывающий числовое условие,
и выбор, минимизирующий стоимость пересечений шва, могут конфликтовать;
согласованность этих двух требований не проверена.
