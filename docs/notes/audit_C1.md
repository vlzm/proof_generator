## 1. Вердикт

Логические переходы §§1–6 проверены по одному (ниже); ни одной ложной
леммы или пробела не найдено. Независимая реализация (`checks/check_C1.py`,
написана по тексту, не по `lrx_2n3_check.py` — правило 3 AGENTS.md)
подтверждает: конструкция сортирует любую перестановку, длина укладывается
в заявленную границу, и все промежуточные неравенства (1)–(12) выполняются
на проверенных диапазонах, включая исчерпывающий перебор нетривиальных
циклов Z_n при 4 <= n <= 8 (13699 циклов при n = 8 — точное число
(n-1)! + ... по всем длинам цикла, без выборки) и всех перестановок при
4 <= n <= 7.

Итог для реестра: **C1 -> PROVED (локальный аудит одной сессии, один
аудитор)**. Раздел 6 (пример точности коэффициента 5/3) — тоже проверен и
подтверждён; он не задевает саму теорему (см. §2.6 ниже).

## 2. Переходы, проверенные вручную

### §1. Нагрузки цикла (F, h_i, M, t, E)

- Знаковая длина `d_j` кратчайшего пути `a_j -> a_{j+1}`: определение
  однозначно, кроме антиподального случая (n чётно, `|d|=n/2`), где текст
  прямо разрешает любое направление («choose either direction in a tie»).
  Для конструктивной проверки зафиксирован явный выбор — положительное
  направление (как и в `lrx_2n3_check.py`); теорема требует существования
  ХОТЯ БЫ одного рабочего выбора, так что фиксация одного явного правила
  достаточна для проверки самой теоремы (не для проверки инвариантности
  относительно выбора — это не заявлено).
- (1): проверено НЕ доверием к рекуррентной формуле, а прямым пересчётом
  `h_i` из явного списка рёбер каждого пути (`checks/check_C1.py:
  check_eq1_load_step`) и сравнением разности с ожидаемым знаком —
  исчерпывающе на всех циклах при 4 <= n <= 8.
- (2) `F+k <= nM+E`: следует из «t различных рёбер перед подъёмами имеют
  нагрузку `<= M-2`» — интуитивно ясно (при подъёме на ребре нагрузка
  скачет с `<=M-2` до `M`, поэтому непосредственно предшествующее ребро
  ограничено), и подтверждено прямым вычислением на всех циклах
  4 <= n <= 8 без единого нарушения.
- Существование вершины-переносчика `b` (максимум нагрузки на месте
  подъёма `-to+`) при смешанных знаках: проверено (`find_carrier`)
  исчерпывающе — таких вершин 0 не найдено ни разу.

### §2. Реализация цикла через carrier

- Тождество «резерв слота 0 через `XL`/`RX`»: `XL[x0,...]=[x0,x2,...,x1]`,
  `RX[x0,...]=[x0,x_{n-1},x1,...,x_{n-2}]` — проверено прямым применением
  `oracle.moves.apply_word` на явных состояниях (в составе исчерпывающего
  прогона, поскольку каждый ход `plan_cycle` строит именно такими блоками).
- «Внутреннее слово `W_C` не включает начальный поворот» — учтено явно
  в независимой проверке: изолированный тест применяет `W_C` только
  ПОСЛЕ `L^b` (перенос позиции `b` на индекс 0) и отменяет его `R^b` после,
  сравнивая результат с `C^{-1}` (в форме перестановки-массива) — иначе
  тест сам по себе проверял бы не то, что доказывает текст (первая версия
  чекера содержала эту ошибку и была исправлена по факту исполнения кода,
  не по чтению текста — см. замечание в §3).
- Стягивание ребра `{b,b+1}` и подсчёт `A=F-M`: подтверждено — число
  «шагов кольца» на сегмент считается как число рёбер пути, НЕ равных
  стянутому ребру; сумма по всем сегментам исчерпывающе совпадает с
  `F - h_b` на всех проверенных циклах (что численно равно `F-M`, так как
  `b` выбран с `h_b=M`).
- Дизъюнктные сокращения `XX`: не проверялись отдельно как самостоятельная
  лемма — их эффект (итоговая длина `<= 2F-S(C)`) проверен напрямую через
  `freely_reduce` и сравнение с границей (4) на каждом цикле; довод
  «сокращения можно выбрать непересекающимися» — комбинаторный аргумент
  о том, что положительный сегмент отдаёт первую букву только предыдущему
  обмену, а отрицательный — последнюю только следующему; проверен на
  примерах, не переформулирован как отдельная лемма (не требуется: итоговое
  неравенство длины проверяется напрямую).

### §3. Оценка `3nS(C) >= 5(F+k)` (уравнение 5)

- Алгебра (6) `3nS(C)-5(F+k) >= n(M-3)+(3n-5)E` проверена вручную
  подстановкой `S(C)=2M+E-1` в `3n S(C) - 5(F+k)` и сравнением с (2) —
  совпадает с текстом координата в координату.
- Случай `M=1`: (1) действительно запрещает знакопеременность (доказано от
  противного: переход `-to+` дал бы `h_{i-1}=h_i-2<=-1<0`, невозможно для
  счётчика рёбер) — значит `t=0`, `E=k`.
- Случай `M=2, E=0`: разбор про единственный подъём `0->2`, связный
  носитель, `k=2` (транспозиция), `S=3`, `F<=n` — переход прямой, ошибок
  не найдено.
- Вся лемма проверена ИСЧЕРПЫВАЮЩЕ по всем нетривиальным циклам Z_n при
  4 <= n <= 8 (`checks/check_C1.py: check_eq5`) — ни одного нарушения.

### §4. Комбинирование циклов и вращений (f_c, F_c, N_c, H(c))

- Тождество (7) `pi o f_c^{-1} o lambda^c = id`: чисто алгебраическое,
  из `f_c = lambda^c o pi` — подстановкой; сверено с конвенцией композиции
  PROBLEM §3 (применение хода — композиция состояния с позиционной
  перестановкой СПРАВА), совпадает.
- (9) `H(c)`: маршрут «в длинную сторону, затем в короткую» — построен
  независимо (`universal_route`) и проверено, что он посещает КАЖДУЮ
  вершину ровно по разу и заканчивается в `c`, при длине, не превышающей
  `H(c)`, — на всех проверенных n (исчерпывающе и выборочно).
- (10): не проверялось как отдельное неравенство над `F_c, N_c` — вместо
  этого проверена БОЛЕЕ сильная и достаточная вещь: реальная построенная
  длина слова `<= (2-5/(3n))F_c - 5/(3n)N_c + H(c)` точной дробной
  арифметикой (`Fraction`), что вместе с фактическим применением слова
  и сверкой с `id_n` строже, чем просто численная проверка неравенства.

### §5. Усреднение (уравнения 11–12)

- `(1/n) sum_c F_c = P` и `(1/n) sum_c N_c = n-1`: это тождества,
  верные для КАЖДОЙ pi по отдельности (не только в среднем по pi) —
  выведено из того, что при фиксированном i значения `f_c(i)` пробегают
  весь `Z_n` при варьировании c. Проверено точной дробной арифметикой на
  нескольких pi (включая id) при 4 <= n <= 8 — совпадает всегда, как
  и предсказывает алгебра (тождество не зависит от pi, так что несколько
  проверок достаточно для отлова ошибки реализации, не для проверки
  общего случая — сама алгебраическая причина проверена вручную выше).
- `(1/n) sum_c H(c) = n-2+(P+2)/n`: не зависит от pi вообще; проверено
  точной дробной арифметикой для 4 <= n <= 8.
- Финальная подстановка в (10) и взятие целой части: сверено с
  `bounds/known.py: baseline_bound_2n3` (уже существующий модуль проекта,
  контрольные значения совпадали и раньше) — независимо пересчитанная
  формула потолка `ceil((2P+11n-11)/(3n))` совпала с `baseline_bound_2n3`
  на 2003 значениях n (4..2000, 5000, 10000, 100000).
- Второй (более слабый) вид границы `C(n,2)+floor(4n/3)-3`: проверено, что
  первая граница `<=` второй при n >= 5, и что обе равны 8 при n = 4 —
  как и утверждает текст.

### §6. Пример точности (не часть теоремы)

- Семейство `C_r` при n=4r: заявленные `k=8, t=4, E=0, F=3n-8, M=3,
  S(C_r)=5` пересчитаны независимо (не по формуле текста, а по прямому
  построению путей и нагрузок) для r = 2..8 — совпадают точно, включая
  равенство `3nS(C_r)=5(F+k)` (точность коэффициента 5/3 подтверждена).
  Текст сам оговаривает, что это НЕ контрпример и не влияет на теорему —
  согласен, раздел только показывает точность вспомогательной леммы (5).

## 3. Замечания к изложению (не пробелы)

- Раздел 2 не проговаривает явно, что `W_C` предполагает уже выполненный
  перенос `carrier` на индекс 0 (это следует из фразы «excluding the
  initial positioning rotation», но не выделено формулой) — первая версия
  независимого юнит-теста ошиблась именно на этом месте (применяла `W_C`
  к `id_n` напрямую); ошибка была в ЧЕКЕРЕ, не в тексте, и исправлена по
  явному указанию текста после разбора несовпадения. Стоит отметить явно
  при последующих чтениях как типичную ловушку.
- «Choose either direction in a tie» — теорема не требует единообразия
  выбора; для КОНКРЕТНОЙ проверяемой конструкции нужен один фиксированный
  выбор (см. §2, §1) — это отмечено, но в тексте явного канонического
  правила нет (сопровождающий код выбирает положительное направление;
  этого достаточно для доказательства теоремы, раз существование
  подтверждено).

## 4. Численное сравнение с истинным d(pi) (диагностика, не часть доказательства)

`checks/check_C1.py` дополнительно сравнивает длину построенного слова
с истинным `d(pi)` по сертифицированным таблицам (C2v, 4 <= n <= 12,
n=11,12 — воспроизведены локально для этой проверки, не закоммичены):

| n | bound (floor(A_n)) | B_n | max(len - d(pi)) на выборке |
|---|---|---|---|
| 8 | 35 | 28 | 6 |
| 9 | 44 | 36 | 10 |
| 10 | 55 | 45 | 10 |
| 11 | 65 | 55 | 10 |
| 12 | 78 | 66 | 14 |

Согласуется с известным из PROBLEM §5.1: запас `floor(A_n)-B_n` растёт
линейно (~4n/3), и сама конструкция (не только оценка) действительно
использует бОльшую часть этого запаса на выборке — не только доказанная
граница рыхлая, слова тоже длиннее нужного. N1 (C16, уже PROVED) и
`constructions/strict_upper.py` дают заметно более короткие слова на тех
же входах (см. `data/runs/strict_loss_audit/`); C1 остаётся исторически
первой удостоверенной оценкой, не лучшей по факту.

## 5. Итог
