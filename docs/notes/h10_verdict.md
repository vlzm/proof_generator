# H10 (C27): состояние после сессии 4 — что доказано, что мешает

Дата: 13.09.2026. Бюджет PLAN §8: 2 сессии до письменного вердикта;
израсходована 1. Это промежуточный вердикт: общий случай не доказан,
препятствия названы, конечное покрытие расширено до n = 11.

## 1. Что установлено

1. **Отражения — доказано** (C28, `docs/proofs/C28_reflections.md`,
   чекер `checks/check_C28.py` PASS при 4 <= n <= 60). Для `pi(i) = h - i`
   `min_c [2F_c - S_c + H(c)]` равно B_n (n нечётно; n чётно и h нечётно),
   B_n - 1 (n = 0 mod 4, h чётно), B_n + 1 (n = 2 mod 4, h чётно). Аргумент:
   F_c и S_c зависят от c только через чётность h + c (леммы 1–3), а
   `H(c) <= n` при c из {0, ±1}. Отсюда первая часть H10 на отражениях.
2. **Точность «+1».** Для варианта с маршрутом R_c минимум равен ровно
   B_n + 1 на отражениях с n = 2 (mod 4) и чётным h, 2 <= h <= n/2 - 1, при
   всех 6 <= n <= 58 (`data/runs/check_C28/report.json`). Первая часть H10
   не усиливается до `<= B_n`; усиление возможно только со свободным
   сокращением (вторая часть).
3. **Исчерпывающая проверка первой части до n = 11**
   (`experiments/h10_scan.py`, `data/runs/h10_scan/`): все перестановки,
   все сдвиги, только оценка `2F_c - S_c + R_c` без построения слов (тождество
   «длина слова = оценка» повторно сверено построением слов на всех pi
   при 4 <= n <= 7, 40 296 пар (pi, c)). Максимум `min_c - B_n`:

   | n | 4 | 5 | 6 | 7 | 8 | 9 | 10 | 11 |
   |---|---|---|---|---|---|---|---|---|
   | max | 0 | 0 | +1 | 0 | 0 | 0 | +1 | 0 |
   | входов с max | 1 | 2 | 1 | 3 | 11 | 10 | 6 | 21 |

   При n = 10 шесть входов с +1: два отражения (h = 2, 4, как в C28) и четыре
   не-отражения, среди них аффинные `i -> 2 + 7i` и `i -> 4 + 3i` (mod 10).
   Время: n = 10 — 279 с, n = 11 — 3 322 с на 4 процессах. Вторая часть H10
   (после сокращения) при n = 10, 11 не проверялась.
4. **Структура экстремальных входов при лучшем c** (все входы с
   `min_c = B_n` или B_n + 1, n = 8..11): всегда `R_c <= n`, `|F_c - P| <= 2`
   (при n = 10 ровно ±1, при n = 9 ровно 0), `S_c >= 3K_c`; но `E_c = 0`
   (все циклы — «чистые» транспозиции по знакам) лишь у части входов
   (n = 8: 2 из 11; n = 11: 8 из 21). То есть у экстремальных входов лучший
   сдвиг одновременно почти-медианный по F и с переносчиками, не требующими
   обхода длиннее n; это наблюдение, а не лемма.

## 2. Что не работает (препятствия для общего доказательства)

1. **Усреднение по c не годится даже с маршрутом R_c.** Максимум по pi
   величины `mean_c [2F_c - S_c + R_c] - B_n` равен 1/2, 0, 1, 5/7, 3/2, 14/9,
   12/5, 25/11 при n = 4..11, а на отражениях с h около n/4 растёт линейно:
   18.52 при n = 100 (h = 25), ≈ 0.185 n (`data/runs/h10_scan/families.md`).
   Причина: на таких отражениях `mean_c R_c` ≈ 1.17 n при s = 3(n-1)/2, а
   для B_n нужно `s - mean_c R_c >= floor(n/2)`. Поэтому любой аргумент вида
   «оценим среднее по c» (как (3.4) в N1) даёт в лучшем случае
   `B_n + Θ(n)`; доказательство H10 обязано выбирать c.
2. **Простые правила выбора c не работают.** По всем перестановкам:
   - медиана F (`c` из `argmin_c F_c`, F_c = 1-медиана мультимножества
     {i - pi(i)}): максимум избытка 0, 0, +1, 0, +2, +2, +2, +4 при n = 4..11; пример n = 8, pi = (0,1,6,3,7,5,2,4):
     F = 14 при c = 0, но S = 6, R = 8, итого B_n + 2, тогда как c = 2 даёт
     F = 16, S = 10, R = 2 — B_n - 4;
   - `c` из {0, ±1}: избыток до +14 (n = 8), +29 (n = 10), +30 (n = 11);
   - минимизатор оценки лежит в `argmin_c F_c` лишь у 82–89 % входов
     (32 990 из 40 320 при n = 8; 27 258 705 из 39 916 800 при n = 11).
   Значит, F-часть (то, что даёт медиана) не определяет лучший сдвиг:
   выигрыш в F теряется в S и особенно в R_c, а R_c зависит от положения
   переносчиков относительно 0 и c — величины, не видной ни F_c, ни S_c.
3. **Экстремальные входы — не только отражения.** При n = 8 из 11 входов с
   `min_c = B_n` только 2 отражения; остальные на расстоянии Хэмминга 4–6 от
   любого отражения, с циклами длины 3, 4, 6; при n = 9 — 4 отражения из 10,
   при n = 11 — 5 из 21. Возмущённый аргумент «pi далеко от отражения =>
   есть запас» не проходит в такой форме; нужна инвариантная характеристика
   экстремальных входов (при лучшем c у них `|F_c - P| <= 2` и `R_c <= n`,
   §1 п. 4; при всех ли c `F_c` около P — не проверено).
4. **Собственный маршрут H(c) не годится** (H9 REFUTED, C26): любое
   доказательство H10 должно работать с R_c, для которого леммы N1 не
   написаны; перенос C18 на R_c тривиален по (3.1) (порядок посещения
   переносчиков не важен), но оценка R_c требует знать переносчики.

## 3. Что нужно доказательству (формулировка препятствия)

Нужно для каждой pi указать c с

```text
S_c - R_c >= 2(F_c - P) + floor(n/2) - 1.
```

На отражениях при c из {0, ±1}: `F_c - P` из {-1, 0, 1}, `S_c = 3K_c` ≈ 3n/2,
`R_c <= n`, запас ≈ n/2 расходуется ровно. В общем случае нижних оценок
`S_c` при конкретном c нет (в N1 есть только средняя по c, (7.3), и она
теряет ≈ 0.9 n), а `R_c` меняется от `delta(0, c)` до ≈ 3n/2 в зависимости
от переносчиков. Кандидат на следующий шаг (сессия 5, остаток бюджета):

1. По §1 п. 4 сформулировать промежуточную цель: для каждой pi найти c с
   `F_c <= P + 2`, `R_c <= n` и `S_c >= 3K_c` одновременно и доказать, что
   такого c достаточно; сначала проверить на всех pi при n <= 11, что
   такой c существует и что он даёт `<= B_n + 1` (не обязательно
   минимизатор). Если существует не всегда — искать, какое из трёх
   условий ослабить.
2. Оценка снизу для `S_c` через `F_c`: `S(C) >= 2M(C) >= 2F(C)/n` слишком
   слаба; нужна оценка, использующая число циклов K_c и `E_c`
   (`S_c = 2 sum M + E_c - K_c`).
3. Если за сессию 5 не появится схемы, дающей на отражениях запас 0 и на
   всех входах n <= 11 неотрицательный запас, — итоговый вердикт «H10 без
   доказательства; препятствия §2», и переход к другому направлению §4.2
   (например, H8/C25: формула длины на sigma_n как локальное C9).
