# H12, шаг (2): вердикт — формула длины политики «горизонт» не доказана

Дата: 13.09.2026 (сессия 7). Бюджет `docs/notes/h12_horizon.md` §5 п. 3:
2 сессии до вердикта; израсходованы обе (сессия 6 — шаг 1, эта сессия —
шаг 2, последняя). Ядро oracle-1.0, конструкция `constructions/candidate_sweep.py`
(sweep-1.3, `mode="horizon"`, H = 3, w = 0.5, thr из {1, 2}, c из {0, 1}).
**Итог: формула длины политики «горизонт» на отражениях не доказана; найден
новый, более сильный численный факт (реестр C32), но путь к общему
доказательству упирается в характеризацию поведения самого поиска с
горизонтом, а не в недостающую лемму. Решение: не продолжать это
направление, перейти к индукции H3 (PLAN §4.3, п. 3).**

## 0. Задача сессии

По `docs/notes/h12_horizon.md` §5 п. 3: доказать для политики «горизонт» на
`pi_h(i) = h − i mod n` при c из {0, 1} (а) `N_X = floor((n−1)^2/4)` как
тождество `N_X = F_c/2 + single` с доказанным числом одинарных обменов и
(б) `N_rot <= floor(n^2/4)` напрямую из механики политики, без обращения
к конструкции N1_R. Критерий: доказанная формула (новая строка PROVED) либо
письменный вердикт с переходом к H3.

## 1. Что подтверждено вычислениями (сильнее, чем C30)

Трассировка политики (`sweep_word`, `mode="horizon"`, независимая реплей-
проверка Phi по определению rem/target — не читает внутренности поиска)
на **всех** отражениях при 4 <= n <= 30 (исчерпывающе, все h) и на выборках
h при n в {50, 60, 80} (плюс отдельно n = 100 для одного лишь N_X) даёт:

1. **Выбор c совпадает с C28.** Для чётного n ровно один из c в {0, 1} не
   даёт тупика (для нечётного n годятся оба); рабочий c всегда даёт
   `h' = h + c` той же чётности, что и в лемме 4 `docs/proofs/C28_reflections.md`
   (нечётное h' при n = 0 mod 4, чётное — при n = 2 mod 4). Это не было
   очевидно заранее: правило выбора сдвига для тупика (чисто механическая
   причина — наличие ребра с `gain >= 1`) и правило выбора сдвига в
   доказательстве C28 (минимизация маршрута H(c)) получены независимо, но
   совпадают.
2. **Каждый обмен — двойной или холостой.** Для каждого X в слове разность
   `Phi_после − Phi_до` равна ровно −2 (оба элемента продвигаются к цели,
   «двойной») или 0 (один элемент продвигается, второй — уже стоящий на
   своём месте бесхозный элемент «отодвигается» на 1, «одинарный»,
   формулировка правила 8/документации sweep-1.3: «carry a bystander»).
   Обменов с `|ΔPhi| = 1` или `ΔPhi = +2` политика с `thr = 1` никогда не
   делает на этом семействе входов (кодовая эвристика `gain` здесь никогда
   не срабатывает во вред).
3. **Тождество и явная формула.** Отсюда `N_X = double + single`, где
   `double = F_c/2` (F_c — величина из леммы 2 C28 при рабочей чётности h'),
   и, что не следует ни из чего доказанного, **single = floor((n − 2)^2/8)
   одно и то же число для всех h при фиксированном n** (проверено
   исчерпывающе по всем h при 4 <= n <= 30 и выборочно при n = 50, 60, 80;
   отдельным вспомогательным прогоном без разложения на double/single —
   совпадение `N_X` также при n = 100). Алгебраически (леммы 2 C28 для F_c,
   три случая по n mod 4)

   ```text
   double + single = F_c/2 + floor((n-2)^2/8) = floor((n-1)^2/4)
   ```

   тождественно совпадает с целевой формулой во всех трёх случаях n mod 4
   (арифметика — ниже, §2). Это даёт явную, проверенную вычислением формулу
   `N_X = floor((n−1)^2/4)` в РАЗЛОЖЕННОМ виде, который требовала задача
   (п. 1), но не её доказательство: пункт «single не зависит от h» —
   утверждение о поведении алгоритма поиска, а не тождество, выведенное из
   определений.

Чекер `checks/check_C32.py`: PASS, `4 <= n <= 30` исчерпывающе (все h),
выборочно `n = 50, 60, 80`; отчёт `data/runs/check_C32/report.json` (отдельным
вспомогательным прогоном, без полного разложения на double/single, — то же
совпадение `N_X` при n = 100, выборка h).
Зарегистрировано как C32 (VERIFIED, не PROVED).

## 2. Алгебра тождества (для протокола)

Ниже — арифметика, а не обоснование того, почему single не меняется по h;
он использует ТОЛЬКО то, что F_c и single взяты как константы по лемме 2
C28 и по найденной эмпирической формуле. Обозначим `P = floor(n^2/4)`,
`target = floor((n−1)^2/4)`. По лемме 2 C28,
на рабочей чётности h':

```text
n нечётно:      F_c = P = (n^2−1)/4              double = (n^2−1)/8
n = 0 (mod 4):   F_c = P = n^2/4  (h' нечётно)    double = n^2/8
n = 2 (mod 4):   F_c = P − 1 = (n^2−4)/4 (h' чётно) double = (n^2−4)/8
```

Прямая подстановка `single = target − double` даёт (n нечётно: `(n−1)(n−3)/8`;
n = 0 mod 4: `n(n−4)/8`; n = 2 mod 4: `(n−2)^2/8`), и все три выражения
равны `floor((n−2)^2/8)`:

- n нечётно: `n − 2` нечётно, `(n−2)^2 ≡ 1 (mod 8)` (квадрат нечётного),
  `(n−2)^2 − 1 = (n−1)(n−3)`, отсюда `(n−1)(n−3)/8 = floor((n−2)^2/8)`.
- n = 0 mod 4: `n − 2 ≡ 2 (mod 4)`, `(n−2)^2 ≡ 4 (mod 16)` — делится на 4,
  не на 8; `(n−2)^2 − 4 = n(n−4)`, а `n(n−4)` при n = 0 mod 4 делится на 8
  (n делится на 4, n−4 чётно), так что `n(n−4)/8 = floor((n−2)^2/8)`.
- n = 2 mod 4: `n − 2 ≡ 0 (mod 4)`, `(n−2)^2` делится на 16, значит и на 8:
  `(n−2)^2/8` — целое, совпадает с `floor(·)` без остатка.

Это чистая арифметика по трём случаям — проверена и вручную, и чекером
(`Fc_formula`/`single_formula` в `checks/check_C32.py`).

## 3. Почему это не доказательство: обструкция

Единственный недоказанный факт во всей цепочке — п. 1.3: **`single` не
зависит от h.** Ниже — почему это не сводится к лемме, которую можно было
бы написать за оставшийся бюджет.

1. **Сведение к инвариантности относительно старта головы.** Величина
   `rem(pos)` в политике зависит только от `h' = h + c`:
   `rem(pos) = signed_step(pos, h' − pos, n)`. Прямая проверка тождества
   даёт `rem_{h'+2t}(pos + t) = rem_{h'}(pos)` для любого целого t — то есть
   конфигурация при параметре `h' + 2t` есть конфигурация при параметре h',
   повёрнутая на t позиций. Голова, однако, ВСЕГДА стартует в позиции 0 (не
   поворачивается вместе с конфигурацией). Поэтому «single не зависит от h»
   при фиксированном n эквивалентно: **полное число одинарных обменов,
   которые делает политика с горизонтом, не зависит от того, в какой точке
   окружности относительно неподвижной оси отражения стартует голова.**
   Это утверждение не о геометрии входа, а о поведении конкретного
   алгоритма поиска (жадный выбор с горизонтом 3, взвешенная оценка листа,
   разрешение ничьих направлением) на семействе входов, различающихся
   только поворотом начальной точки.
2. **Симметрия входа не решает вопрос.** Конфигурация симметрична
   относительно оси h'/2 (`rem_{h'}(h' − pos) = −rem_{h'}(pos)`), но эта
   симметрия — отражение вокруг оси, а не поворот вокруг круга; она не
   тождественна переносу стартовой точки головы и не даёт немедленно
   инвариантности относительно него.
3. **Трассы не сворачиваются в короткое описание.** Прямая трассировка
   (для нескольких n и h, без предположений) показывает, что при горизонте
   3 голова не делает ни «две развёртки» (как геодезические аффинных
   входов, `docs/notes/geodesic_structure.md`), ни «короткие локальные
   колебания вокруг одного переносчика» (как N1 на отражениях): обмены,
   относящиеся к парам позиций `{i, h'−i}` с сильно разными i, чередуются
   на соседних шагах (например, при n = 10, h = 0, c = 0 обмены идут в
   порядке позиций 0, 9, 0, 1, 0, 9, 8, 9, 0, 1, 4, 5, 4, 3, 4, 5, 6, 5, 4,
   3 — без разбиения на «сначала одна пара, потом другая»). Это
   ожидаемо для поиска с горизонтом 3 и весом Phi/2: решение в каждой точке
   сравнивает ветки по числу шагов до продуктивного ребра в обе стороны,
   и какая пара «выигрывает» в моменте t зависит от всей истории обменов
   до t, а не от локального правила. Индуктивный инвариант (что-то вида
   «после k обменов голова находится в известной позиции и оставшаяся
   Phi имеет известную форму») пришлось бы формулировать и доказывать по
   шагам поиска, что фактически означает переписать симуляцию поиска в
   виде доказательства — не сокращение, а повторение вычисления.
4. **Пункт (б) строже пункта (а).** Даже приняв п. 1.3 на веру, `N_rot`
   (в отличие от `N_X`) **не является инвариантом по h**: для n = 9 набор
   `N_rot` по h = 0..8 равен 17, 19, 17, 20, 18, 19, 19, 18, 20 (максимум 20
   = floor(81/4) — точно на sigma_9, h = 1); для n = 10 (`N_rot` по
   h = 0..9): 21, 21, 21, 22, 22, 23, 23, 22, 22, 21 (максимум 23 <
   floor(100/4) = 25 — здесь не точно). Доказательство `N_rot <=
   floor(n^2/4)` требует не константы, а верхней оценки, зависящей от h,
   которая ещё не охарактеризована; при этом п. 2 задачи явно запрещает
   опору на N1_R, а весь наработанный по политике аппарат (single, F_c) —
   это утверждения о `N_X`, они не дают рычага для `N_rot` без того же
   самого прослеживания траектории головы.
5. **Общая причина.** Конструкция N1 и «развёртка» — это ЯВНЫЕ правила
   (для каждой позиции обменa заранее известно, в какую сторону идёт
   голова и когда). «Горизонт» — это ПОИСК: решение в каждой точке —
   результат сравнения оценок веток глубины 3 с эвристическим весом Phi.
   Доказательство длины явной конструкции — это подсчёт по формуле;
   доказательство длины результата ПОИСКА требует либо (i) доказать, что
   поиск с горизонтом 3 на этом входе эквивалентен какому-то явному
   правилу (не найдено — трассы не совпадают с N1_R, см. §4 ниже, и не
   распадаются на две развёртки), либо (ii) провести индукцию по шагам
   самого поиска, что для ветвящегося процесса с горизонтом и весами —
   задача сопоставимая по объёму с построением отдельного доказательства
   длины экстремального пути (C15), а не с производной от неё леммой.

## 4. Слова горизонта не совпадают со словами N1_R

Для контроля: на отражениях при равном N_X слово «горизонта» после
свободного сокращения ПОЧТИ никогда не совпадает буква в букву со словом
N1_R при том же c (сверено при 7 <= n <= 12: совпадение только у 3 из 57
пар (n, h) — n = 8, h = 6 и n = 12, h in {8, 10} — все на h около антипода,
где длина совпадает с B_n − 2).
Это ожидаемо: у «горизонта» на некоторых h длина СТРОГО меньше, чем у N1_R
(например n = 9, h = 1: горизонт 36 = B_n, N1_R 37 = B_n + 1) — политика не
воспроизводит N1, она находит собственные, иногда более короткие слова,
совпадающие по значению с известным наблюдением C31
(`d(pi_h) = B_n − delta_n(h, 1)` при 6 <= n <= 10): горизонт на многих h
достигает именно этой (не доказанной!) величины. Иными словами, длина слова
горизонта на отражениях эмпирически совпадает с ГИПОТЕТИЧЕСКОЙ формулой
истинного расстояния (C31), а не с более грубой оценкой N1 — что делает
прямое доказательство длины слова горизонта фактически ровно такой же
трудности, как доказательство самого C31 (тоже не доказанного, только
таблицы при 6 <= n <= 10).

## 5. Итог и решение

1. **H12(б) остаётся численным фактом, не доказательством.** Строка C30
   (сессия 6) усилена строкой C32 (эта сессия): точная формула `N_X` в
   разложенном виде `F_c/2 + floor((n−2)^2/8)`, совпадение выбора c с C28,
   отсутствие вредных обменов — всё подтверждено на исчерпывающем диапазоне
   `4 <= n <= 30` (все h) и выборочно до n = 80 (и n = 100 отдельным
   вспомогательным прогоном для `N_X`). Это не продвигает
   доказательство `D_n <= B_n` (C15): C9 (`d(sigma_n) <= B_n`) и
   `d(pi_h) <= B_n` для всех отражений уже PROVED через C28 без участия
   политики «горизонт» (см. `docs/proofs/C28_reflections_pr5.md`); горизонт
   на отражениях не даёт ничего, чего не давал бы уже доказанный N1_R —
   разница только в точности (горизонт иногда достигает d, N1_R — только
   B_n).
2. **Обструкция — не пробел в лемме, а сам метод.** Политика «горизонт»
   определена ПОИСКОМ (ветвление, горизонт 3, вес 0.5, разрешение ничьих),
   а не явным правилом; доказательство её длины требует либо свести поиск
   к явному правилу (не получилось — трассы не похожи ни на N1, ни на
   «развёртку»), либо провести индукцию по внутренним шагам самого поиска
   (эквивалентно передоказательству самой длины пути). Оба пути не
   уложились и, по имеющимся данным, не обещают уложиться в разумный
   бюджет: `N_rot` даже не является инвариантом по h (§3 п. 4), то есть
   тождества `N_X` (при всей его красоте) недостаточно даже для доказанной
   структуры — нужна отдельная, ещё не найденная характеризация `N_rot(h)`.
3. **Решение: не продолжать формулу длины политики «горизонт».** Это не
   путь к C15 в разумный срок. H12 закрывается на достигнутом (а) — PROVED
   (шаг 1, портфель); (б) — CONJECTURED/VERIFIED (C30, C32), без плана
   дальнейшего доказательства в рамках этого направления.
4. **Рекомендация: переход к H3** (PLAN §4.3, п. 3) — индуктивная редукция
   от `sigma_(n-1)` к `sigma_n`, бюджет 2 сессии до вердикта (см. PLAN §8).
   Обоснование выбора: H3 — единственное из оставшихся направлений §4.3,
   не опирающееся на устройство конкретной конструкции (N1, «развёртка»,
   «горизонт»), которое уже трижды (H10, H11, H12) упиралось в устройство
   алгоритма, а не в структуру задачи.

## 6. Побочное наблюдение для будущей сессии (не по бюджету H12)

Трассы политики «горизонт» на отражениях (§3 п. 3, §4) наводят на мысль
о явной, не основанной на поиске конструкции, которая напрямую
воспроизводит `d(pi_h) = B_n − delta_n(h, 1)` (C31) без горизонта поиска —
например, явное правило «два вложенных клина» с центром на оси и антиподе.
Это отдельная, не начатая задача (кандидатная, не часть текущего плана):
если такое явное правило существует и совпадает с горизонтом по значению,
у него, в отличие от горизонта, есть шанс на прямое доказательство длины
(явные правила считаются формулой, поиск — нет). Не включено в бюджет H12
и не входит в рекомендацию §5 п. 4.
