## 1. H13-I: попытка и вердикт

Задача (см. `docs/notes/h13_line_model.md` §6): доказать
`I(pi) <= floor((n-1)^2/4)` при всех `pi` из S_n, всех n >= 4, где `I(pi)`
— минимум числа инверсий линии по всем `n^2` двойным разрезам `(q, c)`.

### 1.1. Шаг (1) — исчисление сдвигов `(q, c)`

Построено и доказано (не только проверено численно) точное исчисление того,
как `inv(w)` меняется при единичном сдвиге `c` или `q`:

- **Лемма 1** (сдвиг значения `c -> c+1`): `delta = 2*posmax(c) - (n-1)`,
  где `posmax(c)` — позиция элемента с текущим максимальным значением.
- **Лемма 2** (сдвиг позиции `q -> q+1`): `delta = (n-1-2*w_0) + (n-1-2*j0)`
  — раскладывается на «перенос первого элемента линии в конец» и
  «применение леммы 1 к результату».
- **Лемма 3** (двойственность обращения): `inv(line(pi,q,c)) =
  inv(line(pi^{-1}, q-c, -c))`; следствие `I(pi) = I(pi^{-1})`.
- **Лемма 4** (точная формула двойного счёта): для точки отсчёта `(a,b)` из
  `Z_n x Z_n` и пары точек `{i,i'}` число точек отсчёта, при которых пара
  «согласована» (не образует инверсию), равно `(n-D)(n-D') + D*D'`, где
  `D = (i'-i) mod n`, `D' = (pi(i')-pi(i)) mod n` — точное тождество, не
  оценка.

Все четыре леммы — **PROVED** (полное алгебраическое доказательство, не
только проверка): `docs/proofs/H13I_cutoff_calculus.md`. Численно
подтверждены исчерпывающе для всех `pi, q, c` при 4 <= n <= 7 и выборочно
(60 случайных `pi` + `sigma_n` + `rev_n` на каждый n) для 8 <= n <= 18
(`checks/check_H13I_identities.py`, `data/runs/check_H13I_identities/`).
Зарегистрированы как **C37** (леммы 1–3) и **C38** (лемма 4).

Тождества сами по себе не доказывают H13-I — это калькулятор, а не оценка;
ниже — что было испробовано с их помощью и почему не хватило.

### 1.2. Шаг (2) — попытки построить доказательство

**(а) Усреднение по всем `n^2` разрезам (лемма 4 просуммированная).**
Точная формула суммы `S(pi) = sum_{i<i'} [n^2 - n(D+D') + 2DD']` даёт среднее
число согласованных пар `S(pi)/n^2`; нужно `>= floor(n^2/4)` хотя бы для
одной точки, для чего было бы достаточно (но не обязательно) `S(pi)/n^2 >=
floor(n^2/4)` в среднем. Прямая проверка (`checks/check_H13I_identities.py`,
часть C) показывает, что среднее **уже превышает** нужный порог на
`rev_n` (= `sigma_n` в смысле того же класса окружности — то же среднее)
при всех проверенных n:

| n | floor((n-1)^2/4) | среднее inv по всем n^2 разрезам на sigma_n/rev_n |
|---|---|---|
| 4 | 2 | 3.5 |
| 5 | 4 | 6.0 |
| 6 | 6 | 9.17 |
| 7 | 9 | 13.0 |
| 8 | 12 | 17.5 |
| 9 | 16 | 22.67 |
| 10 | 20 | 28.5 |

(Ранее в задании сессии упоминалась оценка среднего `(n^2-1)/6` — при прямой
проверке это число **меньше** фактического среднего на `sigma_n`/`rev_n` и
не соответствует замеру; возможно, спутано с другой величиной из более
ранней сессии. В любом случае вывод не меняется: усреднение не работает, и
не работает даже сильнее, чем предполагалось — среднее уже выше целевого
порога, а не только «недостаточно близко».)

Итог: усреднение исключено не только «в принципе» (как было записано
раньше), но и количественно — оно проваливается с фактором роста,
сопоставимым с самим `floor((n-1)^2/4)`, то есть не является «почти
достаточным» аргументом, который можно было бы спасти малой поправкой.

**(б) Однопараметрическое семейство `c = 0` (n кандидатов вместо n^2).**
Проверка (та же таблица, столбец `max_pi min_q inv(.,q,0)`,
`checks/check_H13I_identities.py`): при 4 <= n <= 8 максимум по `pi`
минимума по `q` при фиксированном `c = 0` равен 4, 6, 10, 12, 17 —
превышает `floor((n-1)^2/4)` = 2, 4, 6, 9, 12 при всех n. Это семейство
отличается от отвергнутого в `h13_line_model.md` §1.7 семейства «первый
элемент линии имеет значение t» (там перебирались n кандидатов вида
`(q, c(q,t))` для каждого t), но результат тот же: любое естественное
однопараметрическое подсемейство из n разрезов недостаточно уже при малых n,
подтверждая, что нужен совместный (двумерный) выбор `(q, c)`.

**(в) Прямая одномерная редукция.** Зафиксировав `q` (т.е. `t = pi`,
прочитанная с разреза `q`), минимум по `c` при этом `q` равен `inv(t, 0) +
2*min_c f(c)`, где `f(c) = Q(c) - c(n-1)/2`, `Q(c)` — сумма позиций `c`
наименьших значений в `t` (переписанная форма леммы C, `h13_line_model.md`
§4, через частичные суммы). `min_c f(c) <= 0` всегда (`f(0)=f(n)=0`), но
может быть равно 0 (например, когда `t` — развёрнутая последовательность:
`f(c) = c(n-c)/2 >= 0`), так что для «плохого» `q` сдвиг `c` не помогает
вообще, и всё зависит от выбора `q`. Совместная оптимизация двух шагов
(сначала `q`, затем `c`) не сводится к отдельному одномерному аргументу по
каждой переменной — тот же вывод, что и в §4 `h13_line_model.md`, но здесь
получен из явной формулы, а не только из контрпримера.

### 1.3. Вердикт H13-I

**Не доказано за сессию.** H13-I остаётся CONJECTURED, VERIFIED при
4 <= n <= 10 (без изменений, C33). Опробованные и отвергнутые подходы:
усреднение по всем n^2 разрезам (количественно проваливается, не только
качественно), однопараметрическое семейство `c=0`, прямая одномерная
редукция по `q` затем `c`. Не опробовано за отсутствием времени в рамках
бюджета: аргумент через веса/выпуклую комбинацию точек отсчёта вместо
равномерного среднего в лемме 4 (например, отсеять часть точек отсчёта по
структурному признаку и усреднять только по остатку); индукция по паре
удаляемых элементов (не одному, как в §1.7); связь с известными результатами
о `discrepancy`/`necklace splitting` для двух независимых круговых порядков
(не найдено время проверить применимость). Кандидат для следующей попытки —
именно неравномерный вес по лемме 4 (равномерное среднее слишком грубое:
проваливается с большим запасом, а не близко к порогу).

Новые строки реестра: **C37** (леммы 1–3, PROVED), **C38** (лемма 4, PROVED),
**C39** (H13-I как отдельная строка, CONJECTURED, VERIFIED 4<=n<=10 — без
изменений по существу, но теперь со своим ID и явной историей отвергнутых
подходов).

## 2. Пивот на H3 (`PLAN.md` §4.3, п. 3)

Вопрос сессии (по формулировке задания): есть ли явное, доказуемое
преобразование, берущее хорошее сортирующее слово для перестановки размера
`n-1` и продолжающее его до слова для перестановки размера `n` ценой
`<= n-1` (что при `T_4 <= 6` дало бы `D_n <= B_n` по индукции, так как
`B_n - B_{n-1} = n-1` — проверено алгебраически для обеих чётностей, C12).

### 2.1. Структурное препятствие («расфазировка на стыке»)

L и R вращают ВСЕ n позиций окружности, а не «первые n-1» — это отмечено
как проблема ещё в `PLAN.md` §4.3, но здесь оно конкретизировано и измерено.
Рассмотрим самый естественный способ «вложить» задачу размера n-1 в размер
n: взять слово `W`, sorting/строящее `pi'` на n-1 элементах, и **буквально
повторить ту же строку ходов** L/R/X на массиве из n элементов (с одним
лишним «пассажиром», занимающим фиксированный слот). Так как X всегда
меняет местами то, что сейчас под головой, а голова после `k` вращений
находится на позиции `k mod (n-1)` в маленькой задаче и `k mod n` в
большой, две схемы читают массив в РАЗНОМ порядке уже после первого полного
оборота (после `n-1` шагов вращения в одну сторону) — слово, ставшее
геодезическим для n-1 элементов, перестаёт делать то же самое действие на
n элементах. Величина накопленной расфазировки связана с суммарным пробегом
головы `N_rot(W)` слова `W`, а не с числом элементов (1), поэтому естественно
ожидать, что цена патча растёт с `N_rot(W)`, а не остаётся `O(1)`.

### 2.2. Измерение на sigma_n (конкретный пример, не общее доказательство)

Проверено прямо (эталонные ходы `oracle/moves.py`, точные расстояния
`exact/bfs.py`): взять явное слово C32 для `sigma_{n0}` (`h=1`), развернуть
его в слово `id_{n0} -> sigma_{n0}`, применить БУКВАЛЬНО ту же строку ходов
к `id_n` (n = n0+1, лишний элемент добавлен в конец массива), и измерить
расстояние от результата до `sigma_n`:

| n0 | len(слово для sigma_{n0}) = d(sigma_{n0}) | d(результат наивного повтора, sigma_n) | n-1 (бюджет) | сумма | B_n |
|---|---|---|---|---|---|
| 4 | 6 | 4 | 4 | 10 | 10 |
| 5 | 10 | 7 | 5 | 17 | 15 |
| 6 | 15 | 7 | 6 | 22 | 21 |
| 7 | 21 | 7 | 7 | 28 | 28 |
| 8 | 28 | 10 | 8 | 38 | 36 |
| 9 | 36 | 13 | 9 | 49 | 45 |

Патч (расстояние от результата наивного повторения до цели `sigma_n`)
превышает бюджет `n-1` уже при n0 = 5 (7 > 5) и растёт дальше (13 при
n0 = 9), кроме случайного совпадения при n0 = 7 (7 = n-1 ровно; при n0 = 4
тоже совпадение 4 = n-1). Это не опровергает существование ЛУЧШЕГО вложения
(здесь проверен только один наивный вариант — «дописать новый элемент в
конец массива и повторить ту же строку ходов»), но подтверждает
качественно: буквальное повторение слова меньшей задачи без учёта нового
элемента не даёт нужной цены `O(n)` систематически, согласуется с
рассуждением §2.1 о накоплении расфазировки, пропорциональном `N_rot(W)`
(здесь `N_rot(W) = floor(n0^2/4)`, растущему быстрее n).

Код: `experiments/h3_embed_probe.py` (h3_embed_probe-1.0), отчёт
`data/runs/h3_embed_probe/report.md`. 4 из 6 проверенных n0 (5, 6, 8, 9)
превышают бюджет `n-1`; совпадения при n0 = 4, 7 — частный случай, не
закономерность (n0 = 10 не считался: `bfs_dict(11)` на 39.9 млн состояний
в этом пробном скрипте не уложился в 2 минуты — не по существу пробы,
а по бюджету; при продолжении работы по H3 стоит использовать
сертифицированные таблицы `data/tables/dist_n11.bin` вместо BFS на лету).

### 2.3. Вердикт H3 (эта сессия)

**Не решено, реальное препятствие найдено и приблизительно измерено.**
Наивная индукция «вставить новый элемент фиксированным образом + повторить
слово меньшей задачи» не даёт цены `O(n)`; нужна конструкция, которая
явно управляет моментами, когда голова «проходит» позицию нового элемента
(вставлять компенсирующий ход именно в эти моменты, а не патчить только в
конце) — это открытая инженерная/комбинаторная задача, не решённая здесь.
Не проверено за бюджет (кандидаты для следующей попытки, по убыванию
приоритета):

1. Вставлять новый элемент не в фиксированный слот, а «синхронно с головой»
   (например, всегда прямо перед текущей позицией головы в момент вставки,
   так что первый проход головы мимо него бесплатен) и вести учёт голову
   относительно исходных n-1 элементов, транслируя вращения в исходной
   задаче в вращения на один шаг длиннее КАЖДЫЙ РАЗ, когда виртуальная
   голова обходит полный круг — это меняет саму схему трансляции слова
   (не «то же слово», а слово с вставленными по расписанию компенсациями),
   и увеличивает длину на число полных обходов `<= N_rot(W)/(n-1)`, что при
   `N_rot(W) ~ floor((n-1)^2/4)` даёт патч `O(n)`, а не `O(n^2)` — стоит
   проверить точно.
2. Индукция не по «добавить один элемент», а по структуре геодезической
   (C13: расщепление `N_X = floor((n-1)^2/4)`, `N_rot = floor(n^2/4)`) —
   искать рекурренту на уровне ЭТИХ двух чисел отдельно, а не на уровне
   слова целиком.
3. Ограничиться индукцией только для отражений (`pi_h`) как более простым
   частным случаем перед общим `pi` — но это уже закрыто напрямую C32 без
   индукции, так что ценность только методическая (проверить, работает ли
   идея (1) там, где ответ уже известен).
