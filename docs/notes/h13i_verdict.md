# H13-I — попытка доказательства, вердикт

Дата: 14.09.2026 (сессия 9). Задача из PLAN §8 / `docs/notes/h13_line_model.md`
§6: доказать H13-I — `I(pi) <= floor((n − 1)^2/4)` при всех n >= 4 и всех
pi из S_n (торические классы), бюджет 1 сессия до письменного вердикта.
Определения — `docs/notes/h13_line_model.md` §0; тот же I(pi), что в C33/C35/C36
и в `experiments/line_model.py`, `experiments/line_profile.c`.

## 0. Итог

H13-I **не доказана и не опровергнута** за сессию. Три испробованных подхода
к прямому доказательству дали отрицательный результат (см. §§2–3); численные
данные расширены и нового контрпримера не нашли (§1). Решение: закрыть сессию
письменным вердиктом (AGENTS.md правило 12), следующий шаг — индукция H3
(PLAN §4.3, п. 3), как и было условлено в `h13_line_model.md` §6.

## 1. Расширенные численные данные

1. **Исчерпывающе расширено с n <= 10 до n <= 11** (`experiments/h13i_toric.c`,
   h13i_toric-1.0): прямой перебор всех n^2 разрезов (q, c) без таблицы
   расстояний (H13-I — чисто комбинаторное утверждение об I(pi), таблица
   d(pi) не нужна) для всех n! перестановок. Метод: для каждого q — круговой
   разностный массив по C(n,2) парам (каждая пара даёт непрерывную дугу
   значений сдвига s, на которых пара инвертирована; длина дуги n − d,
   d = (a_j − a_k) mod n), затем одна частичная сумма — O(n^2) на q, O(n^3)
   на перестановку. Сверено с полным перебором (q, c) на случайных
   перестановках 3 <= n <= 8 (пофайлово совпадает). Результат:
   `max_I = floor((n-1)^2/4)` точно при 4 <= n <= 11 (n = 11: 25 = floor(100/4),
   достигается на отражении; 39 916 800 перестановок, 2 мин 15 с на одном ядре).
2. **n = 12 — исчерпывающе, завершено**: 4 процесса,
   `gcc -O2 -o h13i_toric experiments/h13i_toric.c && for r in 0 1 2 3; do ./h13i_toric 12 4 $r; done`
   (шардирование по остатку ранга перестановки mod 4). Все
   4 x 119 750 400 = 479 001 600 = 12! перестановок проверены (сумма
   `checked` по шардам сверена с 12!); `max_I = 30 = floor(11^2/4)` точно,
   контрпримера нет. Заняло ~9 мин на 4 ядрах, как и оценивалось по
   масштабированию n = 10 → 11 (x14). Логи
   `data/runs/h13i_search/toric_n12_shard{0,1,2,3}.log`. Диапазон C37 —
   4 <= n <= 12.
3. **SAMPLED n = 11..200** (`experiments/h13i_sample.py`, h13i_sample-1.0):
   отражения (4 значения h), sigma_n = отражение h = 0, аффинные `a*i+b`
   (несколько a, b), половинный блок-реверс, 8 случайных перестановок на
   каждое n; метод I(pi) тот же O(n^3), сверен с полным (q, c)-перебором.
   Ни одного превышения `floor((n-1)^2/4)` при n в
   {11, 12, 15, 20, 25, 30, 40, 50, 60, 80, 100, 150, 200}: на всех отражениях
   (включая sigma_n) — точное равенство target; на прочих входах — строго
   меньше, с растущим запасом (например n = 200: target 9900, случайные
   входы 6400–7000). Отчёт `data/runs/h13i_search/sample_report.md`.
   Это SAMPLED-данные, не сертификат: подтверждают гипотезу и то, что
   отражения остаются единственной известной экстремальной семьёй, но не
   доказывают общий случай.

## 2. Испробованные подходы к доказательству (все отклонены)

### 2.1. Усреднение по всем n^2 разрезам (переоткрыто и подтверждено отклонённым)

Точная формула (вывод см. ниже) показывает, почему усреднение не работает:
фиксируем q, тогда для пары позиций линии j < k со значениями a_j, a_k число
сдвигов s из n, дающих инверсию, равно n − d, d = (a_j − a_k) mod n
(та же дуга, что в §1.1). Суммируя по всем парам и по всем q, среднее
`inv` по всем n^2 разрезам равно `C(n,2) − (1/n) * sum_{q,pairs} d_{jk}(q)`.
Эта сумма зависит от pi нетривиально (не сводится к геометрии позиций одной),
и её точное значение на отражениях даёт среднее `inv`, СТРОГО БОЛЬШЕЕ
`floor((n−1)^2/4)` (численно: n = 10 — среднее ≈ 28.5 против target 20).
Значит `min <= среднее` не даёт нужной оценки: подтверждает вывод сессии 8
(`h13_line_model.md` §6, «усреднение по всем n^2 разрезам не работает»),
теперь с явной причиной (среднее само превышает target на экстремальном
входе, а не только «неточно»).

### 2.2. Диагональные разрезы (происхождение точки, «cut at each point»)

Кандидат: ограничиться n разрезами вместо n^2 — взять началом каждую из n
точек самой pi (q = i − 1, c = i − pi(i), так что pi(i) переходит в
(0, 0)); искать минимум только по этим n кандидатам.

Отклонён: наименьший контрпример — n = 4, pi = (0, 3, 2, 1)
(diagonal даёт 3 > target 2, истинное I = 2). При n = 8 наблюдаемый худший
случай — 21 против target 12 (`experiments/h13i_candidates.py`,
столбец `worst_diagonal`; таблица в §3). Точка происхождения «в точке
перестановки» систематически плоха на входах, где pi(i) = i почти
неподвижна (сама точка не создаёт инверсии, но её выбор не балансирует
остальные n − 1 точек) — это переформулировка отклонённой в сессии 8
«индукции по одному элементу» (`h13_line_model.md` §1.7) в форме готового
кандидата на разрез, а не редукции задачи.

### 2.3. Разрез с фиксированным «модальным» сдвигом c

Кандидат: вычислить b* = мода (по частоте) значения `(pi(i) − i) mod n`
(наиболее частый «сдвиг», который сделал бы pi чистым поворотом), взять
`c = (−b*) mod n` (знак подобран так, чтобы для настоящего поворота
`pi(i) = i + b` результат был I = 0 — проверено явно, см. `rotation_sanity`
в `experiments/h13i_candidates.py`) и искать минимум только по q (n
кандидатов вместо n^2).

Отклонён: при нечётных n = 3, 5, 7 кандидат совпал с истинным максимумом
(`worst_mode_shift == target`) — совпадение, не общее доказательство.
Начиная с n = 4 для чётных n (4, 6, 8) кандидат превышает target
(таблица в §3); наименьший контрпример — снова n = 4, pi = (0, 3, 2, 1)
(mode_shift даёт 3 > 2). Мода — глобальная одномерная статистика, она не
учитывает совместное распределение позиций и значений (тот же пробел, что
и в лемме C `h13_line_model.md` §4: локальных/одномерных условий
недостаточно, нужен совместный сдвиг обоих разрезов).

### 2.3.1. Таблица (`experiments/h13i_candidates.py`, исчерпывающе 3 <= n <= 8)

| n | target | worst_full (=I) | worst_diagonal | worst_mode_shift |
|---|---|---|---|---|
| 3 | 1 | 1 | 1 | 1 |
| 4 | 2 | 2 | 3 | 3 |
| 5 | 4 | 4 | 6 | 4 |
| 6 | 6 | 6 | 10 | 7 |
| 7 | 9 | 9 | 15 | 9 |

`worst_full` подтверждает C33/H13-I на этом диапазоне (совпадает с

target уже при малых n — не близкие приближения, которые можно было бы
подправить константой, а качественно другой (более быстрый) рост.

## 3. Почему это трудно (наблюдение, не лемма)

И §2.1, и §§2.2–2.3 упираются в одно и то же: I(pi) — минимум по n^2
существенно связанным разрезам величины, для которой ни «среднее»,
ни «одна хорошая координата» (диагональ или мода) не служат сертификатом.
Из C32 известно точное решение на отражениях (два зигзага дуг, баланс длин
дуг вокруг оси), но это явная конструкция слова, а не выбор разреза как
функции от pi в замкнутой форме, обобщаемой на произвольную pi. Кандидат,
который стоит проверить в другой сессии (не отклонён, не испробован):
совместный сдвиг обоих координат сразу — искать (q, c) не независимо и не
по одной статистике, а по паре статистик, связывающих позиции и значения
одновременно (например: q и c такие, что оба разреза делят как позиции,
так и значения на почти равные по «массе» дуги в смысле леммы C
`h13_line_model.md` §4, но с совместным, не покоординатным, критерием
баланса). Это направление не бюджетировано в этой сессии.
