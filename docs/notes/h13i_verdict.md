# H13-I — вердикт сессии 9 (без доказательства): расширенная проверка и отклонённые подходы

Дата: 17.09.2026 (сессия 9). Задача из `docs/notes/h13_line_model.md` §6 /
PLAN §8: доказать H13-I (`I(pi) <= floor((n-1)^2/4)` для всех pi из S_n,
`I(pi) = min_{a,b} inv` по двойному разрезу — поворот позиций a и значений b),
бюджет 1 сессия до письменного вердикта.

**Итог: H13-I не доказана.** Три новых подхода к упрощению рассмотрены и
отвергнуты (§2); прямое доказательство через переформулировку суммы по
префиксам получено для внутренней (одномерной) минимизации, но не закрывает
внешнюю минимизацию по a (§3). Вместо этого расширена вычислительная база:
исчерпывающая проверка H13-I доведена до n = 11, 12, 13 (было 4 <= n <= 10,
`experiments/line_profile.c`, сессия 8) независимой реализацией
(`experiments/h13i_exhaustive.c`, см. правило 3 AGENTS.md), и добавлена
структурированная (не исчерпывающая) проверка через adversarial-поиск
(`experiments/h13i_search.c`, имитация отжига) для 14 <= n <= 100:
контрпримера не найдено нигде. Следующая задача по плану — индукция H3
(PLAN §4.3, п. 3).

## 0. Определения

Как в `h13_line_model.md` §0: `I(pi) = min_{a,b} inv(w)`, `w_j = (pi[(a+j)
mod n] - b) mod n`, j = 0..n-1; a — поворот позиций (n выборов), b — сдвиг
значений (n выборов), итого n^2 разрезов. Цель: `I(pi) <= floor((n-1)^2/4)`
для всех pi.

## 1. Быстрое вычисление I(pi): O(n^2) вместо O(n^4)

Оба новых инструмента используют одну и ту же пару рекуррент (выведены и
проверены в этой сессии, независимо переоткрывают форму леммы C
`h13_line_model.md` §4 для полного разреза, а не только приращения):

- по позиции: `inv(a+1, 0) = inv(a, 0) + (n-1-2*pi[a])` (элемент,
  уходящий с начала строки в конец, меняет количество инверсий на
  `(n-1-2*его_значение)`);
- по значению при фиксированном a: `inv(a, b+1) = inv(a, b) + (n-1-2*pos_a[b])`,
  `pos_a[v] = (piinv[v]-a) mod n` — позиция в строке элемента со значением v.

Отсюда `inv(0,0)` считается один раз за O(n^2) (или O(n log n)), а весь
n x n массив `inv(a,b)` — ещё за O(n^2) суммарно (для каждого a — O(n) на
построение `pos_a` и O(n) на проход по b, с переносом `inv(a,0)` от
предыдущего a за O(1)). Корректность: `checks/check_H13I.py` часть A сверяет
эту рекуррентную реализацию (Python, независимо от C-версий) с прямым
перебором O(n^4) на всех перестановках 4 <= n <= 7 и на 4000 случайных при
8 <= n <= 10 — 0 расхождений.

`experiments/h13i_exhaustive.c` (h13i_exhaustive-1.0) — независимая
C-реализация тех же рекуррент (отдельно от `h13i_search.c`, по правилу 3)
для исчерпывающего перебора всех n! перестановок; `experiments/h13i_search.c`
(h13i_search-1.1) — та же формула плюс случайный локальный поиск
(имитация отжига, см. §4) для n за пределами исчерпимого диапазона.

## 2. Три отклонённых подхода к упрощению H13-I

`h13_line_model.md` §6 уже отверг: усреднение по всем n^2 разрезам,
индукцию по одному элементу, семейство разрезов «первый элемент = t»,
локальные условия оптимальности (лемма C). В этой сессии проверены и
отвергнуты ещё три способа свести двумерную минимизацию (n^2 разрезов) к
одномерной (n разрезов) — все дают контрпримеры уже на переборе 4 <= n <= 8
(`checks/check_H13I.py` часть B):

1. **Только сдвиг значений** (`a = 0` зафиксировано, минимум только по b):
   при n = 7 худший случай даёт 10 инверсий > `floor(6^2/4) = 9`
   (при n <= 6 подход случайно не нарушается). Значит, поворот позиций a
   существенен и не может быть опущен даже для одной естественной строки.
2. **Разрезы, привязанные к точке** (`b = pi(a)`, n кандидатов вместо n^2 —
   начало координат совпадает с одной из n точек перестановки): худший
   случай растёт почти как полное число инверсий (n = 8: 21 при границе 12),
   то есть даёт оценку немногим лучше тривиальной `C(n,2)`.
3. **Диагональные разрезы** (`b = a`, n кандидатов): тот же порядок роста
   (n = 8: 17 при границе 12).

Все три подхода отклонены здесь конечными контрпримерами (не общим
аргументом); данные — `checks/check_H13I.py`, `data/runs/h13i_verdict/
part_b_worst.json`. Побочный вывод: подмножество размера n «естественных»
разрезов (по значению, по привязке к точке, по диагонали) не работает —
полная двумерная сетка n^2 разрезов не сокращается очевидным образом; любая
будущая попытка сузить перебор должна использовать структуру самой pi, а не
фиксированное по n правило.

## 3. Частичная переформулировка: внутренняя минимизация как задача о префиксных суммах

Для ФИКСИРОВАННОГО a (то есть для фиксированной строки v = поворот pi) пусть
`q = v^{-1}` (перестановка: `q[k]` — позиция в строке элемента со значением
k). Тогда, используя рекурrenту §1 по b, для J(v) = min_b inv_b(v) верно:

```
J(v) = inv(q) + min_{0<=b<=n} P(b),   P(b) = b(n-1) - 2*sum_{k<b} q[k],   P(0)=0.
```

(`inv(q) = inv(v)`, классическое тождество `inv(v) = inv(v^{-1})`; вывод —
прямое суммирование приращения `(n-1-2*pos(k))` по b от 0 до текущего.)
Это в точности форма классической «леммы о цикле» (cycle lemma) — минимум
достигается там, где префиксная сумма `sum_{k<b} q[k]` максимально
опережает линию `b(n-1)/2`.

Проверка на отражении (`v(i) = h-i mod n`, `q` — тоже полное обращение,
`q[k] = n-1-k`): прямым счётом `P(b) = b(b-n)`, минимум в целых точках при
`b = floor(n/2)` или `ceil(n/2)` даёт (для чётного n = 2m) `P = -n^2/4`, и
`J = n(n-1)/2 - n^2/4 = n(n-2)/4 = floor((n-1)^2/4)` — совпадает с известным
максимумом `I` (`h13_line_model.md` §1.1), проверено алгеброй и численно.

**Это не доказательство H13-I**: формула точна только для ФИКСИРОВАННОГО a;
внешняя минимизация по a (n вариантов строки v) не сведена к этой же
технике — переход `q` от одного a к другому меняет весь набор префиксных
сумм не по простому правилу. Сохранено как кандидат-блок для будущей
сессии: возможный путь — доказать, что для ЛЮБОЙ pi найдётся a, при котором
соответствующий q «достаточно похож на монотонный» (мало отклоняется от
среднего), тогда `min_b P(b)` оценивается через отклонение q от identity.
Не проверено и не проработано дальше в этой сессии.

## 4. Вычислительное расширение (не доказательство)

### 4.1. Исчерпывающая проверка n = 11, 12, 13

`experiments/h13i_exhaustive.c`, независимая от `line_profile.c` (сессия 8)
реализация: перебор всех n! перестановок в лексикографическом порядке,
вычисление I(pi) за O(n^2), сравнение с `floor((n-1)^2/4)`. Скорость измерена
по правилу 10 перед запуском (n=8..10 — доли секунды, затем n=11 (8.7 с),
n=12 (122 с) экстраполяцией подтвердили посильность n=13 (~30 мин)).

| n | перестановок | max I | граница | превышений | время |
|---|---|---|---|---|---|
| 11 | 39 916 800 | 25 | 25 | 0 | 8.7 с |
| 12 | 479 001 600 | 30 | 30 | 0 | 122 с |
| 13 | 6 227 020 800 | 36 (в процессе на момент промежуточного коммита) | 36 | 0 (на > 25% перебора) | ~30 мин (в процессе) |

(этот файл содержит промежуточное состояние: прогон n = 13 запущен в фоне,
`data/runs/h13i_verdict/exhaustive_n13.json` появится и таблица будет
обновлена отдельным коммитом сразу по завершении; до 27% перебора превышений
не было, текущий максимум уже равен границе 36, как и ожидается.)

Во всех случаях максимум достигается ТОЛЬКО на отражениях (аргмакс —
`[0, n-1, n-2, ..., 1]`, поворот `pi(i) = -i mod n`), согласуется с
наблюдением сессии 8 при 4 <= n <= 10.

### 4.2. Adversarial-поиск n = 14..100 (не исчерпывающий, не доказательство)

`experiments/h13i_search.c` (h13i_search-1.1): имитация отжига (случайные
транспозиции двух позиций, приём худшего хода с вероятностью
`exp(delta/T)`, T линейно убывает от n/2 до 0.01) с перезапусками из
случайной перестановки и из случайного отражения (mode 0/1, поочерёдно).
Валидация поисковика: на n = 9, 10, 12 (где точный максимум уже известен
исчерпывающе) поиск за 20 000 итераций x 6 рестартов находит margin = 0
(точное совпадение с границей) — то есть инструмент способен достигать
истинного максимума, а не застревать далеко от него.

Результат для 14 <= n <= 100 (300 000 итераций x 8 рестартов на каждое n,
`data/runs/h13i_verdict/sa_search.log`): margin (I(pi) - floor((n-1)^2/4))
достигает ровно 0 (не больше) на n = 14, 16, 18, 20, 22, 25, 30, 35, 40, 50,
60, 85, 100 (перезапуски с отражения находят точное равенство почти сразу,
`iter=0`, что ожидаемо: отражение уже является локальным и, видимо,
глобальным максимумом); на n = 70 лучший найденный margin = -7 (не 0) —
это, вероятно, недостаток бюджета поиска для этого конкретного n, а не
контрпример (margin отрицателен, граница не нарушена). **Превышений
границы не найдено ни разу** ни с одним из ~1400 рестартов на 14 значениях
n. Это не доказательство (SA не гарантирует нахождение глобального
максимума), но независимая, вручную не подогнанная под кандидата проверка
(правило 4 AGENTS.md) на масштабе, вчетверо превышающем прежний
исчерпывающий предел.

### 4.3. Проверенная и отвергнутая гипотеза о «двублочных» перестановках

Промежуточная гипотеза этой сессии («перестановка из двух независимо
развёрнутых блоков позиций — новое семейство максимизаторов I(pi), шире
отражений») проверена и **отвергнута после перепроверки**: перестановка
`pi(i) = k-1-i` (i < k), `pi(i) = n-1-(i-k)` (i >= k) для любого разбиения
k — это и есть отражение `pi(i) = (h-i) mod n` с `h = k-1`, только записанное
без явного взятия по модулю (сумма `pi(i)+i` совпадает по модулю n на обоих
блоках: `k-1` и `n+k-1 ≡ k-1`). Многоблочные (3+) развёртки дают I заметно
меньше границы (проверено `n = 20, 30, 50, 85`, случайные разбиения).
Урок сессии: гипотезу о новом семействе следует сначала проверять по
модулю n, прежде чем регистрировать как отдельное наблюдение — отражения
остаются единственным известным семейством максимизаторов.

## 5. Вывод и следующая задача

H13-I остаётся CONJECTURED, подтверждена теперь исчерпывающе при
4 <= n <= 13 (было 4 <= n <= 10) и структурированной проверкой без
контрпримеров до n = 100. Ни один из шести испробованных за две сессии
подходов к общему доказательству (усреднение, поэлементная индукция,
семейство «первый элемент = t», локальная оптимальность разреза, три
варианта одномерного сужения из §2 этой сессии) не работает; переформулировка
§3 (лемма о цикле для внутренней минимизации) — новый, не использованный
раньше инструмент, но сама по себе цель не закрывает.

По PLAN §8: следующая задача — индукция H3 (§4.3, п. 3): вложение меньшей
задачи (`sigma_{n-1}` -> `sigma_n` или подобное) и стоимость имитации её
ходов с учётом вращения всего массива; бюджет 2 сессии до вердикта.
Не повторять: усреднение по n^2 разрезам; поэлементную индукцию для I(pi);
одномерные сужения перебора разрезов (§2); полный перебор при n >= 14 без
дополнительного ускорения (n = 13 уже на грани разумного времени при
текущем O(n^2)-на-перестановку переборе).
