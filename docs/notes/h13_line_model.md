Дата: 13.09.2026 (сессия 8). Ядро oracle-1.0, таблицы C2v (4 <= n <= 10).
Код: `experiments/line_profile.c`, `experiments/line_rotation_budget.py`,

`checks/check_C34.py`. Отчёты: `data/runs/line_profile/`,

## 0. Определения

Двойной разрез `(q, c)`: ребро позиций {q, q+1} и сдвиг c. Линия
`w_j = pi(q+1+j) − (q+1−c) mod n`, j = 0..n−1; цель — тождественная линия;
голова стартует в индексе `j0 = (−q−1) mod n`, заканчивает в `j1 = (c−q−1)
mod n`. Слово *линейное*, если голова не переходит и не обменивает через
разрез; *сокращённое*, если каждый обмен снимает инверсию (`N_X = inv(w)`).

- `I(pi) = min_{q,c} inv(w)` — по всем n^2 разрезам (эквивалентно: минимум
  инверсий по торическому классу pi — повороты позиций и значений).
- `d_line(pi)`, `d_walk(pi)`, `d_red(pi)`, `Rbest(pi)`, `Rfree(w)` — см.
  отчёты `line_model`, `line_rotation_budget`. Всегда
  `d <= d_walk <= d_line <= d_red`.

## 1. Что показали данные (исчерпывающе)

1. `I(pi) <= floor((n−1)^2/4)` при 4 <= n <= 10 (равенство — ровно n отражений).
2. `d(pi) <= I(pi) + floor(n^2/4)` при 4 <= n <= 10; более того,
   `d_red(pi) <= I(pi) + floor(n^2/4)` при 4 <= n <= 9: для каждой pi есть
   разрез с `inv = I(pi)` и сокращённое линейное слово с
   `N_rot <= floor(n^2/4)`. Максимум `Rbest = floor(n^2/4)` достигается на
   2, 4, 11, 11, 50, 111 входах (n = 4..9) — не только на отражениях.
3. Профиль `max_{I(pi) = I} d(pi)` (профиль `line_profile`): при I >= max − 1
   равен `I + floor(n^2/4)`, при n <~ I <= max − 2 — `I + floor(n^2/4) − 1`,
   при малых I — около `2I + n`. Бюджет вращений `floor(n^2/4)` требуется
   уже при I ≈ n.
4. `max_pi (d − 2I)` = 3, 3, 5, 6, 8, 10, 13 при n = 4..10: растёт не медленнее
   n − 1 (лемма B) и быстрее n (обмен блоков у антипода).
5. `max_w Rfree(w) = B_n − 1` при 4 <= n <= 9 — без выбора разреза бюджет
   вращений равен `B_n − 1` (лемма A, точно).
6. `d_walk = d` при n <= 7; при n = 8, 9 есть входы с `d_walk − d` до 4, 5
   (аффинные), но при `I >= max − 1` всегда `d_line = d`.
7. Индукция по одному элементу для п. 1 не проходит: при n = 8 аффинный вход
   `(0,5,2,7,4,1,6,3)` имеет I = 11, а все восемь его редукций (удаление
   элемента с контракцией позиций и значений) — I = 6, тогда как
   `floor((n−1)^2/4) − floor((n−2)^2/4) = floor((n−1)/2) = 3`. Семейство
   разрезов «первый элемент линии имеет значение t» (n разрезов вместо n^2)
   тоже недостаточно ни при каком t (n = 5: `(0,2,4,1,3)`; n = 7:
   `(0,2,4,6,1,3,5)`).

## 2. Лемма A (универсальный маршрут линии; PROVED)

Для любой линии w из n позиций существует сокращённое линейное слово с
`N_X = inv(w)` и `N_rot = B_n − 1` (конец головы свободен; старт — ребро 0).
Оценка точна: полностью обращённая линия имеет `inv = B_n`, а в кратчайшем
слове `N_rot >= N_X − 1`.

Маршрут (`constructions/line_cocktail.py`): проход 1 по рёбрам 0, 1, ..., n−2;
проход 2 по n−3, ..., 0; проход 3 по 1, ..., n−4; проход 4 по n−5, ..., 1; …
(k-й проход содержит n − k рёбер, направления чередуются, каждый проход
начинается рядом с концом предыдущего). На каждом ребре обмен делается
тогда и только тогда, когда пара инвертирована. Всего `1 + 2 + … + (n−1) =
B_n` сравнений, длина пути `B_n − 1`.

Корректность: проход 1 переносит максимум на позицию n−1; проход 2 —
минимум позиций 0..n−2 на позицию 0; проход 3 — максимум позиций 1..n−2 на
n−2; и т. д. (шейкер-сортировка с сужающимися границами). После k проходов
`ceil(k/2)` наибольших и `floor(k/2)` наименьших элементов стоят на своих
местах, после n − 1 проходов — все. Каждый обмен снимает ровно одну инверсию,
поэтому обменов ровно `inv(w)`. ∎ Проверено эталонными ходами на всех линиях
при 4 <= n <= 8 (`checks/check_C34.py`, часть A).

Следствие. Для любой pi и любого разреза `d(pi) <= inv(w) + B_n − 1 + подход +
финал`. Это бесполезно для C15: вся экономия до `floor(n^2/4)` — в выборе
разреза (п. 1.5), а не в маршруте по данной линии.

## 3. Лемма B (антиподальная транспозиция; PROVED при чётных n >= 6, таблицы 4..10)

Пусть n = 2m чётно и `tau_n` — тождественная перестановка с обменянными
позициями m, m+1. Тогда `I(tau_n) = 1` и `d(tau_n) = n + 1`.

`I = 1`: разрез q = n−1, c = 0 даёт линию с одной инверсией; `I = 0` только у
поворотов тождественной. Верхняя оценка — слово `L^m X R^m` длины n + 1.

Нижняя оценка. Пусть слово сортирует tau_n и голова заканчивает в c; тогда
элемент e должен оказаться на позиции e + c. Для элемента e обозначим `t_e`
его суммарное знаковое смещение по обменам (каждый X даёт +1 одному и −1
другому участнику); `sum_e t_e = 0`, `N_X >= (1/2) sum_e |t_e|`, и
`t_e ≡ c (mod n)` при e ∉ {m, m+1}, `t_m ≡ c − 1`, `t_{m+1} ≡ c + 1`.

Случай c = 0. Если есть обмен на ребре m (антипод старта), голова проходит
0 → m → 0: `N_rot >= 2m = n`, `N_X >= 1`, итого >= n + 1. Если обменов на ребре
m нет, все обмены — соседние транспозиции пути `m+1, m+2, …, n−1, 0, …, m`
(окружность без ребра m), и их произведение как перестановка позиций равно
транспозиции концов этого пути, длина которой в порождающих пути равна
`2n − 3 >= n + 1`.

Случай c ≠ 0. Автоморфизм `p -> sigma_n o p o sigma_n` (PROBLEM §4.3) меняет
L и R местами, сохраняет tau_n (проверка: 1 − tau(1 − i) = i при i ∉ {m, m+1}
и меняет m, m+1 местами) и переводит c в −c; поэтому достаточно 1 <= c <= m.
Запишем `t_e = r_e + n·k_e`, `r_e` — остаток в [0, n): `sum r_e = (n−2)c +
(c−1) + (c+1) = nc`, значит `sum k_e = −c`. Стоимость `|t_e|` при k = 0 равна
r, при k = −1 — n − r, каждый следующий шаг |k| добавляет n; k > 0 стоит
n + r и требует лишнего уменьшения у другого элемента. Минимум `sum |t_e|`
достигается, когда ровно c элементов имеют k = −1 — те, у кого остатки
наибольшие: один с остатком c + 1 и c − 1 с остатком c:
`sum |t_e| >= nc + (n − 2c − 2) + (c − 1)(n − 2c) = 2cn − 2c^2 − 2`,
`N_X >= cn − c^2 − 1`. При 1 <= c <= m правая часть вогнута по c, на концах
`n − 2` (c = 1) и `m^2 − 1 >= n − 2` (c = m), так что `N_X >= n − 2`. В
кратчайшем слове нет XX, поэтому `N_rot >= N_X − 1` и длина `>= 2n − 5 >= n + 1`
при n >= 6. ∎ При n = 4 равенство `d = 5` — по таблице; `d = n + 1` при
n = 4, 6, 8, 10 сверено с таблицами (`check_C34.py`, часть B).

Следствие. Всякая оценка вида `d(pi) <= 2·I(pi) + g(n)`, верная при всех pi,
требует `g(n) >= n − 1` (чётные n). Критерий PLAN §8 (`g(n) <= floor(n/2) +
O(1)`) недостижим. Обмен блоков длины k у антипода даёт ещё больше:
`d − 2I` = 8 (n = 8, k = 2), 13 (n = 10, k = 3).

## 4. Лемма C (локальная оптимальность разреза)

Если (q, c) минимизирует inv, то линия w удовлетворяет
`sum_{j<k} w_j <= k(n−1)/2` для всех k (и симметрично для суффиксов), и то же
для обратной перестановки (`sum_{x<k} pos(x) <= k(n−1)/2`): сдвиг разреза
позиций на k переносит первые k элементов в конец, меняя inv на
`sum_{j<k} (n − 1 − 2 w_j)`; сдвиг разреза значений на k делает элементы
0..k−1 наибольшими, меняя inv на `sum_{x<k} (n − 1 − 2 pos(x))`. ∎

Этих условий недостаточно для `inv <= floor((n−1)^2/4)`: линия
`(0,5,4,3,2,1,6)` при n = 7 удовлетворяет всем им (суммы 0, 5, 9, 12, 14, 15
при порогах 0, 6, 9, 12, 15, 18; обратная — те же), но `inv = 10 > 9`; её
торический класс имеет I = 8 при несоседнем разрезе. Доказательство п. 1.1
должно использовать совместные сдвиги обоих разрезов.

## 5. Вердикт по H13

1. Исходная форма H13 («один неиспользуемый разрез достаточен для диаметра»)
   подтверждена конечно и уточнена: на слоях `B_n`, `B_n − 1` `d_line = d`
   при 4 <= n <= 9, но в общем случае обмены через все рёбра бывают нужны
   (n = 8, 9).
2. Критерий PLAN §8 — оценка `d <= 2I + g(n)` с `g(n) <= floor(n/2) + O(1)` —
   ложен (лемма B). Правильная форма — с наклоном 1:
   **H13′: `d(pi) <= I(pi) + floor(n^2/4)`**, распадающаяся на
   **H13-I: `I(pi) <= floor((n−1)^2/4)`** (чистая комбинаторика торических
   классов) и **H13-R: существует разрез с `inv = I(pi)` и сокращённое линейное
   слово с `N_rot <= floor(n^2/4)`** (бюджет вращений, не зависящий от I).
   `H13-I + H13-R => C15` по C12. Обе части VERIFIED (4 <= n <= 10 и 4 <= n <= 9),
   обе тесны.
3. «Доказуемая схема слова для линии с inv инверсиями и `N_rot <= inv + f`»
   (PLAN §8 п. (2)) не существует в нужной силе: бюджет вращений не убывает с
   inv (Rbest = floor(n^2/4) при I ≈ n), а без выбора разреза он равен
   `B_n − 1` (лемма A). Схема должна выбирать разрез; экстремальные маршруты
   разного вида (зигзаги на отражениях, холостые переходы на блочных входах).
4. Пункт (3) PLAN §8 (входы с `I > max − n/4`) не сводит задачу к конечному
   числу семейств: их 660 при n = 10 и они растут с n.

## 6. Следующий шаг

Доказать H13-I отдельно (бюджет 1 сессия): утверждение о торических классах —
у каждой pi есть поворот позиций и значений с не более `floor((n−1)^2/4)`
инверсиями. Эквивалентная форма: у каждой pi есть двойной разрез с не менее
`floor(n^2/4)` неинверсий; в терминах точек `(i, pi(i))` на торе — точка
`(q, s)` тора, лежащая в «одноимённых» квадрантах не менее `floor(n^2/4)` пар.
Известно: усреднение по всем n^2 разрезам не работает (среднее для sigma_n
равно `(n^2 − 1)/6 < n^2/4` в форме максимума и `~n^2/3` для id в форме
минимума), индукция по одному элементу не работает (п. 1.7), локальные
условия недостаточны (лемма C). Кандидаты: сдвиги обоих разрезов вместе;
экстремальность отражений через леммы C32 (баланс дуг); литература о
торических классах перестановок. Если H13-I доказана — H13-R остаётся
эквивалентом C15 при известном N_X и переходит в задачу о маршрутах; если
нет за сессию — переход к индукции H3 (PLAN §4.3).

### 7.1 Точные тождества для сетки inv(s, t) (лемма D, PROVED)

Перепараметризуем двойной разрез: `s = q + 1` (сдвиг позиций), `t = shift =
q + 1 − c` (сдвиг значений); `s, t` пробегают `Z_n` независимо, те же n^2
разрезов. `inv(s, t)` — число инверсий линии в этой параметризации. Тогда
точно (не эвристика, не условие локального оптимума — тождество при любых
s, t, любой pi):

```
inv(s+1, t) = inv(s, t) + (n-1) - 2*((pi[s]    - t) mod n)      (s-рекуррентность)
inv(s, t+1) = inv(s, t) + (n-1) - 2*((piinv[t] - s) mod n)      (t-рекуррентность)
```

Вывод: `inv(s+1,t)` получается из `inv(s,t)` переносом переднего элемента
линии (значение `v = (pi[s]-t) mod n`) в конец — стандартное тождество
пузырьковой сортировки: элемент терял `v` инверсий (был больше всех `v`
меньших элементов перед ним — их нет, он на фронте) и приобретает `n-1-v`
новых (со всеми элементами, кроме себя, теперь стоящими перед ним), так что
разница `inv(s+1,t)-inv(s,t) = (n-1-v) - v = n-1-2v`. `t`-рекуррентность —
то же тождество для обратной перестановки `pi^{-1}` (`inv(w) = inv(w^{-1})`
всегда): элемент, «покидающий фронт» при повороте значений на 1, — это
позиция текущего минимума (значения 0), т.е. `piinv[t] - s mod n`.

Проверено брутфорсом на всех перестановках 2 <= n <= 7 (5912 штук, все n^2
клеток сетки; `experiments/toric_I_recurrence_check.py`, отчёт
`data/runs/toric_I_recurrence_check/report.md`) — 0 нарушений.

Следствие (не новое по существу, но теперь как прямое следствие тождества, а
не отдельного геометрического аргумента): применяя s-рекуррентность k раз,
`inv(s+k,t) - inv(s,t) = k(n-1) - 2*sum_{j<k} w_j(s,t)`; если `(s,t)` —
глобальный минимум сетки, это `>= 0` для всех k, что в точности даёт условие
леммы C (`sum_{j<k} w_j <= k(n-1)/2`) на обеих осях по отдельности — лемма C
сессии 8 есть однопараметрическое (по одной оси） частное применение этого
тождества. Совместный (по обеим осям сразу, например по диагонали s=t)
аналог тождества выводится композицией, но не даёт простого замкнутого
условия (см. 7.4) — направление «жёсткое совместное условие» осталось
открытым.

Точная формула для суммы по всем n^2 разрезам (тоже PROVED, брутфорс
2 <= n <= 7 — та же проверка): для точек `(i, pi(i))`, пары `{p,q}`,
`a = (x2-x1) mod n`, `b = (y2-y1) mod n`:

```
sum_{s,t} inv(s,t) = sum_{pairs {p,q}} f(a,b),   f(a,b) = n(a+b) - 2ab = n^2/2 - 2(a - n/2)(b - n/2)
```

`f` симметрична относительно `(a,b) -> (n-a,n-b)` (переобозначение пары),
максимальна (~`n^2-2n+2`) на «сильно несогласных» парах (`a` мало, `b`
близко к `n`, или наоборот) и минимальна (`2n-2`) на «согласных» (`a` и `b`
малы одного знака). На отражениях `pi_h(i)=h-i mod n` у КАЖДОЙ пары `b = n-a`
точно (что и объясняет их экстремальность для среднего/максимума по разрезам
— C26/C27-подобное усреднение уже отвергнуто в §1.7 как недостаточное для
самого H13-I, но формула `f` даёт точный, не оценочный, вид этого
усреднения). Использовать `f(a,b)` для прямого доказательства min (а не
среднего) не удалось за сессию — среднее велико именно на «плохих» pi
(id-подобных), а нужен argument именно про минимум по сетке, не про сумму.

### 7.2 Быстрый алгоритм и расширение H13-I до n <= 12 (C33 расширена)

Тождества 7.1 дают алгоритм O(n^2) на перестановку (заполнить строку t=0
рекуррентностью по s, затем каждый столбец — рекуррентностью по t) вместо
O(n^4) у `line_profile.c` (перебор n^2 разрезов x пересчёт инверсий за
O(n^2) каждый). Реализация: `experiments/toric_I_fast.c`
(toric_I_fast-1.0). Проверка корректности реализации (независимо от вывода
формул): (а) совпадение `max I(pi)` с `line_profile.c` на 4 <= n <= 10 —
2, 4, 6, 9, 12, 16, 20, побайтово; (б) отдельный BFS-брутфорс совершенно
другим кодом (`experiments/circle_sort_equivalence.py`, см. 7.3) на n <= 7.

Результат (`data/runs/toric_I_fast/report.md`): **исчерпывающая проверка
`I(pi) <= floor((n-1)^2/4)` расширена с 4 <= n <= 10 (C33) до 4 <= n <= 12**
(совпадает с диапазоном сертифицированных таблиц C2v, хотя таблицы здесь не
нужны). При каждом n = 4..12 максимум равен точно `floor((n-1)^2/4)`,
достигается ровно на n входах (отражения), без исключений; n = 12 —
479 001 600 перестановок за 45.5 с на одном ядре. Оценка стоимости перед
запуском n = 12 и n = 13 сделана по времени n = 9, 10, 11 (rule 10),
экстраполяция подтвердилась с точностью до множителя ~1.2.

n = 13 (6 227 020 800 перестановок) запущен отдельно в фоне и завершился за
687 с (~11.5 мин, почти точно по модели): `max I = 36 = floor(12^2/4)`,
ровно 13 отражений-экстремумов, без исключений (`data/runs/toric_I_fast/`).
**H13-I исчерпывающе подтверждена при 4 <= n <= 13.** n = 14 не запускался:
экстраполяция даёт `~3.1` часа (множитель между соседними n растёт линейно,
время — как `n!`, не полиномиально), а качественная картина не менялась ни
разу от n = 4 до 13 — решено не тратить бюджет на ещё одну точку без нового
вопроса, который она решает (rule 10).

### 7.3 Переформулировка как «сортировка на окружности» и находка в литературе

Наблюдение: `I(pi)` совпадает (проверено BFS-брутфорсом, точно, на всех
перестановках 3 <= n <= 7 — `experiments/circle_sort_equivalence.py`, 0
расхождений) с расстоянием в графе Кэли на `S_n`, порождённом n
«соседними по кругу» транспозициями `s_i = (i, i+1 mod n)` (i = 0..n-1,
каждая применима в любой момент без отдельной стоимости движения — в
отличие от модели L/R/X этого проекта, где X применим только в текущей
активной позиции, а её смена стоит вращения), от pi до ближайшего из n
циклических поворотов тождественной перестановки.

Одно направление — **лемма E, PROVED, все n**: `noas(pi) <= I(pi)`, где
`noas(pi)` — это расстояние выше. Доказательство: для разреза `(q,c)`,
достигающего `I(pi)`, сортировка линии пузырьком вдоль разреза (никогда не
трогая ребро разреза) — корректная последовательность из `inv(w) = I(pi)`
соседних-по-кругу транспозиций, приводящая pi к c-му повороту тождественной;
значит `noas(pi) <= inv(w) = I(pi)`.

Обратное направление (`noas(pi) >= I(pi)`, т.е. использование ребра разреза
никогда не выгодно) **не доказано в этой сессии** — только проверено
брутфорсом, точно, при n <= 7 (см. выше). Прямая попытка (показать, что
`Phi(w) = min_q inv_q(w)` меняется не более чем на 1 при любом соседнем
обмене) не проходит: обмен ИМЕННО на текущем оптимальном ребре `q*` не
ограничен по величине этим аргументом (соседние `q != q*` меняются на ±1
каждый, но `Phi` после хода — минимум по НОВЫМ значениям всех `q`, включая,
возможно, гораздо больший второй по величине `inv_q`). Это и есть, по всей
видимости, содержательная часть нижней оценки — не тривиальна.

Эта переформулировка (n меток на окружности, сортировка соседними
обменами, цель — любой поворот тождественной) — это ровно задача **circular
sorting**. Поиск (WebSearch, доступ к полным текстам arXiv заблокирован
политикой egress-прокси этой сессии — `curl` до `arxiv.org` даёт `403` на
уровне прокси, не инструмента; см. `curl -sS
"$HTTPS_PROXY/__agentproxy/status"`) нашёл:

> Ron M. Adin, Noga Alon, Yuval Roichman, **"Circular sorting"**,
> arXiv:2502.14398 (v1 и более новая версия; по сопутствующим слайдам
> gilkalai.wordpress.com, июль 2026, работа активна). По агрегированным
> результатам поиска (не по первоисточнику — см. ниже про статус): вводится
> `csortadj(n) := max_{pi in S_n} noas(pi)` («число соседних обменов»,
> определённое, по всей видимости, ровно как `noas` выше — точку
> зафиксировать по первоисточнику не удалось) и доказывается **`csortadj(n)
> = floor((n-1)^2/4)` для всех n >= 1**, с экстремумом на полном развороте
> `[n, n-1, ..., 1]` — той же перестановке (с точностью до поворота), что и
> наши n отражений-экстремумов (7.2, C33).

**Статус: CLAIMED, не проаудировано.** Полный текст источника недоступен в
этой сессии (домен `arxiv.org`, а также зеркала/обзоры `themoonlight.io`,
`pith.science`, `researchgate.net`, `export.arxiv.org`,
`api.semanticscholar.org` — заблокированы политикой egress этой сессии, не
временная неполадка). Формулировка выше собрана из фрагментов результатов
поиска (WebSearch), не из самого текста статьи — точные определения,
условия на n, формулировка доказательства и его строгость не проверены.
Точное совпадение формулы (`floor((n-1)^2/4)`) и экстремальной перестановки
(разворот = наши отражения) с независимо полученными данными сессий 8–9 —
сильный, но не заменяющий аудит сигнал. Если бы `noas(pi) = I(pi)` было
доказано (лемма E, обратное направление) и теорема цитаты подтверждена по
первоисточнику, H13-I была бы PROVED при условии этого источника (по правилу
реестра — статус «PROVED при условии C37-lit», не PROVED).

### 7.4 Что ещё не сработало

Прямая попытка усилить лемму C до совместного (диагонального) условия —
рассмотреть `inv(s+1,t+1) - inv(s,t)` как композицию двух шагов 7.1 — не
дала замкнутой формулы (промежуточный шаг зависит от `w_0` НОВОЙ линии после
первого сдвига, т.е. от структуры pi нелинейно). Формула `f(a,b)` (7.1)
уточняет усреднение по всем n^2 разрезам до точного вида, но усреднение уже
отвергнуто как недостаточное для минимума (§1.7, сессия 8) — точная формула
это не чинит, поскольку сама идея (среднее мало => есть маленький элемент)
верна только когда среднее уже ниже цели, а для id-подобных входов среднее
`~n^2/3` выше `floor((n-1)^2/4)`.

### 7.5 Вердикт

**H13-I: не доказана, не опровергнута.** Итог сессии 9:

1. Новое точное тождество (лемма D) и формула пары (7.1) — PROVED,
   брутфорс-проверены; дают быстрый алгоритм.
2. Исчерпывающая проверка `I(pi) <= floor((n-1)^2/4)` расширена с
   4 <= n <= 10 до **4 <= n <= 13**; экстремум точно на n отражениях при
   каждом n, без исключений (n = 12 совпадает с диапазоном таблиц C2v,
   n = 13 — сверх него, чисто комбинаторно, таблицы расстояний не нужны).
3. Переформулирована как расстояние в графе Кэли «соседних по кругу»
   транспозиций (лемма E: одно направление PROVED, все n; обратное —
   верно, вероятно, но не доказано, проверено брутфорсом n <= 7).
4. Найдена внешняя работа (Adin–Alon–Roichman, «Circular sorting»,
   arXiv:2502.14398) с формулировкой, совпадающей с H13-I по формуле и
   экстремальной перестановке — CLAIMED, аудит невозможен в этой сессии
   (сеть заблокирована), не PROVED.

Решение по бюджету (rule 12): **сессия завершается письменным вердиктом,
без доказательства и без опровержения.** Следующая задача — не индукция H3
(в отличие от плана §6, потому что появилась конкретная, сильная зацепка):
(а) получить доступ к полному тексту arXiv:2502.14398 (в другой сессии/сети)
и провести аудит по правилу 11 — точные определения, точная формулировка,
все переходы доказательства, диапазон n; при удаче — перенести доказательство
(с адаптацией терминологии) в `docs/proofs/C37_toric_I_bound.md`; (б)
параллельно или при недоступности источника — попытаться самостоятельно
доказать обратное направление леммы E (`noas(pi) >= I(pi)`, т.е. что ребро
разреза никогда не выгодно использовать) как отдельный шаг, это открытый
и, по всей видимости, содержательный под-результат независимо от (а). Если
и это не удастся за следующую сессию — тогда индукция H3 (PLAN §4.3) как
ранее запланированный запасной путь.
