# H10 для произвольной pi (шаг 2, PLAN §8) — рабочие заметки сессии 4

Не доказательство: честный отчёт о попытках и о том, где они ломаются, по
просьбе задачи сессии («progress notes, even partial/negative»). Отражения
разобраны отдельно и полностью в `docs/proofs/H10_reflections.md` (PROVED).

## Что уже известно (входные данные сессии)

- Тождество `F_c = sum_i delta_n(i - pi(i), c)` (PROVED, проверено
  4<=n<=7 в `experiments/loss_map.py`): `F_c` — сумма расстояний от `c` до
  мультимножества `D = {i - pi(i) mod n : i}`, т.е. `min_c F_c` — это
  1-медиана (точка Ферма на цикле) множества `D`. `mean_c F_c = P` — всегда,
  тривиально (трансляционная инвариантность `delta_n`).
- H9 (тот же минимум, но с собственным маршрутом `H(c)` вместо `R_c`)
  REFUTED на конкретном 9-цикле (C26, `data/runs/strict_loss_audit/perms_n9.json`):
  на минимизирующем `F_c` сдвиге маршрут `H(c)` может быть длинным даже
  когда `F_c` близко к минимуму. Поэтому шаг 2 не может использовать
  собственный маршрут N1 вообще ни при каком выборе `c` — только `R_c`.
- Экспериментально (карта потерь, `data/runs/strict_loss_audit/`):
  `min_c[2F_c-S_c+R_c] - B_n <= 0` на ВСЕХ перестановках `4<=n<=9` (362 880
  входов при n=9), кроме единственного отражения `n=6,h=2` (`= B_n+1`);
  `<= 0` на всех выборках `n=20,50,100`. То есть худший известный случай для
  H10 в целом — это как раз тот же самый отражённый случай, который теперь
  ПОЛНОСТЬЮ объяснён и доказан алгебраически (§4 `H10_reflections.md`).
  Никакого другого потенциального контрпримера в проверенном диапазоне нет.

## Идея 1: перенести аргумент отражений через «связность носителя»

Ключевой факт N1 §1 (уже PROVED как часть C18): для одного цикла `C`
множество рёбер с положительной нагрузкой связно (единый дуговой интервал).
Отсюда: каждое ребро этого интервала несёт нагрузку `>= 1`, поэтому длина
интервала (число рёбер) `<= F(C)` — то есть **все** вершины цикла `C`,
включая переносчик, лежат в дуге длины не больше `F(C)`.

Это даёт локальную оценку (переносчик цикла `C` не может быть «далеко
раскидан» относительно ОСТАЛЬНЫХ вершин ТОГО ЖЕ цикла), но НЕ даёт глобальной
оценки на взаимное расположение переносчиков РАЗНЫХ циклов: два цикла с
маленькими `F(C)` каждый (скажем, `F(C)=2`, две соседние транспозиции) всё
равно могут иметь переносчики в противоположных концах окружности. Сумма
`sum_C F(C) = F_c` ограничивает суммарный «локальный» разброс, но не мешает
расставить `K_c` компактных кластеров равномерно по всей окружности —
именно этот случай и есть источник худшего сценария для `R_c` (маршрут
вынужден обойти почти весь круг, `R_c ~ H(c)`, окружность «плотно занята»
кластерами). Проверено на n=9 контрпримере H9: там ОДИН цикл длины 9
(f_c для большинства c — единственный длинный цикл), так что вопрос
разброса между РАЗНЫМИ циклами там не встаёт; для этого частного случая
`R_c` уже сильно (на 4-7) меньше `H(c)` (по данным report.md,
`Q_R − B_n = −4` для контрпримера H9), поэтому именно длинные единственные
циклы — не проблема. Проблемный случай остаётся гипотетическим: много
КОРОТКИХ циклов с равномерно раскиданными переносчиками. Ни один найденный
перебором вход (4<=n<=9 все перестановки, 4<=n<=12 семейства, n=20/50/100
выборки) не реализует одновременно (а) `F_c` близко к `min_c F_c`,
(б) много коротких циклов, (в) переносчики равномерно раскиданы, при ВСЕХ
`c` сразу — вывод: либо такая перестановка существует только при большем
`n` (не проверено, см. «Не сделано» ниже), либо есть структурная причина,
почему при `F_c` близком к минимуму циклы не могут одновременно быть
многочисленными и разбросанными — эта причина не найдена.

## Идея 2: контрольный пример — чистые вращения (нулевые циклы)

pi(i) = i+k (вращение). Тогда `D = {-k}` — одноэлементное мультимножество,
`min_c F_c = 0` при `c=-k` (f_c = id, нет нетривиальных циклов вовсе).
При этом `R_c` для ПУСТОГО множества требуемых точек — это просто
`delta_n(0,c)` (прямой путь, без обхода, так как обходить нечего;
`constructions/strict_upper.py: carrier_route` с `required=[]` даёт именно
это по построению — прямая дуга от 0 до c). Значит на вращениях
`min_c[2F_c-S_c+R_c] = delta_n(0,-k) = d(pi)` ТОЧНО: карьерный маршрут даёт
оптимум без всякого зазора. Это подтверждает, что именно `R_c` (а не `H(c)`,
который был бы `~n`, катастрофически хуже) — правильный вариант для этого
направления, но также показывает, что «хорошие» случаи (мало циклов) не
дают материала для контрпримера: искать нужно среди перестановок с МНОГИМИ
циклами, что возвращает к нерешённому случаю идеи 1.

## Идея 3 (не реализована из-за бюджета): нижняя оценка S_c около медианы

PLAN §8 предлагает: либо нижнюю оценку `S_c` при `c` около медианы `F`,
либо min-max аргумент. Идея, которую не успели проверить: `S_c = sum_C
(2M(C)+E(C)-1)`, и `M(C)>=1` для любого нетривиального цикла, так что
`S_c >= 2*K_c + sum_C E(C) - K_c = K_c + sum E(C) >= K_c` (так как `E(C)>=0`).
Значит `S_c >= K_c` — грубая, но верная нижняя оценка, не использованная
здесь: она уменьшает `2F_c - S_c` на величину числа циклов, но никак не
связана с `R_c`, и её грубость (равенство только при `M(C)=1` для всех
циклов, т.е. только вращения одного цикла на весь набор нагрузок) делает
её, вероятно, недостаточной — не проверено численно в этой сессии.

## Обструкция (честный итог)

Перенос доказательства N1 (C18, лемма о нагрузках/связности) на `R_c`
работает только НА УРОВНЕ ОДНОГО ЦИКЛА (ограничивает разброс вершин внутри
цикла его собственным `F(C)`), а H10 для общего `pi` требует ограничения на
СОВМЕСТНОЕ расположение переносчиков ВСЕХ циклов сразу — это качественно
другое утверждение, для которого в N1 нет ни аналога, ни намёка на метод (по
правилу 16 AGENTS.md перенос C18 на `R_c` в этом месте действительно
"требует отдельного обоснования", как и предупреждает PLAN §8, и это
обоснование не найдено). Без него единственная опора — численный перебор,
который пока (4<=n<=9 исчерпывающе, 4<=n<=12 семейства, n<=100 выборки) не
нашёл ни одного `pi`, где `min_c[2F_c-S_c+R_c] > B_n+1`, и единственный
известный вход с точным равенством `B_n+1` — это отражение `n=6,h=2`,
которое теперь полностью объяснено (`H10_reflections.md`).

## Не сделано в этой сессии (для следующей)

- Не измерена скорость n=10 exhaustive check для H10 (3.6 млн перестановок);
  по правилу 10 не запущена без оценки. Оценка по интерполяции времени
  n=9 (869 с) с учётом роста стоимости на перестановку с `n` (`O(n^2)` за
  счёт `cycle_data`/`carrier_route`) и роста числа перестановок (`x10`):
  порядка `869 * 10 * (10/9)^2 ~ 10700 с ~ 3 ч`, что совпадает с оценкой
  PLAN (`~3ч`) — не запускать без отдельного решения владельца (правило 10).
- Не проверена идея 3 (нижняя оценка `S_c >= K_c`) численно.
- Не исследованы структурированные семейства с МНОГИМИ короткими циклами и
  специально расставленными (адверсариально) переносчиками при `n` порядка
  нескольких десятков (не 20/50/100 случайных выборок, а целенаправленно
  сконструированные) — естественный следующий эксперимент для сессии 5.
