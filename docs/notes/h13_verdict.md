сессия 7). Задача из трёх пунктов; ниже — по пунктам.

## Итог

  `f(n) <= floor(n/2) + O(1)` — **не найдена и не опровергнута строго** в рамках
  бюджета. Первая попытка построить контрпример-опровержение содержала ошибку
  (см. §2 ниже, оставлено как предупреждение будущей сессии); после её
  исправления доступные данные (точные таблицы, 9 <= n <= 12) недостаточны,
  чтобы отличить «растёт неограниченно, но медленно» от «остаётся O(1)».
  Статус H13(2): **CONJECTURED/OPEN**, не PROVED и не REFUTED.
- Пункты (1) и (3) выполнены на исчерпывающих данных при малых n (VERIFIED
  4 <= n <= 8 для (1), 4 <= n <= 9 для (3)) и дают содержательный, годный
  для дальнейшей работы ответ (см. §3, §4).
- Критерий сессии 7 («доказанная общая оценка либо вердикт и переход к H3»)
  не даёт доказанной оценки; по букве критерия и по исчерпанию бюджета одной
  сессии — переход к H3 (индукция, PLAN §4.3 п.3) как следующему направлению,
  H13 остаётся открытой гипотезой для отдельной попытки другими средствами
  (не численным перебором — см. §2).

## 1. Метод

`experiments/h13_blocks.py` (h13_blocks-1.1): семейство `pi_k(n)` — тождество
с k непересекающимися локальными обменами на рёбрах `floor(i*n/k)`, i = 0..k-1
(рёбра на расстоянии >= 2 друг от друга, не взаимодействуют). Вычисляется
`I(pi)` (как в `line_model.py`), точное `d(pi)` из сертифицированных таблиц
`data/tables/dist_n{9,10,11,12}.bin` (n = 11, 12 воспроизведены заново
`exact/bfs_fast.c`, 15 с и ~2 мин), и (для n <= 10) точное `d_line(pi)` через
`line_bfs` из `line_model.py`.

`experiments/h13_structure.py` (h13_structure-1.0): при 4 <= n <= 8 —
исчерпывающе по всем pi: `I(pi)`, `d_line(pi)`, `d(pi)`, `blocks(pi)` (число
связных кусков несовпадений в лучшей (q, c)-релейблинге). Отчёты
`data/runs/h13_blocks/`, `data/runs/h13_structure/`.

## 2. Пункт (2): попытка контрпримера и её ошибка

Гипотеза: для `pi_k(n)` при фиксированном k >= 3 и растущем n минимальное
число вращений в любом слове с `N_X = I(pi) = k` должно быть не меньше длины
кратчайшего обхода k точек на окружности из фиксированного старта — по
формуле `n - maxgap`, где `maxgap` — наибольший из k зазоров между рёбрами
(для равномерной расстановки `maxgap = n/k`). Отсюда ожидалось
`d_line(pi_k) >= k + n - n/k`, что при k = 3 растёт как `n/6` быстрее любого
`floor(n/2) + O(1)` — предполагаемое опровержение.

**Эта оценка неверна как точная формула для линейной модели.** Прямая проверка
(`n = 8, k = 3`, рёбра {0,1},{2,3},{5,6}): формула предсказывает
`I + (n − maxgap) = 3 + 5 = 8`, но точное `d_line` (через `line_bfs`,
исчерпывающий BFS по всем (q, c)) равно 13, и прямая независимая BFS-проверка
в объектной модели (state, head) подтверждает 13, а не 8. Причина ошибки:
в линейной модели конечная позиция головы `c` не свободна независимо от
конечного расклада — сдвиг c одновременно переразмечивает СОДЕРЖИМОЕ линии
(не только целевую позицию головы), так что «дойти до финиша с любой головой»
и «дойти до конкретного (id, head = j1(c))» — разные задачи; путь длины 8,
которым голова доходит до состояния (identity, head = 5), не соответствует
НИКАКОМУ допустимому c (для c = 5 целевой релейблинг — другой массив, не pi).
Простое «TSP по кругу с фиксированным стартом» не учитывает эту связку и
даёт заниженную (недостижимую) оценку. Отсюда: план обобщить связку «F_c, S_c,
подход/стык/финал» на общий pi нужен целиком (леммы 3–4 C32), а не только
геометрия обхода точек — асимптотика n(1 − 1/k) не доказана.

Урок для дальнейшей работы: расстояние в линейной модели не сводится к сумме
«число обменов + геометрический обход рёбер обмена»; кратчайшее слово, видимо,
использует ещё и позиции, где обмена нет, для регулировки итогового сдвига.
Не повторять этот вывод без проверки на объектной BFS малого n (как сделано
здесь), прежде чем публиковать формулу.

## 3. Пункт (2): что подтверждено числами (n <= 12, k <= 4)

`data/runs/h13_blocks/report.json` (`exact_d` — сертифицированные таблицы,
надёжно; отдельный прогон с `exact_d_line` прерван по времени — из него
сохранилась только точка n = 9, k = 2 в `report.log`, `line_bfs` пересчитывает
таблицу заново на каждую (k, n) и не годится для полного сканирования этим
скриптом без кеширования):

| k | n = 9 | n = 10 | n = 11 | n = 12 | `d − 2I − floor(n/2)` (9..12) |
|---|---|---|---|---|---|
| 2 | d=10 | d=12 | d=12 | d=14 | 2, 3, 3, 4 |
| 3 | d=12 | d=13 | d=14 | d=15 | 2, 2, 3, 3 |
| 4 | d=13 | d=14 | d=15 | d=16 | 1, 1, 2, 2 |

`I(pi_k) = k` точно во всех проверенных случаях (не доказано в общем n, только
проверено численно 9 <= n <= 12). Разрыв `d - 2I - floor(n/2)` растёт очень
медленно (на 1 за 3-4 шага n) и слишком мал диапазон n (единственно доступный
без нового BFS — до n = 12, дальше n! не позволяет точную таблицу), чтобы
отличить рост `Theta(n)` от `O(1)` или `O(log n)`. Для n = 9, k = 2:
`d_line = d = 10` (обход по кругу не даёт преимущества на этом входе).
**Вывод: данные не опровергают и не подтверждают строгую формулу H13(2);
нужен либо больший n (за пределами точного BFS — нужна доказанная нижняя
оценка, не перебор), либо другая техника.** Не повторять BFS при n >= 13
(факториал не позволяет точную таблицу за разумное время и место).

## 4. Пункты (1) и (3): структура на n <= 8/9 (исчерпывающе)

`data/runs/h13_structure/report_n7_7.json`, `report_n8_8.json`.

**(3) Кто близок к максимуму `I(pi)`.** Порог `floor((n−1)^2/4) − n/4`:
n = 7 → 7.25 (56 pi с `I > 7.25`, т.е. `I in {8,9}`); n = 8 → 10.0 (80 pi
с `I in {11, 12}`). Единственный максимум `I = floor((n-1)^2/4)` при
4 <= n <= 9 — ровно `rev_n` (все n его вращений дают одно и то же I по
симметрии; подтверждает наблюдение line_model report — argmax_inv = rev_n на
всём диапазоне). Полоса `I = floor((n-1)^2/4) − 1` уже не только отражения:
из 56 (n=7) только 7 — отражения (все вращения rev_7), 49 — не отражения,
это перестановки с 1-3 связными «блоками» почти-развёрнутых участков (т.е.
локальные частичные развороты типа `(...,6,5,4,3,2,...)`), не рассеянные.
**Значит близкий к максимуму I(pi) сам по себе не выделяет только отражения**,
но выделяет «мало и крупных блоков», а не «много и мелких» — обратный режим
семейству §2-3.

**(1) `d_line − d` по числу блоков** (n=7: `{1: max 3 (299/81/24 случаев),
2: max 3, 3: max 1, 4: 0}`; n=8: `{1: max 4 (124 случая), 2: max 4, 3: max 2,
4: 0}`). При этих малых n разрыв `d_line − d` не растёт с числом блоков —
наоборот, permutations с 1-2 блоками дают самый большой наблюдаемый разрыв, а
4 блока — разрыв 0 (n=8, 336 входов). Это НЕ то же явление, что §2-3 (там
разрыв — между `d_line` и «геометрический перебор точек», здесь — между
`d_line` и истинным `d`, т.е. выигрыш от обхода по кругу): обход по кругу
помогает больше всего при малом числе крупных блоков (где один «плохой» разрыв
можно обойти с другой стороны), а не при многих мелких.

## 5. Рекомендация

H13(2) — не путь к C15 в пределах одной сессии; ни конструктивная схема, ни
доказанная нижняя оценка не получены. Численные данные малых n не различают
гипотезы. Следующая сессия — H3 (индукция, PLAN §4.3 п.3), бюджет 2 сессии до
вердикта, как в PLAN. H13(1) существование `d_line = B_n` только на sigma_n
(C33) остаётся VERIFIED 4 <= n <= 9 и не затронуто этим вердиктом.
