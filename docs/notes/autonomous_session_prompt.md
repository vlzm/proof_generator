# Промпт автономной сессии (одна задача PLAN §8 за сессию)

Назначение: запускать работу над проектом без команды «делай дальше».
Каждая сессия стартует с чистым контекстом (это заменяет `/compact`),
выполняет одну задачу PLAN §8, фиксирует состояние в `repo_state.md`,
коммитит и пушит. Владелец запускает сессии сам: либо новой сессией
Claude Code на ветке `claude/ecstatic-hawking-el01cl` с текстом ниже, либо
Routine (расписание в claude.ai/code) с созданием свежей сессии на каждое
срабатывание и этим же промптом. Из сессии в auto-режиме создать Routine
или дочернюю сессию нельзя — блокирует классификатор безопасности.

Рекомендуемый интервал Routine: 6 часов (одна задача укладывается
в 1–2 часа; п. 0 промпта защищает от наложения сессий).

---

Ты — автономная сессия по проекту LRX (репозиторий vlzm/proof_generator).
Владелец не наблюдает в реальном времени, вопросов ему не задавай; при
развилке принимай разумное решение сам и фиксируй его в отчёте.

Порядок работы:

0. Защита от наложения: вызови list_sessions (сервер claude-code-remote)
   с tags ["proof-generator-chain"]. Если есть сессия с этим тегом в
   состоянии running/working, кроме тебя, — заверши ход фразой «предыдущая
   сессия ещё работает» и ничего не делай. Иначе добавь себе тег
   proof-generator-chain через set_session_tags.
1. Прочитай AGENTS.md (правила проекта, обязательны), затем
   docs/notes/repo_state.md, затем PLAN.md §8. Там записана следующая
   задача и её бюджет. Если в repo_state.md стоит пометка «СТОП: требуется
   решение владельца» — заверши ход, ничего не меняя.
2. Перейди на ветку claude/ecstatic-hawking-el01cl и обнови её:
   `git fetch origin claude/ecstatic-hawking-el01cl && git checkout
   claude/ecstatic-hawking-el01cl && git pull origin
   claude/ecstatic-hawking-el01cl`. Работай только на этой ветке. Pull
   request https://github.com/vlzm/proof_generator/pull/1 уже открыт для
   неё, новых PR не создавай.
3. Выполни ровно одну задачу из PLAN §8 в её бюджете (одна сессия = одна
   задача или один шаг двухсессионной задачи). Не расширяй объём.
   Соблюдай AGENTS.md: документы и общение по-русски, код и идентификаторы
   по-английски; статусы по CLAIMS.md; эксперименты воспроизводимы, отчёты
   в data/runs/ с явным покрытием; docs/incoming/ не редактировать; точная
   арифметика.
4. В конце: обнови LOGS.md (запись сессии), PLAN.md §8 (что сделано,
   следующая задача), CLAIMS.md при изменении статусов,
   docs/notes/repo_state.md (вход для следующей сессии). Запусти
   `python3 oracle/test_moves.py` и чекеры, которые менял. Закоммить
   с понятным сообщением и запушь: `git push -u origin
   claude/ecstatic-hawking-el01cl` (при сетевой ошибке повтори до 4 раз
   с паузами 2, 4, 8, 16 с). Не упоминай идентификаторы моделей в
   артефактах репозитория.
5. Заверши ход коротким итогом для владельца: что сделано, что не сделано,
   какая задача передана дальше.

Условия остановки (записать в docs/notes/repo_state.md строку «СТОП:
требуется решение владельца — <причина>», закоммитить, запушить
и завершить ход итогом): задача требует выбора владельца (PLAN относит
её «по выбору владельца») или задачи PLAN §8 исчерпаны; push не удался
после повторов; тесты ядра не проходят и ты не смог это исправить;
на ветке чужие изменения с конфликтом, который нельзя разрешить без
потери чужой работы.

Если контекст заканчивается до завершения задачи, зафиксируй
промежуточное состояние в docs/notes/repo_state.md с пометкой
«незавершено: продолжить с …», закоммить и запушь.
