# H3 — начало: склейка соседней пары как вложение задачи n − 1

Дата: 15.09.2026 (сессия 9, после вердикта по H13-I). Ядро oracle-1.0.
Код: `experiments/h3_glue_probe.py` (h3_glue_probe-1.0).
Отчёт: `data/runs/h3_glue_probe/report.md`, `probe.json`.

Это **не** вердикт по H3 — задача сессии 9 была H13-I. Здесь зафиксировано
ровно то, что успела измерить одна короткая проба, чтобы сессия 10 не
начинала с нуля.

## 1. Схема

H3 (PLAN §4.3, п. 3): рекуррента `T_n <= T_{n−1} + (n − 1)` при `T_4 <= 6`
даёт ровно `B_n`; запас нулевой. Нужно вложение задачи n − 1 в задачу n и
стоимость имитации её ходов; L и R вращают весь массив, поэтому элемент
нельзя молча исключить.

Проверенная схема — **склейка**: привести состояние к такому, где два
значения `v` и `v + 1 mod n` стоят в циклически соседних ячейках именно в
этом порядке (как в тождественной перестановке), затем считать пару одной
«суперъячейкой» и решать задачу размера n − 1.

- `G_A` — склеена именно пара `(n−1, 0)`; контракция `c_A` удаляет из слова
  значение `n − 1`.
- `G_B` — склеена какая-нибудь пара `(v, v+1 mod n)`; контракция `c_B`
  удаляет значение `v + 1` первой склеенной пары и пересчитывает ранги.
  Обе контракции переводят тождественную перестановку в тождественную.

Величина, которая решает дело:

    R(n) = max_pi min_{sigma ∈ G} [ dist(pi, sigma) + E(sigma) ],
    E(sigma) = d_n(sigma) − d_{n−1}(c(sigma)).

Действительно `d_n(pi) <= dist(pi,sigma) + d_n(sigma) =
dist + E(sigma) + d_{n−1}(c(sigma)) <= R(n) + T_{n−1}`, так что
`R(n) <= n − 1` замыкает рекуррентy, а `R(n) > n − 1` опровергает схему
в этом виде.

## 2. Измерено (исчерпывающе, 4 <= n <= 8, BFS эталонными ходами)

| n | бюджет n−1 | схема A: S, E, R | схема B: S, R |
| --- | --- | --- | --- |
| 4 | 3 | 3, 2, **5** | 1, **4** |
| 5 | 4 | 4, 4, **6** | 3, **4** |
| 6 | 5 | 5, 6, **8** | 3, **5** |
| 7 | 6 | 6, 7, **10** | 5, **6** |
| 8 | 7 | 8, 9, **13** | 5, **8** |

1. **Схема A опровергнута**, наименьшее n равно 4, и перерасход растёт:
   `R − (n−1)` = +2, +2, +3, +4, +6. Грубая оценка «худшая склейка + худшая
   имитация» (`S + E`) ещё хуже: 5, 8, 11, 13, 17 против 3, 4, 5, 6, 7.
   Это тот же эффект, что у одноэлементной редукции для `I(pi)`
   (`h13_line_model.md` §1.7): фиксированный выделенный элемент — плохое
   вложение.
2. **Схема B почти проходит**: `R − (n−1)` = +1, 0, 0, 0, +1
   (равенство при n = 5, 6, 7; перерасход ровно 1 при n = 4 и n = 8,
   свидетель n = 8 — `(0,3,5,7,2,6,4,1)`). В этом виде схема тоже не
   замыкает рекуррентy, но промах — единица, а не растущая величина.
3. **Структурный факт (проверено при 4 <= n <= 8, все pi):** у каждого
   состояния есть *кратчайшее* слово, проходящее через `G_B`:
   `min_{sigma ∈ G_B} [dist(pi, sigma) + d_n(sigma)] = d_n(pi)` для всех pi
   (обход равен 0). Значит склейка соседней пары не требует крюка;
   потеря в п. 2 — целиком в оценке `d_{n−1}(c_B(sigma))` сверху величиной
   `B_{n−1}` для *всех* склеенных состояний, тогда как трудные
   контрактированные экземпляры встречаются не у всех sigma.

## 3. Что делать в сессии 10

1. Уточнить R, учитывая совместное распределение `E(sigma)` и
   `d_{n−1}(c_B(sigma))`: нужна не оценка `max E + max d_{n−1}`, а
   `max_pi min_sigma [dist + E(sigma) + d_{n−1}(c_B(sigma))]`, то есть
   оценка на склеенных состояниях с *большим* `d_{n−1}(c_B)`. Измерить
   `max E(sigma)` отдельно по слоям `d_{n−1}(c_B(sigma))`.
2. Проверить варианты контракции: удалять `v` вместо `v+1`; выбирать
   склеенную пару, минимизирующую `E`; склеивать блок длины >= 2.
3. Явная имитация: построить слово задачи n из кратчайшего слова задачи
   n − 1, считая пересечения головой суперъячейки (каждое пересечение
   стоит +1 вращение); сравнить фактическую длину с `B_n` при 4 <= n <= 8.
   Это и есть «стоимость имитации ходов» из PLAN §4.3.
4. Бюджет — 1 сессия до письменного вердикта.
