# Route bound via the largest carrier gap (C32)

Редакция 13.09.2026 (сессия 5, продолжение H10 после сессии 4:
`docs/proofs/h10_reflections.md`, C28-C31). Строит инструмент общего случая,
не привязанный к отражениям: усиление леммы 6 (`R_c <= H(c)`) той же статьи.
Обозначения — PROBLEM §5.2, `carrier_route` — `constructions/strict_upper.py`.
Машинная сверка — `checks/check_C32.py`, отчёт `data/runs/check_C32/`.

## 1. Утверждение

Пусть `pts` — конечное подмножество `Z_n`, `0` и `c` из `pts` (в частности
`pts = carriers(f_c) u {0, c}`). Определим `g_max(pts)` как наибольший из
циклических промежутков между соседними (в порядке на окружности) точками
`pts`; если `|pts| = 1`, положим `g_max = n`.

**Лемма (C32).** `R_c <= 2(n - g_max)`, где `R_c` — длина маршрута,
построенного `carrier_route(required, c, n)` для `required = carriers(f_c)`.

Это не зависит от структуры f_c (циклов, транспозиций, отражений): чисто
геометрическое утверждение о функции `carrier_route`.

## 2. Доказательство

Пусть `pts = required u {0,c}` отсортированы на окружности, `m = |pts|`.
`carrier_route` перебирает все `m` промежутков между соседними точками
`pts` как кандидата на «непокрытый» (шаг g в коде); для промежутка g,
исключаемого из покрытия, `L = n - (длина промежутка g)` — длина покрываемой
дуги от `lo` до `hi` (в рёбрах), а `x0, xc` из `[0, L]` — положения `0` и `c`
внутри этой дуги относительно `lo`. Для выбранного `g` алгоритм строит два
маршрута:

```text
costA = x0 + L + (L - xc) = 2L + x0 - xc,
costB = (L - x0) + L + xc = 2L - x0 + xc,
```

оба обходят дугу `[lo,hi]` целиком (значит, покрывают все точки `pts`,
поэтому и все точки `required`) и заканчиваются в `c`. Так как
`x0, xc` из `[0, L]`, то `costA + costB = 4L`, откуда

```text
min(costA, costB) <= 2L.
```

Это верно для любого выбора исключаемого промежутка `g`, в частности для
`g`, реализующего `g_max` (промежуток максимальной длины). Для этого выбора
`L = n - g_max`. Поскольку `carrier_route` берёт минимум по всем `g` (и
дополнительно рассматривает маршруты с полным оборотом, которые могут только
уменьшить итоговую стоимость), длина найденного маршрута не больше значения
при этом конкретном `g`:

```text
R_c <= min(costA, costB)|_{g = g_max} <= 2(n - g_max).
```

Случай `m = 1` (тогда `required = {}` или `required subset {0} `, `c = 0`):
код задаёт `L = 0` явно, маршрут пуст, `R_c = 0 = 2(n - n)`, что согласуется
с принятым `g_max = n`. QED.

## 3. Сравнение с леммой 6

`H(c)` не меньше `2(n - g_max)` при всех входах, встреченных в проверке
(§4): интуитивно `H(c)` — маршрут, рассчитанный на худшее возможное
расположение переносчиков (весь остаток окружности), тогда как `2(n-g_max)`
использует фактическое наибольшее пустое место в `carriers(f_c) u {0,c}`
именно для этого `pi` и `c`. Строгого доказательства `2(n-g_max) <= H(c)`
при всех входах в этом файле нет (не требуется: C32 — самостоятельная верхняя
оценка на `R_c`, не сравнение с `H(c)`); численно неравенство наблюдается
во всех проверенных случаях (§4).

## 4. Применение: усиленное достаточное условие H10

Подставляя C32 вместо леммы 6 в лемму 10 (C30) той же схемы (C29 даёт
`S_c >= 3 K_c`, лемма 8 — переформулировку H10), получаем более точное
достаточное условие:

```text
(SC')   3 K_c + 2(P - F_c) >= floor(n/2) - 1 + 2(n - g_max(c))
```

Если для данного `pi` существует `c` с (SC'), то H10 верна для этого `pi`
(доказательство дословно повторяет доказательство леммы 10, с `2(n-g_max(c))`
на месте `H(c)`).

(SC') не слабее (SC) из C30: при том же `c`, `2(n-g_max(c)) <= H(c)`
эмпирически (§3) на всех проверенных входах, значит выполнение (SC) влечёт
выполнение (SC') при том же `c` во всех этих случаях; строгого доказательства
импликации в общем виде нет, но она не нужна для вывода ниже — оба условия
проверяются напрямую по факту, а не друг через друга.

## 5. Измеренное покрытие

`checks/check_C32.py --exhaustive N`: для каждого `pi` при `4 <= n <= N`
проверяется (а) сама лемма C32 на всех `(pi,c)` — не нарушена ни разу; (б)
доля `pi`, для которых (SC) или (SC') выполнено хотя бы при одном `c`:

| n | SC (C30, H(c)) | SC' (C32, 2(n-g_max)) |
|---|---|---|
| 4 | 100.0 % | 100.0 % |
| 5 | 91.7 % | 100.0 % |
| 6 | 92.5 % | 95.3 % |
| 7 | 90.3 % | 92.8 % |
| 8 | 83.1 % | 90.8 % |
| 9 | 81.5 % | 89.7 % |

(SC') закрывает заметно больше входов, чем (SC) (например, все входы при
n = 5, а не 91.7 %), но доля непокрытых входов не обнуляется и, судя по
тренду n = 6..8, не убывает к нулю с ростом n. Значит одних лемм C29 + C32
(независимо применённых к одному и тому же кандидату `c`) недостаточно для
общего доказательства H10: непокрытые случаи — именно те, где ни один
`c` не даёт одновременно малое `F_c` (или большое `K_c`) и большой
`g_max(c)`; это тот же геометрический разрыв, что описан в
`docs/notes/H10_general_obstruction.md` §1 («идея 1»), теперь измеренный
через `g_max` вместо `H(c)`, но не устранённый.

## 6. Статус и вывод

C32 — PROVED (доказательство §2, элементарное, без ограничений на `pi`).
Она не доказывает H10 в общем случае и не обязана: это инструмент (более
точная верхняя оценка `R_c`), а не завершение цепочки. Оставшийся разрыв —
не в качестве оценки `R_c` для фиксированного `c`, а в связи между `c`,
минимизирующим `2F_c - S_c`, и `c`, максимизирующим `g_max` (или иначе
минимизирующим фактический `R_c`) — эти два `c` в общем случае разные
(пример N1 §... см. таблицу в `H10_general_obstruction.md`), и совместная
оценка по одному и тому же `c` не найдена.
