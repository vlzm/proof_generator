# fast_toric_inv — быстрый алгоритм для I(pi), расширенная проверка H13-I (сессия 9)

Задача из PLAN §8 / `docs/notes/h13_line_model.md` §6: доказать H13-I
(`I(pi) <= floor((n-1)^2/4)` для всех pi при всех n >= 4), бюджет 1 сессия
до письменного вердикта.

Версия: `fast_toric_inv-1.1` (`experiments/fast_toric_inv.c`, C), ядро не
используется напрямую (чистая комбинаторика перестановок, без ходов LRX).

## 0. Быстрый алгоритм

`experiments/line_profile.c` считает `I(pi) = min_{q,c} inv(w)` перебором всех
`n^2` разрезов и явным подсчётом инверсий за `O(n^2)` каждый — итого `O(n^4)`
на одну pi, что ограничивало исчерпывающую проверку n <= 10 (n = 10: 93 с).

Новый алгоритм — `O(n^2)` на одну pi (для сравнения: n = 12 — 3.5 мин против
оценки в часы для `O(n^4)`):

1. Для фиксированного разреза позиций q (вращение v перестановки pi, начиная
   с индекса q) и сдвига значений s пусть `pos = v^{-1}`. При переходе
   `s -> s+1` инверсии меняются ровно на `n-1-2*pos[s]`: элемент с исходным
   значением s перескакивает с ранга 0 (наименьший после переразметки s) на
   ранг n-1 (наибольший после s+1) — единственный элемент, чей вклад меняется.
   Значит `min_s inv(v; s) = inv(v; 0) + min_{0<=t<=n} S_t`, `S_0 = 0`,
   `S_t = sum_{k=0}^{t-1} (n-1-2*pos[k])` — префиксные суммы, `O(n)` после
   готового `pos`.
2. При переходе `q -> q+1` (v сдвигается влево на один, `v[0]` уходит в конец)
   инверсии v меняются ровно на `n-1-2*v[0]` (v[0] — значение из 0..n-1, среди
   остальных n-1 элементов ровно `v[0]` меньше него). `pos` при этом сдвигается
   на `-1 mod n` для всех значений — тоже `O(n)`.

Итого `O(n)` на один q, `O(n^2)` на одну pi (плюс разовый `O(n^2)` или
`O(n log n)` на инициализацию — не доминирует). Обозначение:
`C_q(pi) := min_c inv(w_{q,c})` — минимум по сдвигу значений при
фиксированном разрезе позиций; `I(pi) = min_q C_q(pi)`.

Проверка корректности: `validate n` сравнивает быстрый и прямой (`O(n^4)`)
алгоритмы на всех перестановках — совпадение без исключений при
4 <= n <= 9 (`validate_n4-9.jsonl`, все 439 640 перестановок, 0 расхождений).

`pi_h(i) = h - i mod n`. **H13-I VERIFIED расширено с 4 <= n <= 10 до
4 <= n <= 12** (исчерпывающе), нарушений нет.

## 2. Большие n и состязательный поиск

`sample n trials seed family` (family: reflection | affine | random | rotsigma
— поворот sigma_n) и `localsearch n restarts stall seed` (hill-climbing:
случайные транспозиции, принимается только строгое улучшение, `stall`
неудач подряд — рестарт).

- **Отражения** (`sample_reflection.jsonl`): `I = floor((n-1)^2/4)` **точно**
  при n = 20, 50, 100, 101, 200, 500, 1000 — формула, видимо, точна при всех n
  (ожидаемо: сессия 8 уже знала это при n <= 10; здесь подтверждено на 3
  порядка величины дальше).
- **Аффинные** `pi(i) = a*i+b mod n` (gcd(a,n)=1), **повороты sigma_n**
  (`sample_random_affine_rotsigma.jsonl`): при тех же n достигают точного
  `floor((n-1)^2/4)` на части выборки (включают отражения/их аналоги как
  частный случай) — нарушений нет ни разу (2000 проб на n).
- **Случайные** перестановки: `I` заметно ниже бюджета (например n = 1000:
  max 236 591 из 2000 проб против бюджета 249 500) — ожидаемо, максимум редок.
- **Состязательный локальный поиск** (`localsearch_small.jsonl`,
  `localsearch_large.jsonl`): на n = 11, 12 (где ответ известен точно) находит
  ровно верный максимум (25, 30) — метод валиден. При n = 15 находит точный
  максимум `floor((n-1)^2/4) = 49` (лучшее найденное слово — два блока
  реверса, структурно похоже на C32). При n = 20, 30, 50, 100 (500 рестартов,
  до 3000 неудач подряд) — максимум найден ниже точного (out of reach for
  a weak single-transposition neighbourhood: 80/90, 188/210, 548/600,
  2283/2450), но **ни одного нарушения бюджета не найдено** ни в одном из
  примерно 10 000 локальных прогонов суммарно.

Итог §2: нет контрпримера к H13-I ни в структурированных семействах, ни при
состязательном поиске, вплоть до n = 1000 (структуры) / n = 100 (полный
локальный поиск).

## 3. H13-I-avg — более сильная и, по-видимому, более доступная лемма

Из алгоритма §0: `I(pi) = min_q C_q(pi)`, где `C_q` вычисляется точно и дёшево.
Значит **min_q C_q(pi) <= (1/n) sum_q C_q(pi)** тривиально (минимум не больше
среднего) — если доказать усреднённую версию, H13-I следует немедленно.
В отличие от совместного усреднения по всем `n^2` разрезам (q, c) (сессия 8:
не работает, для sigma_n среднее ~n^2/3 > n^2/4), здесь усреднение — только по
q, а c для каждого q берётся **точно оптимальным**, что даёт гораздо более
сильную (и, по данным, верную) оценку:

**H13-I-avg**: `(1/n) * sum_{q=0}^{n-1} C_q(pi) <= floor((n-1)^2/4)` для всех
pi, всех n >= 4.

`avgexhaust n` — точная проверка (`avgexhaust_n4-11.jsonl`, `avgexhaust_n12.json`):

| n | n * floor((n-1)^2/4) | max sum_q C_q(pi) | равенство (max/n = bound) | нарушений |
|---|---|---|---|---|
| 4 | 8 | 8 | да | 0 |
| 5 | 20 | 20 | да | 0 |
| 6 | 36 | 36 | да | 0 |
| 7 | 63 | 63 | да | 0 |
| 8 | 96 | 96 | да | 0 |
| 9 | 144 | 144 | да | 0 |
| 10 | 200 | 200 | да | 0 |
| 11 | 275 | 275 | да | 0 |
| 12 | 360 | 360 | да | 0 |

**VERIFIED 4 <= n <= 12**: максимум среднего равен ровно `floor((n-1)^2/4)`
(тесно, без запаса), достигается на argmax = sigma_n (последняя перестановка
в порядке Лемера при каждом n) — по built C33 sigma_n является отражением,
так что равенство согласовано.

### 3.1. Доказательство H13-I-avg не найдено за сессию

Разложение: `C_q = inv(v_q) - 2 M_q`, `M_q = max_{0<=t<=n} (P_t(v_q) -
t(n-1)/2)`, `P_t(v_q) = sum_{k<t} pos_q(k)` — сумма позиций (во вращении v_q)
t наименьших значений. Отдельно:

- `sum_q inv(v_q) = sum_{delta=1}^{n-1} (n-delta) * K_delta(pi)`,
  `K_delta = #{i : pi(i) > pi((i+delta) mod n)}` (число i было явно перепроверено:
  для тождественной pi при n=4 даёт 10, что совпадает с прямым подсчётом суммы
  инверсий по всем 4 вращениям — 0+3+4+3=10).
- Замкнутой формулы для `sum_q M_q` через K_delta или другие простые
  инварианты pi за сессию не найдено; попытка «сопряжённого» тождества
  (M через ту же схему, что и inv, но по значениям вместо позиций) не
  завершена.

### 3.2. Отвергнутые универсальные правила выбора q (не повторять)

Проверено и **опровергнуто** экзистенциальными контрпримерами (перебор):

- **Фиксированный q = 0** (`q0exhaust.jsonl`): `max_pi C_0(pi) > floor((n-1)^2/4)`
  начиная с n = 7 (перебор `bound+1`: n=7 — 7 входов, n=8 — 16, n=9 — 162 из
  362 880). Значит НИКАКОЙ фиксированный (не зависящий от pi) разрез позиций
  не работает всегда.
- **Фиксированная пара (q, q+off)** для одного глобального off (`pairexhaust.jsonl`):
  off=1 работает без нарушений при n = 7, 8, 9, но **нарушается** при n = 10
  (10 входов, `max = 21 = bound+1`) и n = 11 (11 входов, `max = 26`); антипод
  off = n/2 нарушается уже при n = 8 (8 входов); off=2 и off=n-2 нарушаются
  при n = 9 (9 входов каждый). Число нарушающих входов каждый раз равно
  ровно n — предположительно сами отражения (не проверено поимённо, но
  согласуется с тем, что I(pi)=bound достигается ровно на n отражениях).

Вывод: хороший q существенно зависит от pi; простое универсальное правило
(фиксированный q или фиксированная малая группа q) не существует — это
уточняет и подтверждает вывод сессии 8 (лемма C: локальные условия
недостаточны) на новом, более точном инструменте.

## 4. Вердикт

H13-I остаётся CONJECTURED в общем виде. Расширения по сравнению с сессией 8:

1. Новый алгоритм `O(n^2)` вместо `O(n^4)` (validated exactly, 4 <= n <= 9).
2. H13-I VERIFIED расширено с 4 <= n <= 10 до **4 <= n <= 12** (исчерпывающе);
   SAMPLED без нарушений структурированными семействами до n = 1000 и
   состязательным локальным поиском до n = 100 (~10 000 локальных прогонов).
3. Найдена и VERIFIED (4 <= n <= 12, тесно) более сильная лемма H13-I-avg
   (среднее по q точного минимума по c), которая влечёт H13-I и выглядит
   существенно более доступной для доказательства, чем совместное усреднение
   по (q, c) (заведомо ложное) — но доказательство не найдено за сессию.
4. Простые универсальные (не зависящие от pi) правила выбора q — фиксированный
   q, фиксированная пара (q, q+off) для любого испытанного off — REFUTED
   конечными контрпримерами (n = 7..11).

Рекомендация следующей сессии: (а) наиболее многообещающее — попытаться
замкнуть доказательство H13-I-avg (нужна формула или оценка для `sum_q M_q`
в терминах инвариантов pi, парная с уже полученной для `sum_q inv(v_q)`);
(б) при неудаче — переход к индукции H3 (PLAN §4.3, бюджет 2 сессии), как
предписано PLAN §8 при исчерпании бюджета H13-I.
