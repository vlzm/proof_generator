# circular_sorting — cs(pi) против I(pi) и литературный след (сессия 9)

Цель. Установить, совпадает ли H13-I с результатом статьи
R. M. Adin, N. Alon, Y. Roichman, «Circular sorting», arXiv:2502.14398 (2025),
в которой, по доступным описаниям, доказано `max_pi cs(pi) = floor((n − 1)^2/4)`,
где `cs(pi)` — минимальное число обменов соседних по циклу позиций,
переводящих pi в поворот тождественной перестановки (голова отсутствует,
разрешены все n рёбер окружности, цель — тождественный циклический порядок).

Версии и код: `experiments/circular_sorting.py` (circular_sorting-1.0),
BFS по всему S_n от n поворотов тождественной перестановки, n генераторов.
`I(pi)` — по лемме 7 C37 (`docs/proofs/C37_toric_average.md`).
Ядро ходов и таблицы расстояний не используются.

Команда: `python3 experiments/circular_sorting.py --nmax 9`.
Параметры: только n; случайности нет. Покрытие: **исчерпывающее** по всем
`n!` перестановкам, все `n! * n` рёбер графа обменов. Время: 0.0, 0.0, 0.0,
0.1, 0.7, 8.3 с при n = 4..9; память при n = 9 — около 0.6 ГБ (список всех
перестановок и словарь индексов в Python). n = 10 не запускался: тот же код
потребует ~10 ГБ.

## Результат

| n | перестановок | max cs | `floor((n−1)^2/4)` | argmax cs | `cs != I` | `cs > I` | max `I − cs` (где) |
|---|---|---|---|---|---|---|---|
| 4 | 24 | 2 | 2 | `(0,3,2,1)` | 0 | 0 | 0 |
| 5 | 120 | 4 | 4 | `(0,4,3,2,1)` | 0 | 0 | 0 |
| 6 | 720 | 6 | 6 | `(0,5,4,3,2,1)` | 0 | 0 | 0 |
| 7 | 5 040 | 9 | 9 | `(0,6,5,4,3,2,1)` | 0 | 0 | 0 |
| 8 | 40 320 | 12 | 12 | `(0,7,6,5,4,3,2,1)` | 16 | 0 | 3 — `(0,5,2,7,4,1,6,3)` |
| 9 | 362 880 | 16 | 16 | `(0,8,7,6,5,4,3,2,1)` | 2 232 | 0 | 2 — `(0,1,6,3,8,5,2,7,4)` |

1. `cs(pi) <= I(pi)` для всех проверенных pi (`cs > I` — ни разу): сортировка
   пузырьком вдоль наилучшего двойного разреза не использует ребро разреза.
2. Равенство `cs = I` при `4 <= n <= 7`, но не при n = 8, 9: сортировка,
   использующая все n рёбер, бывает строго короче любого разреза. Самый
   большой разрыв при n = 8 — аффинный вход `(0,5,2,7,4,1,6,3)`
   (`I = 11`, `cs = 8`); это тот же вход, на котором сорвалась индукция
   по одному элементу (`docs/notes/h13_line_model.md` §1.7).
3. `max_pi cs(pi) = floor((n − 1)^2/4)` при `4 <= n <= 9` — согласуется
   с заявленной теоремой arXiv:2502.14398 (максимум на обращении, то есть
   на отражениях).

## Что это значит для проекта

- H13-I (`max_pi I = floor((n−1)^2/4)`) **строго сильнее** теоремы о
  `cs`: `cs <= I`, и при n = 8, 9 неравенство строгое на 16 и 2232 входах.
  Поэтому заявленная теорема сама по себе H13-I не даёт; вопрос в том, идёт
  ли её доказательство верхней оценки (по описанию — раздел 2.1) через выбор
  разреза: тогда это и есть H13-I.
- `cs(pi) <= N_X(w)` для любого слова w модели LRX, сортирующего pi (обмены
  слова — это обмены соседних по циклу позиций, а итог — поворот
  тождественной). Значит заявленная в статье точность на обращении
  (`cs(rev) >= floor((n−1)^2/4)`) — это нижняя оценка числа обменов
  для отражения, то есть часть нижней оценки C8/C13.
- Возможная замена разложения: вместо `N_X = I(pi)` (H13-I + H13-R) —
  `N_X = cs(pi)` плюс маршрут головы `<= floor(n^2/4)`; величина `cs` меньше,
  но маршрут головы должен обходить все рёбра, а не линию.

## Статус источника

Полный текст arXiv:2502.14398 в сессии 9 **не прочитан**: домен arxiv.org
закрыт egress-политикой окружения. Формулировка взята из описаний поисковой
выдачи (аннотация и оглавление) и здесь лишь **подтверждена численно**
для `4 <= n <= 9`. В CLAIMS.md это строка C38 со статусом CLAIMED.
Следующий шаг — получить текст разрешённым способом и провести аудит
раздела с верхней оценкой.
