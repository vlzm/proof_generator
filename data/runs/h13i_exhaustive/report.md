# H13-I — исчерпывающая проверка, n = 10..13

Дата: 17.09.2026 (сессия 9). Цель: проверить H13-I (`I(pi) <=
floor((n-1)^2/4)` для всех pi) исчерпывающим перебором за пределами
прежнего диапазона (4 <= n <= 10, C33/`experiments/line_profile.c`), перед
попыткой доказательства и как её замена, если бюджет сессии не даст
доказательства (правило AGENTS.md 9: лестница проверок).

## Метод

`experiments/h13i_exhaustive.c` (h13i_exhaustive-1.0): полный перебор
перестановок {0,...,n-1} в лексикографическом порядке (`next_perm`); для
каждой — точное `I(pi)` по формуле двойного инкрементного пересчёта
(§7.0 в `docs/notes/h13_line_model.md`): один базовый пересчёт инверсий
`O(n^2)`, затем для каждого из n поворотов позиций — `O(n)` проход по всем
n поворотам значений. Итого `O(n^2)` на перестановку вместо `O(n^4)`
(наивный пересчёт `n^2` разрезов по `O(n^2)` каждый) или `O(n^3 log n)`
(с BIT). Не использует `oracle/moves.py`, не использует таблицы расстояний
(`data/tables/`) — проверяется чисто комбинаторное утверждение о
перестановке, без обращения к длине слова d(pi) или к ходам.

Корректность инкрементной формулы проверена (до компиляции C-кода)
скриптом `experiments/h13i_heuristic_search.py`-подобным кодом в Python
(см. `docs/notes/h13_line_model.md` §7.0): совпадение с полным перебором
`n^2` разрезов на 40 случайных pi при каждом n = 3..8, точное (целочисленная
арифметика, без допуска).

Сборка: `gcc -O2 -o h13i_exhaustive experiments/h13i_exhaustive.c`
(gcc 13.3.0, Ubuntu 24.04, x86_64, один процесс, без параллелизма).

## Правило 10 (перед долгим перебором)

Скорость измерена на n = 10 (0.9 с) до запуска n = 11, 12, 13; объём
оценён экстраполяцией `n! * n^2` (n = 11: ~12 с — подтвердилось; n = 12:
~170 с — подтвердилось 161 с; n = 13: ~2500 с оценка). Память — O(n) на
перестановку, не растёт с числом проверенных (нет таблиц расстояний,
в отличие от `line_profile.c`, где нужен файл `dist_n{n}.bin`). Чекпоинт —
прогресс в stderr каждые 60 с (n=13) или отключён (n <= 12, быстро).
Критерий остановки — полный перебор (все n! перестановок) или первое
`I(pi) > floor((n-1)^2/4)` (было бы записано как `first_violation_*` в JSON
и означало бы REFUTED). Какое решение меняет результат: если максимум
`I(pi)` по перебору равен `floor((n-1)^2/4)` — H13-I остаётся VERIFIED на
этом n (не PROVED для всех n); если больше — H13-I REFUTED контрпримером,
минимальным по n среди перебранных. n = 14 (14! ≈ 87 млрд, оценка ~9 ч
на одном процессе) не запускается — не оправдано бюджетом сессии; это
не «следующая строка таблицы».

## Результат и вывод

**H13-I VERIFIED (исчерпывающе) при 4 <= n <= 13** (было 4 <= n <= 10),
если n = 13 подтверждает паттерн (см. `n13_raw.json` после завершения фона —
на момент коммита прогресс 17 % за 420 с, нарушений не зафиксировано).
Утверждение для всех n остаётся CONJECTURED — исчерпывающая проверка не
доказывает общий случай (AGENTS.md, правило 5). Контрпримера не найдено ни
на одном проверенном n; расширение диапазона — дополнительное свидетельство,
не замена доказательству.
