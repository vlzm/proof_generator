# toric_I_fast — H13-I, exhaustive max I(pi), extended to n <= 12 (сессия 9)

Цель: расширить исчерпывающую проверку `I(pi) <= floor((n-1)^2/4)` (H13-I,
C33) с 4 <= n <= 10 (`experiments/line_profile.c`, O(n^4) на перестановку) до
максимально доступного n за счёт более быстрого алгоритма, чтобы усилить
конечное подтверждение перед письменным вердиктом.

Версии: `experiments/toric_I_fast.c` (toric_I_fast-1.0), ядро не требуется
(вычисление чисто комбинаторное, таблицы расстояний не нужны — H13-I
утверждение только про I(pi), не про d(pi)).

Команда: `gcc -O3 -o toric_I_fast experiments/toric_I_fast.c && for n in 4 5
6 7 8 9 10 11 12; do ./toric_I_fast $n; done`. Перебор в лексикографическом
(код Лемера) порядке, как в `line_profile.c`.

Алгоритм: та же величина `I(pi) = min_{q,c} inv(w)` по n^2 разрезам, но за
O(n^2) на перестановку вместо O(n^4): сетка `inv(s,t)` (s — сдвиг позиций,
t — сдвиг значений) заполняется по двум точным тождествам (вывод и проверка —
`docs/notes/h13_line_model.md` §7, `experiments/circle_sort_equivalence.py`
и приложенный `verify_recurrence.py`, проверено брутфорсом при 2 <= n <= 7 —
5912 перестановок, 0 расхождений):

```
inv(s+1, t) = inv(s, t) + (n-1) - 2*((pi[s]    - t) mod n)
inv(s, t+1) = inv(s, t) + (n-1) - 2*((piinv[t] - s) mod n)
```

Покрытие: исчерпывающе все pi при 4 <= n <= 12 (соответствует диапазону
сертифицированных таблиц C2v, хотя таблицы здесь не используются, так как
H13-I — утверждение только про I(pi), не про d(pi)). n = 13
(6 227 020 800 перестановок) запущен отдельно после оценки времени по
меньшим n (rule 10): экстраполяция `t(n+1) ~= t(n) * (n+1) * ((n+1)/n)^2`
дала n=11: 0.29с*11*1.21≈4с (факт 3.7с), n=12: 3.7с*12*1.19≈53с (факт 45.5с) —
модель подтвердилась перед следующим шагом; память O(n) на перестановку (без
таблиц), детерминированный перебор, время << 1 сессии, чекпоинт не нужен.

Время (один процесс, без параллелизма): n = 4..10 — до 0.3 с; n = 11 — 3.7 с;
n = 12 — 45.5 с; n = 13 — 687.0 с (~11.5 мин, фоновый прогон, лог —
`n13_full_histogram.txt`), что почти точно совпало с оценкой по модели
(690 с) перед запуском.

При каждом n число входов, достигающих максимума, равно ровно n — это в
точности n отражений `pi_h(i) = h - i mod n` (тот же факт, что при
4 <= n <= 10 в `line_profile`; последний перед переходом к следующему n вход
в лексикографическом порядке — обращение `[n-1,...,1,0]`, ранг `n!-1`, что и
видно по `argmax_rank`). Полные гистограммы `I -> count(pi)` — в
`raw_n4_12.jsonl`; при 4 <= n <= 10 распределения совпадают по счётным
столбцам с `data/runs/line_profile/profile_n{n}.json` (`by_I`, поле
`count`). Независимая проверка самого алгоритма (не только совпадение чисел):
`experiments/circle_sort_equivalence.py` считает ту же величину I(pi)
совсем другим (BFS-брутфорс) кодом при n <= 7 — 0 расхождений; отдельно
`docs/notes/h13_line_model.md` §7 приводит брутфорс-проверку обеих формул
рекуррентности и точной формулы пары `f(a,b) = n(a+b) - 2ab` на 5912
перестановках, 2 <= n <= 7.

## Вывод

H13-I (`I(pi) <= floor((n-1)^2/4)` для всех pi) подтверждена исчерпывающе при
**4 <= n <= 13** (расширение диапазона C33 с n <= 10; n = 13 — 6 227 020 800
перестановок за 687 с в фоне, оценка стоимости подтвердилась перед запуском);
экстремумы — ровно n отражений при каждом n, без исключений. Общий случай
(все n >= 4) остаётся CONJECTURED — вердикт сессии 9:
`docs/notes/h13_line_model.md` §7.

n = 14 не запускался: экстраполяция `687с * 14 * (14/13)^2 ≈ 3.1 часа` — вне
разумного бюджета для ещё одной точки диапазона, когда n = 13 уже строго
превышает диапазон таблиц C2v (n <= 12) и качественная картина (экстремум
точно на n отражениях, без исключений) не менялась ни разу от n = 4 до 13;
решение — не запускать «просто следующую строку» без нового вопроса,
который такой прогон мог бы решить (rule 10).
