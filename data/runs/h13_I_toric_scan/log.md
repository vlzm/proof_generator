# h13_I_toric_scan — исчерпывающая проверка H13-I при 4 <= n <= 13

Сессия 9 (15.09.2026). Цель: расширить исчерпывающую проверку `I(pi) <=
floor((n-1)^2/4)` для всех pi (H13-I, `docs/notes/h13_line_model.md`) с
`4 <= n <= 10` (сессия 8, `experiments/line_profile.c`, `O(n^4)` на pi) до
максимально доступного n за бюджет одной сессии.

## Команда и воспроизведение

```
gcc -O3 -o toric_I_fast experiments/toric_I_fast.c
for n in 4 5 6 7 8 9 10 11 12; do ./toric_I_fast $n; done
./toric_I_fast 13 progress   # ~19 минут, прогресс в stderr каждые 5M рангов
```

Версия: `toric_I_fast-1.0` (`experiments/toric_I_fast.c`). Ядро не
используется напрямую (комбинаторный подсчёт инверсий, не BFS оракула), но
формула проверена независимым `O(n^4)` перебором (`checks/check_C37.py`
часть A). Seed: не применимо (исчерпывающий перебор, не случайная выборка).
Машина: контейнер сессии, один поток.

## Покрытие

Исчерпывающее: все `n!` перестановок для каждого `4 <= n <= 13`, для каждой
— минимум `inv` по всем `n^2` двойным разрезам `(q,c)` (точный подсчёт через
`O(n^2)`-рекурсию, не выборка). Полное число проверенных пар
(перестановка, разрез) при n = 13: `6227020800 * 169 ≈ 1.05 * 10^12`.

**Ни одного нарушения при 4 <= n <= 13.** Максимум `I(pi)` всегда точно
равен `floor((n-1)^2/4)` и достигается ровно на перестановках вида
«элемент 0 неподвижен, остальные n-1 развёрнуты» (лексикографически первая
из n поворотов sigma_n = «-i mod n»), что согласуется с сессиями 7-8
(экстремаль — sigma_n и её n поворотов).

Это заменяет и расширяет строку C33/сессии 8 (там — только `4 <= n <= 10`,
метод `O(n^4)`): числа при `4 <= n <= 10` совпадают с прежним результатом
(`data/runs/line_profile/report.md`), что служит кросс-проверкой нового
алгоритма отдельно от `checks/check_C37.py` части A.

## Выборки при больших n (n = 20, 50, 100, 101)

Выполнены в `checks/check_C37.py` часть B2 (не требуют отдельного C-запуска,
`O(n^2)` тривиально в Python на этих размерах): 1307 структурных и
случайных входов, 0 нарушений; `sigma_n` и её повороты точно достигают
`floor((n-1)^2/4)`. Подробности и список семейств — заголовок части B2 в
`checks/check_C37.py` и `docs/notes/h13_I_attempt_2026-09-15.md` §3.

## Вывод и следующий вопрос

Данные не опровергают H13-I ни разу вплоть до n = 13 (перебор всех `13!`
перестановок) и остаются согласованными с гипотезой при больших n
(структурные и случайные образцы n = 20..101). Доказательства это не
заменяет (правило 5 реестра: конечный перебор не доказывает общий случай).
Следующий вопрос — не вычислительный: нужен либо содержательный
комбинаторный аргумент (см. попытки в `docs/notes/h13_I_attempt_2026-09-15.md`
§4), либо перенос конструкции из независимой литературы (§5 той же
заметки, доступ заблокирован в этой сессии). n = 14 (`14! ≈ 8.7*10^10`,
оценка по времени линейным масштабированием — ~13 * 1114с ≈ 4 часа) — не
запускать без отдельного обоснования бюджета (правило 10): сама по себе
очередная n не даст нового аргумента, только ещё один пункт данных.
