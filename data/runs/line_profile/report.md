# line_profile — профиль `I(pi)` против `d(pi)` (H13, сессия 8)

Цель: для всех pi при 4 <= n <= 10 сопоставить `I(pi) = min_{q,c} inv`
(двойной разрез: ребро позиций q и сдвиг c, см. `experiments/line_model.py`)
с точным `d(pi)` из сертифицированных таблиц (C2v). Ответить: какой вид
имеет наилучшая оценка `d <= f(I, n)`, и достижима ли форма `2·I + g(n)`
с `g(n) <= floor(n/2) + O(1)` из PLAN §8.

Версии: line_profile-1.0 (`experiments/line_profile.c`, C), ядро oracle-1.0,
таблицы C2v. Команда: `gcc -O2 -o line_profile experiments/line_profile.c &&
./line_profile n data/tables/dist_n{n}.bin [I_n{n}.bin]`. Исчерпывающе по всем
pi (перебор в порядке кода Лемера, как в таблицах), все n^2 разрезов.
Время: n = 9 — 6 с, n = 10 — 93 с. Выход: `profile_n{n}.json` (по каждому I:
число входов, max d, min d, первый argmax; по каждому d: max/min I;
совместная гистограмма (I, d)); файлы `I_n{n}.bin` (байт на pi) не в git —
воспроизводятся командой выше.

## Главное

| n | B_n | max I (floor((n−1)^2/4)) | max (d − I) (floor(n^2/4)) | max (d − 2I) | где достигается max (d − 2I) |
|---|---|---|---|---|---|
| 4 | 6 | 2 (2) | 4 (4) | 3 | (0,1,3,2) |
| 5 | 10 | 4 (4) | 6 (6) | 3 | (0,1,2,4,3) |
| 6 | 15 | 6 (6) | 9 (9) | 5 | (0,1,2,4,3,5) |
| 7 | 21 | 9 (9) | 12 (12) | 6 | (0,1,2,5,6,3,4) |
| 8 | 28 | 12 (12) | 16 (16) | 8 | (0,1,2,5,6,3,4,7) |
| 9 | 36 | 16 (16) | 20 (20) | 10 | (0,1,2,5,7,8,3,4,6) |
| 10 | 45 | 20 (20) | 25 (25) | 13 | (0,1,2,6,7,8,3,4,5,9) |

1. `d(pi) <= I(pi) + floor(n^2/4)` для всех pi при 4 <= n <= 10, с равенством
   на sigma_n и на его соседях `sigma_n X` (I = max − 1), и вообще тесно:
   `max_{I} d − I` равно `floor(n^2/4)` при I >= max − 1 и `floor(n^2/4) − 1`
   при примерно n <= I <= max − 2 (например n = 9: I = 9..14 дают 28..33 =
   I + 19). То есть бюджет вращений ≈ n^2/4 нужен не только отражениям.
2. Форма `2·I + g(n)` требует `g(n) >= max(d − 2I)` = 3, 3, 5, 6, 8, 10, 13:
   не меньше n − 1 (антиподальная транспозиция, лемма B заметки) и растёт
   быстрее n (обмен двух блоков длины k у антипода: n = 10, k = 3 даёт
   d − 2I = 13 = n + 3). Критерий PLAN §8 (`g(n) <= floor(n/2) + O(1)`)
   недостижим ни при каком n >= 4.
3. При малых I максимум d ведёт себя как `2I + n + O(1)` (n = 10: I = 1..9 —
   11, 13, 15, 18, 20, 23, 25, 28, 31); при больших I работает потолок
   `I + floor(n^2/4)`.
4. Число входов с `I >= floor((n−1)^2/4) − floor(n/4)` (там мал запас на
   вращения при любой схеме со «слопом 2»): n = 8: 368 (I >= 10), n = 9: 513
   (I >= 14), n = 10: 660 (I >= 18) — отражения (I = max, n штук), отражения с
   одной соседней транспозицией (I = max − 1, n^2 штук) и их дальнейшие
   локальные возмущения. Они не являются «конечным числом семейств» в смысле
   PLAN §8 п. (3): при том же I = max − 2 уже 550 входов при n = 10.

Полные таблицы по I — в `profile_n{n}.json`; числа `max(d − 2I)` и
`max(d − I)` перечитывает `checks/check_C34.py` (часть C).
