# horizon_eval — политика головы «горизонт» (H12, шаг 1)

Цель: проверить единую политику головы `mode="horizon"` кандидата
`constructions/candidate_sweep.py` (sweep-1.2: режим; sweep-1.3: флаг фолбэка
`fallback` при тупике, при `fallback=False` поведение sweep-1.2 воспроизводится
буквально) против таблиц C2v, B_n и N1_R (`strict_upper.py`, маршрут по
переносчикам, минимум по c). Версии: horizon_eval-1.0/1.1, sweep-1.2/1.3,
strict_upper-1.0, oracle-1.0. Seed 1 для случайных выборок. Все слова исполнены
эталонными ходами внутри `sweep_word`. Память незначительна (< 200 МБ на процесс).

Параметры политики: глубина H = 3, вес остатка w = 0.5 (главный вариант),
w = 1 (сравнение), thr в {1, 2}, минимум по c и dir — 4n слов на вход.

`len − B_n = −g(h)`, g = delta(h, 1) при delta <= n/4 + O(1), затем g убывает
до 2 на антиподе h = n/2 + 1 (n = 60: минимум −16 при h = 17, 45; −2 при h = 31).

## Тупики фиксированного сдвига (sweep-1.2 без фолбэка)

Пар (pi, c), где все четыре (dir, thr) заканчиваются `ConstructionError`
(нет ребра с `gain >= 1`): 2508 / 4320 (n = 6), 18 368 / 35 280 (n = 7),
197 608 / 322 560 (n = 8; тупиковый c есть у каждой pi). С фолбэком
(флаг длинной дуги у элемента с наибольшим |rem|) тупиков нет (0 / 35 280
при n = 7), минимум по c тот же на всех pi при 4 <= n <= 8; фиксированный
плохой c даёт до B_n + 19 при n = 6, 7.

## Вывод

Политика «горизонт» (H = 3, w = 0.5, минимум по c, dir, thr) даёт `<= B_n`
на всех pi при 4 <= n <= 9 (равенство только на sigma_n при n = 4, 5, 7, 8, 9;
при n = 6 ещё два входа), на всех отражениях при n <= 20 и n в
{24, 30, 40, 50, 60} (равенство только на sigma_n), на аффинных и случайных
входах — с запасом, растущим с n. Критерий шага (1) H12 выполнен без
портфеля с N1_R. Число обменов на отражениях — ровно расщепление
геодезических sigma_n; потеря `len − d` при n = 9 не выше 8, на 45 % входов 0.
Ограничение: при фиксированном c политика тупикова более чем на половине
пар (pi, c); формула длины при выбранном c — задача шага (2).
