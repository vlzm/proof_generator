# frontier_eval — оценка кандидата «frontier» (weighted), H12 шаг 1

Дата: 13-14.09.2026 (сессия 6). Цель: PLAN.md H12 (`docs/notes/geodesic_structure.md`
§5) — найти единую политику головы без портфеля, дающую `<= B_n` на всех pi при
4 <= n <= 9 исчерпывающе и на отражениях/аффинных при n <= 60.

Ядро oracle-1.0. Конструкция `constructions/candidate_frontier.py`
(CANDIDATE_VERSION `frontier-1.1`), режим `weighted` (`weighted_word`/`best_weighted`):
направление выбирается по `score = gain - tw*distance` в ближайшем продуктивном
ребре по каждую сторону головы (tw = 1.0 фиксирован); `best_weighted` — минимум
длины по сдвигу c (0..n-1), thr in {1, 2}, tie_pref in {+1, -1}, init_dir in {+1, -1}.
Слова исполнены и сверены с эталоном (`oracle/moves.apply_word`) в каждом вызове.
Второй режим модуля, `farthest`/`frontier_word`, эмпирически совпадает с
`sweep-1.1` nearest на всех проверенных случаях (не используется `best_weighted`,
сохранён для отчёта, см. докстринг `candidate_frontier.py`).

Скрипт `experiments/frontier_eval.py` (VERSION `frontier_eval-1.0`) — та же
структура, что `experiments/sweep_eval.py`, плюс сравнение с N1 (`strict_upper-1.0`,
carrier-route) и `sweep-1.1` рядом.

## Команды и покрытие

1. Исчерпывающая проверка по всем pi, 4 <= n <= 9, со сверкой с сертифицированными
   таблицами `data/tables/dist_n{4..12}.bin` (для len - d):

   ```
   python3 experiments/frontier_eval.py --perms 9 --workers 4
   ```

   seed не используется (эта часть без выборок); версии — см. meta ниже;
   362 880 перестановок при n = 9, 1751 с (4 процесса).
   Результат: `report_perms9_fam0.json`.

2. Семейства n = 4..60 (без повторного исчерпывающего перебора, `--perms 4`
   пропускает шаг 1):

   ```
   python3 experiments/frontier_eval.py --perms 4 --families 60 --samples 30 --seed 1
   ```

   4961 с (однопоточно). Результат: `report_perms4_fam60.json`, сырой стдаут —
   `families_run.out`.

   Покрытие внутри семейств (явно, по правилу 9 AGENTS.md):
   - отражения: все h при 4 <= n <= 40; при 41 <= n <= 60 — 10 значений h
     (0, 1, 2, 3, окрестности n/4 и n/2, n-3..n-1 — конкретный список в каждой
     строке JSON/report.log, поле `reflections_h_coverage`), не исчерпывающе;
   - sigma_n, rev_n: точное значение (по одному входу на n), все n = 4..60;
   - аффинные `pi(i) = a*i+b`: все взаимно простые с n значения a и все b при
     4 <= n <= 20; все a и b in {0, 1, n//2, n-1} при 21 <= n <= 40; 8
     выбранных a (равномерно по диапазону, все coprime(a, n)) и b in {0, 1,
     n//2, n-1} при 41 <= n <= 60 (поле `affine_a_coverage` в каждой строке) —
     не исчерпывающе для n >= 41;
   - повороты sigma_n: все k при n <= 40, 5 значений k при n >= 41 (поле
     `rotations_sigma_coverage`);
   - случайные перестановки: 30 на каждое n (seed = 1), не исчерпывающе.

   Примечание к воспроизведению: сессия 6 запускала этот скрипт трижды из-за
   параллельных фоновых процессов и перезапуска контейнера в середине работы;
   `report.log` в этой папке — накопленный лог со смешанными строками от разных
   попыток (в т.ч. одна с `--samples 5/10`, старее и с другими числами по
   `random_max`, и позже перезаписанные тем же n при повторном запуске).
   Канонический, единственный полный и непрерывный прогон семейств —
   `families_run.out` + `report_perms4_fam60.json` (второй скрипт выше, seed 1,
   samples 30, завершился без ошибок, "families total 4961 s"). Использовать
   для цитирования только эти два файла и `report_perms9_fam0.json`.

## Результат

Шаг 1 (4 <= n <= 9, исчерпывающе): максимум `len - B_n` по всем перестановкам
равен **0** при каждом n = 4..9 (единственный вход на каждое n достигает
равенства, остальные строго меньше B_n); ни одного превышения. `len - d`
(потеря против точного расстояния) растёт до +7 при n = 9 — конструкция не
геодезическая, но это здесь не требуется. Время (1 процесс/4 процесса):
n=4..8 доли секунды — 133 с, n=9 — 1751 с.

Семейства (4 <= n <= 60): во всех категориях `best_weighted(pi) - B_n <= 0`
без единого исключения:

| n | отражения (max) | sigma_n | rev_n | аффинные без отражений (max) | повороты sigma_n (max) | случайные 30 (max) |
|---|---|---|---|---|---|---|
| 4 | 0 | 0 | -2 | None | 0 | -1 |
| 9 | 0 | 0 | -2 | -6 | 0 | -4 |
| 18 | 0 | 0 | -2 | -22 | 0 | -24 |
| 20 | 0 | 0 | -2 | -16 | 0 | -28 |
| 40 | 0 | 0 | -2 | -60 | 0 | -132 |
| 60 | 0 | 0 | -2 | -182 | 0 | -261 |

(полные строки n = 4..60 — `report_perms4_fam60.json` и `families_run.out`).
Отражения и sigma_n достигают ровно B_n (совпадает с N1, C28/C9); rev_n и
аффинные — строго меньше B_n с растущим запасом; случайные перестановки —
с большим запасом, растущим по модулю быстрее n.

## Вывод

H12, шаг 1 (`docs/notes/h12_verdict.md`): критерий выполнен на всём проверенном
диапазоне — единая политика головы (`best_weighted`, без портфеля с N1 или
sweep) даёт `<= B_n`. Статус — CONJECTURED (конечные данные, не доказательство
для общего n): CLAIMS.md, новая строка.
