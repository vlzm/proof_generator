# toric_inv — исчерпывающая проверка H13-I при 4 <= n <= 13 (сессия 9)

Цель: проверить `I(pi) = min_{q,c} inv(w) <= floor((n − 1)^2/4)` (H13-I) для
всех перестановок при n до 13 и выяснить, кто экстремален.

Код: `experiments/toric_inv.c` (toric_inv-1.0, C). Ядро ходов LRX не
используется: величина `I(pi)` чисто комбинаторная (число инверсий
переразмеченной линии, `docs/notes/h13_line_model.md` §0).

Команда:

```text
gcc -O2 -o toric_inv experiments/toric_inv.c
./toric_inv n --dump-extremal 2  > data/runs/toric_inv/toric_inv_n{n}.json
./toric_inv n --full             (перебор всех n!, сверка сокращения)
```

Параметры: seed не используется (детерминированный перебор).
Покрытие: исчерпывающее по торическим классам. `I(pi)` — торический инвариант
(разрезы просто сдвигаются), поэтому перебираются `(n − 1)!` представителей
с `pi(0) = 0`; каждый класс содержит хотя бы одного такого представителя.
Сверка сокращения: `--full` при n = 5, 6, 7 даёт тот же `max I` и ровно n
экстремальных перестановок — n отражений (совпадает с C33).

Ускорение: вся сетка `F(a, b)` считается за `O(n^2)` по двум рекуррентам
(лемма 1 в `docs/proofs/C37_toric_cut_identity.md`) вместо `O(n^4)`
переразметок (`experiments/line_profile.c`). Рекурренты сверены с прямым
пересчётом всех линий в `checks/check_C37.py` (часть A, все pi при n <= 7)
и в `experiments/toric_spearman.py`.

Память: O(n^2) (одна строка сетки), < 1 МБ. Контрпримеров нет.

Экстремальный представитель при каждом n единственный: `pi(i) = −i mod n`,
то есть класс отражений (в полном переборе — ровно n отражений `pi_h`).
Гистограммы `I` — в `toric_inv_n{n}.json` (поле `hist_I`).

Вывод: **H13-I VERIFIED при 4 <= n <= 13** (было 4 <= n <= 10, C33), максимум
достигается только на отражениях. n = 14 стоил бы ~30 мин (13! · 14^2), n = 15
~8 ч — запускать только под конкретный вопрос (правило 10).
