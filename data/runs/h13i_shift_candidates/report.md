# H13-I: restricted position-rotation candidates — negative result

Дата: 14.09.2026 (сессия 9). Задача из PLAN §8 / `docs/notes/h13_line_model.md`
§6: доказать H13-I (`I(pi) <= floor((n-1)^2/4)` для всех pi, где
`I(pi) = min_{q,c} inv(w)` по n^2 двойным разрезам). Цель этого эксперимента —
проверить, не сводится ли задача к перебору по МАЛОМУ (n-независимому или
медленно растущему) множеству кандидатов позиционного сдвига r, оставляя
значение c(=s) свободным по всем n вариантам — что дало бы прямой путь
к доказательству.

Код: `experiments/h13i_shift_candidates.py` (h13i_shift_candidates-1.0).
Ядро не используется (чистая комбинаторика перестановок, не LRX-ходы);
версия зафиксирована в `env.txt` (git HEAD на момент прогона).

## Команды и результаты

### 1. `exhaustive-r0` — r = 0 фиксировано, s свободно (n вариантов вместо n^2)

```
python3 experiments/h13i_shift_candidates.py exhaustive-r0 --nmin 4 --nmax 9
```

Покрытие: исчерпывающее по всем pi при 4 <= n <= 9 (n = 9: 362 880 перестановок,
12.85 с). Результат (`r0.jsonl`): при n <= 6 совпадает с границей; начиная
с n = 7 превышает границу на 1 (7, 16, 162 входа с превышением при n = 7, 8, 9).
Худший вход при n = 7: `(0,5,4,3,2,1,6)` — тот же пример, что и контрпример
к лемме C в `docs/notes/h13_line_model.md` §4 (локальные условия
недостаточны). Семейство `(0, n-2, n-3, ..., 1, n-1)` даёт избыток ровно +1
при всех проверенных 7 <= n <= 15 (не растёт для этого конкретного семейства).

Вывод: без свободы по r единственный сдвиг c не достигает границы уже
при n = 7 — подтверждает (независимо от Lemma C), что обе степени свободы
нужны в общем случае.

### 2. `exhaustive-diag` — r = i0, s = pi(i0), минимум по i0 (разрез через
точку перестановки, n вариантов)

```
python3 experiments/h13i_shift_candidates.py exhaustive-diag --nmin 4 --nmax 8
```

Покрытие: исчерпывающее 4 <= n <= 8. Результат (`diag.jsonl`): избыток растёт
быстро — 1, 2, 4, 6, 9 при n = 4..8 (худший вход — обращение с неподвижной
точкой 0: `(0, n-1, n-2, ..., 1)`). Эвристика «разрез через диагональ»
значительно хуже, чем даже r = 0 фиксированное; отброшена.

### 3. `exhaustive-rset` — r ∈ {0, 1}, s свободно (2n вариантов вместо n^2)

```
python3 experiments/h13i_shift_candidates.py exhaustive-rset --rset 0,1 --nmin 4 --nmax 9
```

Покрытие: исчерпывающее 4 <= n <= 9 (n = 9: 27.2 с). Результат (`rset01.jsonl`):
**нулевое превышение границы при всех 4 <= n <= 9** — множества всего двух
соседних r достаточно на этом диапазоне. Заманчивый кандидат на общее
доказательство (2n вместо n^2 разрезов), но недостаточен — см. следующий пункт.

### 4. `local-search-rset` — {0,1} на больших n (эвристический поиск худшего входа)

```
for n in 10 15 20 25 30; do
  python3 experiments/h13i_shift_candidates.py local-search-rset --rset 0,1 \
    --nmin $n --nmax $n --iters 2500 --restarts 5 --seed 2
done
```

Покрытие: не исчерпывающее — hill-climbing (обмен пары позиций, принимается
любой ход, не уменьшающий текущий счёт; 5 случайных стартов, seed = 2,
2500 итераций на старт). Результат (`local_search_rset01.jsonl`, нижняя
оценка истинного максимума, не сертификат): избыток над границей найден
растущим — 1 (n=10), 0 (n=15, не найден локальным поиском при этой
конфигурации), 1 (n=20), 4 (n=25), 7 (n=30). Немонотонность по n —
артефакт ограниченного локального поиска (не полный перебор), но сам факт
роста избытка при n = 25, 30 опровергает достаточность фиксированного
двухэлементного {0,1} в общем случае.

## Вывод

Ни один из проверенных способов сократить перебор по r до малого
(n-независимого или использующего структуру pi через одну точку) множества
не работает в общем случае:

- r = 0 фиксировано: недостаточно уже при n = 7 (избыток +1, растёт по числу
  затронутых входов, но не по величине избытка в проверенных семействах).
- диагональный разрез (r = i0, s = pi(i0)): недостаточно, избыток растёт
  быстро с n (не путь к доказательству).
- r ∈ {0, 1}: точно на границе при 4 <= n <= 9 (совпадает с исчерпывающим
  I(pi) <= floor((n-1)^2/4) для всех pi на этом диапазоне), но эвристический
  локальный поиск находит нарушения при n = 25, 30 — двух кандидатов
  недостаточно асимптотически.

Побочная переформулировка (не даёт нового доказательства, но фиксирует
структуру для будущей сессии): при фиксированном r ряд `inv(s)` как функция
s — циклическое блуждание `inv(s+1) - inv(s) = n - 1 - 2*p_s`, где
`p_s = позиция значения s в r-сдвинутой строке`; шаги образуют перестановку
фиксированного симметричного множества `{n-1, n-3, ..., -(n-1)}`, но порядок
шагов (а значит и min_s inv(s)) зависит от pi производно и не сводится к
классической лемме о цикле (шаги нельзя переставлять свободно — их порядок
и есть pi).

Задача H13-I остаётся открытой; общего доказательства не найдено за эту
сессию. Следующий шаг по плану (`docs/notes/h13_line_model.md` §6,
PLAN §8) — переход к индукции H3 (§4.3, п. 3) как основному направлению;
H13-I остаётся зарегистрированной гипотезой (C33) с этими отрицательными
результатами как ориентиром для возможной будущей попытки (data-dependent
выбор r, а не фиксированное множество).

Артефакты: `r0.jsonl`, `diag.jsonl`, `rset01.jsonl`, `local_search_rset01.jsonl`,
`env.txt` (версия ядра/HEAD), этот отчёт.
