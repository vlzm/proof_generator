# h13i_negative_results — H13-I: две дополнительные отвергнутые схемы

Цель (задача сессии из `docs/notes/repo_state.md`): доказать H13-I
(`I(pi) <= floor((n-1)^2/4)` для всех pi, торические классы, см.
`docs/notes/h13_line_model.md` §6) за бюджет 1 сессия. Проверены два
кандидата, оба указаны в §6 как возможные направления или естественные
усиления уже отвергнутых подходов.

Версии: `h13i_negative_results-1.0` (C, тест A и тест B, точная арифметика,
без зависимости от `oracle/moves.py` — I(pi) чисто комбинаторная величина,
как и в `experiments/line_profile.c`), `h13i_affine_growth-1.0` (Python,
рост зазора теста B на аффинном семействе). Команды:

```
gcc -O2 -o h13i_negative_results experiments/h13i_negative_results.c
./h13i_negative_results 9
python3 experiments/h13i_affine_growth.py --nmin 8 --nmax 16
```

Покрытие: тест A и тест B — исчерпывающе все pi при 4 <= n <= 9 (правило 9
AGENTS.md, лестница 4..8 плюс 9 — дёшево, 10 с на n = 9); рост зазора теста B
на аффинном семействе `pi(i) = a*i+b mod n`, все (a, b) с gcd(a, n) = 1, при
8 <= n <= 16 (SAMPLED — не весь S_n, только семейство). Время: `h13i_negative_results 9`
— 9.6 с; `h13i_affine_growth.py --nmax 16` — 57 с. Память — не измерялась
отдельно, все структуры малы (таблицы I для приведённых перестановок размера
<= 7: 5040 байт).

## Тест A — «одного вращения (значений) достаточно, вращение позиций не нужно»

Фиксируем чтение pi в исходном порядке (s = 0, ребро разреза {n-1, 0}) и
минимизируем `inv` только по сдвигу значений c: `I_fixed(pi) = min_c inv`.
Вопрос: верно ли `I_fixed(pi) <= floor((n-1)^2/4)` для всех pi (тогда поиск
по обоим вращениям был бы не нужен для самой оценки, хотя мог бы понадобиться
для H13-R)?

**FALSE, начиная с n = 7** (при 4 <= n <= 6 нарушений нет — `testA_fails = 0`).
Первый контрпример: `(0,5,4,3,2,1,6)` при n = 7 даёт `I_fixed = 13 > 9 =
floor(6^2/4)` (при этом полный `I(pi) = 8` — вращение позиций необходимо;
этот вход уже фигурировал в лемме C заметки §4 как контрпример к локальным
условиям оптимальности разреза, но не был проверен как контрпример к тесту A
явно). Число нарушений: 0, 0, 0, 7, 16, 162 при n = 4..9; максимальный зазор
`I_fixed - floor((n-1)^2/4)` равен 0, 0, 0, 1, 1, 1 — растёт медленно, но не
равен нулю: обе степени свободы (s и t) нужны одновременно, ни одна не
сводится к перебору по другой. Данные: `exhaustive_n4_9.json`, поле `testA_*`.

## Тест B — индукция с удалением пары элементов (обобщение §1.7 на k = 2)

`docs/notes/h13_line_model.md` §1.7 показала, что индукция по ОДНОМУ элементу
не проходит (контрпример n = 8). Естественное усиление: удалять ДВЕ позиции
{p, r} сразу (сжатие: удалить позиции p, r и значения pi(p), pi(r),
перенумеровать оставшиеся позиции и значения 0..n-3 с сохранением порядка),
получить pi' размера n-2, и потребовать
`I(pi) - min_{p,r} I(pi') <= floor((n-1)^2/4) - floor((n-3)^2/4) =: budget(n)`
(вдвое больший бюджет на шаг индукции, чем при одном элементе).

**FALSE, начиная с n = 8, и зазор растёт с n, а не является артефактом
малых n.** Исчерпывающая проверка (все pi, все C(n,2) пар {p,r}, все
4 <= n <= 9): `budget(n)` = 4, 5, 6, 7 при n = 6..9; максимум нужного
`I(pi) - best_reduced` = 4, 5, 7, 8 — зазор (needed - budget) = 0, 0, 1, 1;
число нарушающих pi = 0, 0, 16, 1908 (`exhaustive_n4_9.json`, поле `testB_*`).
Худший вход при n = 9 — `(0,1,6,3,8,5,2,7,4)`.

Проверка на аффинном семействе `pi(i) = a*i+b mod n` при 8 <= n <= 16
(`affine_growth.json`) показывает, что зазор НЕ ограничен и растёт с n:

| n | budget | худший needed | зазор | худшая (a,b) |
|---|---|---|---|---|
| 8 | 6 | 7 | 1 | (3, 0) |
| 9 | 7 | 8 | 1 | (4, 0) |
| 10 | 8 | 9 | 1 | (3, 0) |
| 11 | 9 | 12 | 3 | (7, 0) |
| 12 | 10 | 14 | 4 | (7, 0) |
| 13 | 11 | 15 | 4 | (5, 0) |
| 14 | 12 | 17 | 5 | (9, 0) |
| 15 | 13 | 19 | 6 | (11, 0) |
| 16 | 14 | 19 | 5 | (5, 0) |

Зазор растёт примерно как n/3 (не убывает, не выходит на плато при
n <= 16); наибольшие худшие входы — все с b = 0 (чисто мультипликативные
`pi(i) = a*i mod n`), a варьируется без явного паттерна кратного n
(3, 4, 3, 7, 7, 5, 9, 11, 5) — не сводится к малому конечному набору a.
Прогон при n <= 24 запущен и остановлен на n = 18 по правилу 10 AGENTS.md
(измеренная скорость деградирует быстрее, чем полиномиально: O(n) значений
a x O(n) значений b x O(n^2) пар для сжатия x O(n^4) на вычисление I —
итого ~O(n^8); n = 16 уже 57 с, n = 24 экстраполируется в часы) — тренд
роста зазора при n <= 16 уже достаточен для вывода, дальнейшие точки не
меняют ответа.

## Вывод

Обе схемы, которые сократили бы перебор двух вращений (s, t) до перебора
одного, или свели бы H13-I к индукции с O(1) удаляемыми элементами,
опровергнуты — причём тест B хуже, чем предыдущая (одноэлементная) неудача:
там был единственный известный контрпример при конкретном n, а здесь зазор
`needed - budget` растёт с n на явном семействе. Это говорит, что удаление
ЛЮБОГО фиксированного малого числа элементов не может быть механизмом
индуктивного доказательства H13-I (аффинные/мультипликативные входы
`a*i mod n` сохраняют структуру, которая резистентна к локальным сокращениям
любого фиксированного размера k — согласуется с наблюдением §1.7 о том, что
это семейство уже опровергало k = 1).

Следствие для дальнейшей работы (PLAN §4.3, п. 3, индукция H3): если H3
использует индукцию по удалению элементов размера n - (n-1) = 1 или
аналогичного вида, стоит ожидать того же препятствия на мультипликативных
входах, если она устроена как «удалить кусок, применить ту же оценку
рекурсивно с локальным бюджетом на шаг». Возможный обходной путь — бюджет
на шаг, зависящий от n (не константа и не малая степень), или индукция
не по элементам, а по структуре (например по делителям n, используя
мультипликативную природу худших примеров).

## Что дальше

H13-I не доказана за отведённый бюджет (1 сессия, включая предыдущую
сессию 8 и эту). Вердикт сессии — переход к H3 (PLAN §4.3, п. 3) как
основному следующему направлению, с явным предупреждением из этого отчёта:
не пробовать вариант «удалить O(1) элементов, единый бюджет на шаг» без
изменения схемы — он уже опровергнут дважды (k = 1 и k = 2) с растущим
зазором. Артефакты: `experiments/h13i_negative_results.c`,
`experiments/h13i_affine_growth.py`, `exhaustive_n4_9.json`,
`affine_growth.json` (этот каталог).
