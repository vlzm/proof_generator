# line_toric_scan — исчерпывающая проверка H13-I по торическим классам

Цель: расширить диапазон конечной проверки H13-I (`I(pi) <= floor((n−1)^2/4)`)
за n = 10 и проверить, только ли отражения дают максимум. `I(pi)` — минимум
числа инверсий линии по всем n^2 двойным разрезам (`docs/notes/h13_line_model.md`
§0).

Версия: line_toric_scan-1.1 (`experiments/line_toric_scan.c`, C; 1.0 — тот же
перебор без счётчиков H13-S). Ядро oracle-1.0
не используется: слова здесь не строятся, проверяется чисто комбинаторная
величина. Таблицы расстояний не нужны.

Команда:

```text
gcc -O2 -o line_toric_scan experiments/line_toric_scan.c
./line_toric_scan n > data/runs/line_toric_scan/scan_n{n}.json
```

Покрытие: исчерпывающее по торическим классам. `I` постоянна на торическом
классе (повороты позиций и значений), и каждый класс содержит линию с `w_0 = 0`,
поэтому достаточно перебрать `(n−1)!` представителей вместо `n!` — экономия
в n раз. Для каждого представителя строится вся сетка `n^2` разрезов
пересчётом за O(1) на шаг:

```text
inv(a, b+1) = inv(a, b) + (n − 1 − 2p),  p — позиция значения b в линии (a, b);
inv(a+1, 0) = inv(a, 0) + (n − 1 − 2 w_a).
```

Память: O(n). Детерминированный перебор, seed не нужен.

Контрпримеров нет: `max_pi I(pi) = floor((n−1)^2/4)` при 4 <= n <= 13.
Максимум достигается ровно на одном торическом классе — классе отражений
(его представитель с `w_0 = 0` — это `(0, n−1, n−2, ..., 1)`). Что отражения
дают ровно `floor((n−1)^2/4)` при всех n, доказано (лемма 6
`docs/proofs/C37_toric_mean_bound.md`); конечная часть здесь — что больше
никто не даёт столько же и больше.

Побочное наблюдение (не проверялось на больших n): на уровне `max − 1` ровно
n классов при 9 <= n <= 13.

## Гипотеза H13-S в том же переборе (версия 1.1)

Тот же проход считает правило C39: среди разрезов, максимизирующих
`sum_j j·w_j` (то есть минимизирующих расстояние Спирмена `sum_j (w_j − j)^2`),
берётся наибольшее число инверсий; слабая форма требует, чтобы оно не
превосходило `floor((n−1)^2/4)`, сильная — чтобы оно равнялось `I(pi)`.
Счётчики `H13S_weak_failures` и `H13S_strong_failures` в `scan_n{n}.json`
равны нулю при 4 <= n <= 12 (все торические классы; обе величины постоянны на
классе, поэтому перебор представителей исчерпывающ). Независимая проверка
вторым кодом — `experiments/line_cut_rules.py`
(`data/runs/line_cut_rules/report.md`).

Время (один поток): n = 12 — 10.3 с, n = 13 — около 2 мин; рост примерно в n
раз на каждый шаг n -> n + 1.

## Вывод и следующий вопрос

H13-I конечно подтверждена при 4 <= n <= 13 и остаётся недоказанной в общем
случае (вердикт сессии: `docs/notes/h13i_verdict.md`). Дальнейший перебор даёт
всё меньше: n = 15 стоит уже около 7 часов одного потока, а структура ответа
(единственный экстремальный класс — отражения) стабильна с n = 4. Следующий
вопрос — не n = 15, а доказательство «единственности отражений» (усиление:
если pi не отражение, то `I(pi) <= floor((n−1)^2/4) − 1`) или аффинное
подсемейство (`docs/notes/h13i_verdict.md` §4).
