## 4. Фаза 2. Верхняя оценка

Конечная цель — C15: `D_n <= B_n`. Новая C16 уменьшает линейный коэффициент
до kappa ≈ 1.17225. Улучшение коэффициента, границы с остатком o(n), O(1)
и точная B_n — разные достижения. Каждое регистрируется с собственной
формулой; остаток O(1) сам по себе не завершает C15.

### 4.1. Первый эксперимент: карта потерь N1

Бюджет — 1 сессия после аудита нужных частей конструкции. Использовать
подтверждённое ядро и таблицы; при отсутствии полного BFS можно проверить
слова и внутренние неравенства, но нельзя выдавать `len - B_n` за `len - d(pi)`.

Реализовать точно описанную конструкцию как `constructions/strict_upper.py`
с выбором сдвига по явно заданному правилу. Для каждого pi и каждого c
сохранять реальные слова и статистики из правила 15 AGENTS.md. Разделять:

1. Локальные слова: их фактическая суммарная длина против `2F_c-S_c`.
2. Позиционирование: фактический внешний маршрут против H(c).
3. Выбор сдвига: минимум фактической длины, минимум `2F_c-S_c+H(c)`
   и среднее этого выражения — три разные величины.
4. Оценки s: точное s против правых частей (7.3), (8.1), (8.2), (8.3)
   N1; для каждого перехода — разница и условия равенства.
5. Стыки: длина полного слова до и после дополнительного свободного
   сокращения; N_X и N_rot в обоих случаях. Сокращение не подменяет
   длину того варианта слова, который оценивается на конкретном шаге.

Начать с отражений (включая sigma_n и все её вращения), малых возмущений
отражений и семейства C23; затем все перестановки 4 <= n <= 7, расширение
до n = 8 по бюджету. C24 служит точным контрольным расчётом: на отражениях
даже точное s оставляет в (3.4) остаток порядка n/4. Это направляет поиск
на переход к среднему, стоимость H(c) и сами слова, а не только на §§5–8.

Выход — отчёт `data/runs/strict_loss_audit/` с покрытием, раздельными потерями,
трудными входами и одним выбранным следующим направлением.

Выполнено 12.09.2026 (сессия 3): `constructions/strict_upper.py`,
`experiments/loss_map.py`, отчёт `data/runs/strict_loss_audit/report.md`

(PLAN §0: гипотеза «переход от sigma_(n-1) к sigma_n стоит floor((n-1)/2)
обменов и floor(n/2) шагов головы»), явно расписать, как ходы L/R/X на
массиве длины n имитируют ходы на массиве длины n-1 при наличии
фиксированного (n-1)-го элемента (PLAN §4.3 п. 3: фиксированный элемент
нельзя молча исключать — L и R вращают весь массив),
и явно построить конструкцию для sigma_n длины `T_(n-1) + (n-1)` по
рекурренте (при `T_4 <= 6`, что даёт ровно B_4 = 6). Проверить формулу
исчерпывающе при 4 <= n <= 9 (сверка с таблицами C2v) построением слов и их
исполнением эталоном (не только длины); учесть восстановление ориентации
головы/массива между уровнями рекурсии (запас рекурренты по условию H3 —
нулевой, значит любая лишняя операция ломает точность). Если рекуррента не
даёт точного B_n (а не оценки с запасом) уже на малых n — зафиксировать
контрпример и минимальное n, не подгонять определение вложения под
результат (правило 4 AGENTS.md). Критерий сессии: явная конструкция и её
проверка на 4 <= n <= 9, план второй сессии (общее n или вердикт). Не
повторять: работу с политикой «горизонт»/«развёрткой»/N1 — H3 не зависит от
них и не должна на них ссылаться, кроме сравнения итоговых длин.

Параллельно доступны: аудит S1 (§3.2, C8) и аудит прежнего комплекта
(C1, gap-файл) — входные файлы теперь в `docs/incoming/`; доказательство
H8/C25 (формула длины на sigma_n).

## 9. Спецификации модулей

### 9.1. `oracle/moves.py`

Функции: `apply_move(state, move)`, `apply_word(state, word)` (слева направо),
`freely_reduce(word)` (сокращает XX, LR, RL), `delta(a, b, n)`, `sigma(n)`.
Предусловие: state — перестановка 0..n-1, n >= 2; проверяется на внешней
границе, а не в каждом внутреннем вызове BFS.

Обязательные тесты: пример XL; обратимость L/R; `X^2 = id`; `L^n = id`;
сохранение множества элементов; эквивалентность свободно сокращённого слова
исходному. `oracle/verify_word.py` проверяет алфавит и результат слова.

### 9.2. BFS и таблицы

- n <= 8: BFS от id_n со словарём «кортеж -> расстояние»; n = 9 так же, если
  измеренная память подходит.
- n >= 10: сначала измерить скорость и память на меньшем n; при необходимости
  код Лемера (биекция перестановок и чисел 0..n!-1; проверить взаимную
  обратность и совпадение с простым BFS) и плотный массив расстояний.
- Один байт на расстояние: около 3.6 МБ при n = 10, 40 МБ при n = 11,
  479 МБ при n = 12 — только массив, без очереди. Тип данных содержит отдельное
  значение «не посещено» и защищён от переполнения без опоры на гипотезу
  о диаметре.
- Время чистого Python не обещать заранее; ускорение (NumPy, компиляция,
  другой backend) выбирать по измеренному узкому месту; векторизация
  не гарантирует экономию памяти.
- Файл `dist_n{n}.bin` сопровождают метаданные: n, генераторы и конвенции,
  индексация, тип данных, версия кода, полнота обхода, максимальное
  расстояние, контрольная сумма; частичная таблица помечается partial.
- Долгий обход восстанавливается из checkpoint: расстояния, фронт и служебное
  состояние. Одного массива посещённых вершин недостаточно.

### 9.3. Сертификат таблицы (`oracle/verify_distances.py`)

Для полной таблицы h на всех S_n независимый модуль проверяет:

1. Все значения — неотрицательные целые; единственный ноль — в id_n.
2. Для каждого ребра {p,q}: `|h(p) - h(q)| <= 1`.
3. Для каждой p != id_n есть сосед q с `h(q) = h(p) - 1`.

Плюс полнота множества перестановок и корректность индексации. Тогда
h(p) = d(p): условие 2 даёт h(p) <= d(p) вдоль любого пути от id_n, условие 3
строит путь длины h(p) к единственной вершине с нулём.

Контрольная сумма удостоверяет целостность файла, не точность. Выборочная
проверка условий — диагностика, не сертификат. Проверяющий модуль проверяется
также на намеренно повреждённых таблицах.

### 9.4. Проверки опорных данных

На сертифицированных таблицах: D_n из PROBLEM §4.1; единственность sigma_n;
`d(rev_n) = D_n - 2`; слой D_n - 1 — три соседа sigma_n; два равенства
из PROBLEM §4.3. Максимум вычисляется один раз, вне перебора; BFS не
пересчитывается отдельно для каждого теста.

### 9.5. `experiments/mine_worst.py`

- Читает n и сертифицированную таблицу.
- Находит D_n, все максимумы, слои D_n - 1 и D_n - 2, профиль числа вершин
  по расстояниям.
- Проверяет C5, C6, C14 отдельно от формулы диаметра; вычисляет цикловой тип,
  неподвижные точки, `F_c(p)` для всех c.
- Группирует данные под действием преобразований PROBLEM §4.3, не называя
  обращение автоморфизмом.
- Выдаёт JSON, сводку, запись в журнале.

### 9.6. `experiments/mine_geodesics.py`

- Для sigma_n и каждой вершины слоёв D_n - 1, D_n - 2 при n <= 8 (n = 9 при
  наличии таблицы): число геодезических; распределение (N_X, N_rot); сами слова
  (все при n <= 6, выборка при больших n); длины серий вращений между обменами
  и хвост; последовательность позиций обмена h_1..h_k на окружности
  в неподвижной системе позиций.
- Проверяет C13. Выдаёт JSON и сводку.
- Назначение: образцы для конструкции (фаза 2, шаг 2) и мишень для нижней оценки.

### 9.7. `invariants/framework.py`

- Интерфейс: `phi(p: tuple[int, ...]) -> number` с явной областью n
  и арифметикой; бесконечности и NaN — ошибка вычисления.
- Допустимость: нормировка и рёбра L и X; при проверке всех p этого достаточно
  для R (R = L^-1); при выборочной проверке — все три хода. Для VERIFIED —
  все состояния и нужные рёбра при данном n, точная или строго
  контролируемая арифметика.
- Сила: `Phi(sigma_n)`, `B_n - Phi(sigma_n)`; при наличии таблицы — максимум
  нарушения `Phi(p) <= d(p)`, доля точных совпадений, распределение
  зазора `d(p) - Phi(p)`. Недостижение B_n не означает недопустимость.
- Отчёт содержит отдельно coverage, arithmetic, admissibility, strength.
  Выборка не даёт сертификата допустимости; проверка `Phi <= d` без проверки
  рёбер допустимость не доказывает.
- Предпочтительны целые и рациональные числа; float с допуском — только
  для поиска, с пометкой NUMERICAL.

### 9.8. `evaluation/constructions.py`

- Кандидат предоставляет `sorting_word(state) -> list[Move]`.
- Кандидат выполняется в отдельном процессе с бюджетом ресурсов; берётся
  само слово, не заявленный балл. Родитель проверяет алфавит и сортировку
  эталонными ходами.
- Сохраняются исходная и свободно сокращённая длина, N_X и N_rot; для сравнения
  заранее фиксируется один режим; соответствие доказанному алгоритму сохраняется.
- Лестница проверок — правило 9 AGENTS.md (для дорогих конструкций n = 8
  по бюджету). Кандидаты сравниваются на одном наборе входов; сохраняются
  худшие входы, время, покрытие.
- Исходы: CORRECT_ON_TESTED_INPUTS, WRONG_WORD, ERROR, TIMEOUT, RESOURCE_LIMIT.
  Таймаут — превышение бюджета, не контрпример.
- Метрики. При n <= 9 с точной таблицей — основная диагностика: распределение
  `len - d(p)` по всем p и топ входов; где известно расщепление геодезических,
  потеря делится на лишние обмены и лишний пробег. При больших n —
  `max_len_observed - B_n`; наблюдаемый максимум не выдаётся за оценку
  на всём S_n. Сравнение с формулой — диагностика, не критерий корректности.
- Кандидат, претендующий на явную полиномиальную конструкцию, не запускает
  поиск по всему S_n и не читает таблицы во время работы. Проверка импортов —
  дисциплина, не доказательство сложности; сложность обосновывается отдельно.
  Полиномиальность — цель конструкции, а не условие любого доказательства.
- Для N1 сохранять статистики по сдвигам и раздельные потери (§4.1,
  AGENTS.md правило 15). Выбор c по минимуму оценки и по минимуму фактической
  длины — разные режимы; правило, все проверенные c и время выбора входят
  в описание алгоритма. Минимум по неполному набору нельзя назвать минимумом
  по всему Z_n.
- Изоляция: отдельный процесс, таймаут, проверка в родителе. Ничего сильнее
  до появления массовой эволюции произвольного кода.

### 9.9. Проверки входных доказательств

`checks/check_C1.py` воспроизводит базовую конструкцию после чтения входных
файлов; адаптация ходов сверяется с исходным поведением; общий статус требует
и логического аудита текста.

`checks/check_gap_T1.py` создаётся после чтения gap-файла. Термины M, S, k,
нагрузка и карман сначала определяются по источнику. План:

- допустимые циклы при n = 4..8, включая все направления при ничьих дуг;
- заявленные леммы `M <= 2 => S >= k + 1`, `S >= min(k + 1, 5 + (k mod 2))`,
  F-оценки, исключительные случаи k = 6, 7;
- точная арифметика малых n, округлений A_n и порогов;
- заявленная средняя экономия против фактической — ровно с той мерой усреднения
  и теми вариантами конструкции, которые заданы в тексте;
- общий аргумент для диапазонов, отсутствующих при малых n, и целевые примеры
  около порогов 138 и 852.

Границы перебора соответствуют кванторам лемм; примеры около большого порога
не проверяют все перестановки этих размеров. Улучшения на 2 и 3 хода —
отдельные строки реестра и отдельные проверки.

### 9.10. `bounds/known.py`

Сохранить `target_diameter(n)`, рациональную `A_n(n)`,
`baseline_bound_2n3(n) = floor(A_n)` и прежние gap-формулы с областями действия.
Добавить `strict_upper_bound(n) = U_n` (C16),
`strict_upper_bound_simple(n)` (C17) и сравнение применимых формул.
Имена функций не удостоверяют результат; статусы и зависимости — CLAIMS.md.

Для U_n использовать целочисленную/символьную арифметику или удостоверенные
интервалы. Например, при `z = 3n^2-4n+1-4P`,
`a = 36nP+25n^2-43n-12P+36`, `b = 7n`, `d = 18n` имеем
`R_n = (a-b*sqrt(z))/d`. Поэтому
`U_n = (a-ceil_sqrt(b^2*z)) // d`, где ceil_sqrt — точный целочисленный
квадратный корень с округлением вверх. Обосновать и проверить обработку
полных квадратов; float с допуском не используется для итогового floor.
Для floor(kappa*n) применим тот же приём к `(31n-7n*sqrt(2))/18`.

Сравнение возвращает формулу, диапазон и ID. Подтверждённый минимум использует
PROVED-границы и, при наличии, VERIFIED-данные только в их конечном диапазоне.
Минимум CLAIMED-формул показывается отдельно. Если подтверждённых оценок
в подключённом наборе нет, результат так и помечается, без повышения статуса.
Контрольные значения U_n: 9, 27, 211, 5065 при n = 4, 7, 20, 100.

После чтения N1 реализовать независимую проверку C18–C21 и округлений C16/C17
с явной привязкой каждого assert к лемме. Нагрузки можно считать перечислением
рёбер; слова проверять фактическим применением букв. Отдельно проверять

Для C22 — отдельный режим поиска контрпримеров, для C23 — проверка заданного

Общее доказательство C16 не заменяется проходом всех конечных assert.

### 9.11. Формат доказательства (`docs/proofs/<id>.md`)

1. Точное утверждение, область n, конвенции, нумерованные леммы, зависимости,
   полный аргумент, раздел «Машинная сверка» с границами применимости.
2. `checks/check_<id>.py`: вычислительно проверяемые части с привязкой к леммам
   и отчётами о покрытии.
3. Отчёт аудита логических переходов, особенно не удостоверяемых конечными
   примерами.

Код проверки следует тексту; оптимизированная версия — отдельный алгоритм,
пока не обоснована эквивалентность нужных свойств. Если лемма не имеет
содержательной конечной проверки, описывается способ логического аудита;
assert ради наличия чекера не создаётся. Если общий случай сводится
к конечному перебору, отдельно удостоверяются полнота редукции
и исчерпывающее вычисление. Формальная верификация возможна, не обязательна.
